# Середовище: як скомпілювати, запустити й перевірити програму

Олімпіадна задача читає дані зі **стандартного введення** (клавіатура або перенаправлений файл) і пише відповідь у **стандартне виведення**. Інструкція нижче допоможе налаштувати комп'ютер, запускати програму на тестах і перевіряти її скриптом репозиторію.

Перевірено 09.10.2026 на Windows 11 (Python 3.12, g++ 13.3 у WSL Ubuntu 24.04).

## 1. Встановлення

### Python 3

- Windows: інсталятор з <https://www.python.org/downloads/>. Під час встановлення увімкніть пункт **Add python.exe to PATH**.
- Linux: `sudo apt install python3`.

Перевірка: `python --version` (у Linux — `python3 --version`).

### Компілятор C++ (GCC)

**Windows, варіант 1 — MSYS2** (так рекомендує [документація VS Code](https://code.visualstudio.com/docs/cpp/config-mingw)):

1. Встановіть MSYS2 з <https://www.msys2.org/> у теку за замовчуванням `C:\msys64`.
2. У терміналі MSYS2 виконайте:
   ```
   pacman -S --needed base-devel mingw-w64-ucrt-x86_64-toolchain
   ```
3. Додайте `C:\msys64\ucrt64\bin` до змінної середовища `Path` користувача і відкрийте **нове** вікно терміналу.
4. Перевірка: `g++ --version`.

**Windows, варіант 2 — WSL** (Linux усередині Windows): у PowerShell від імені адміністратора `wsl --install`, після перезавантаження в Ubuntu виконайте `sudo apt update && sudo apt install g++ python3`. Скрипт перевірки репозиторію сам знаходить g++ у WSL, якщо його немає у Windows.

**Linux:** `sudo apt install g++`.

**macOS:** стандартний компілятор Apple clang не має заголовка `bits/stdc++.h`. Встановіть GCC через Homebrew (`brew install gcc`) і викликайте його з номером версії, наприклад `g++-15` (який номер у вас, покаже команда `ls $(brew --prefix)/bin | grep g++`), або підключайте потрібні заголовки (`<iostream>`, `<vector>`, `<algorithm>` тощо) явно.

### Редактор

Підійде будь-який редактор, у якому ви вмієте швидко відкрити термінал. Наприклад, [Visual Studio Code](https://code.visualstudio.com/) з розширеннями C/C++ і Python. На олімпіаді набір програм визначають організатори, тож не звикайте до інструментів, яких там може не бути. Вмійте компілювати з командного рядка.

## 2. Компіляція і запуск

C++:

```
g++ -std=c++17 -O2 -Wall -o prog prog.cpp
```

- `-std=c++17` — стандарт мови, для якого написано еталонні розв'язки репозиторію;
- `-O2` — оптимізація, як в олімпіадних системах;
- `-Wall` — попередження. **Читайте їх**: вони часто вказують на справжні помилки (неініціалізована змінна, порівняння `int` з `size_t`).

Запуск із введенням з файлу:

| Оболонка | C++ | Python |
|---|---|---|
| Linux, macOS, WSL | `./prog < 01.in` | `python3 prog.py < 01.in` |
| Git Bash у Windows | `./prog.exe < 01.in` | `python prog.py < 01.in` |
| Командний рядок Windows (cmd) | `prog.exe < 01.in` | `python prog.py < 01.in` |
| PowerShell | `Get-Content 01.in \| .\prog.exe` | `Get-Content 01.in \| python prog.py` |

PowerShell не підтримує перенаправлення `<`, тому там використовується конвеєр `Get-Content … |`. Якщо консоль працює в UTF-8 (команда `chcp` показує `65001`), Windows PowerShell 5.1 додає на початок даних невидимий символ BOM, і програма не прочитає перше число. Тоді запускайте через cmd: `cmd /c "prog.exe < 01.in"`.

## 3. Автоматична перевірка на тестах репозиторію

Скрипт [інструменти/перевірити.py](../інструменти/перевірити.py) запускає розв'язок на всіх тестах задачі, порівнює відповіді і рахує бали двома способами: **за підзадачами** (підзадача зараховується, лише якщо пройдено всі її тести, — як на III етапі) і **потестово** (за кожен пройдений тест, — як на I і II етапах 2025/2026, див. [ОЛІМПІАДИ.md](ОЛІМПІАДИ.md#формат-і-оцінювання)). Запускайте його з кореня репозиторію:

```
python інструменти/перевірити.py 13 мій.cpp     # ваш розв'язок задачі 13 (C++)
python інструменти/перевірити.py 13 мій.py      # або Python
```

Приклад результату (правильний, але повільний розв'язок задачі 13):

```
[13-опади] мій.cpp: ПОМИЛКА — 7/11 тестів, найдовший 5.02 с (обмеження в умові 1 с)
    бали за підзадачами: 30/100 (підзадачі: 1 — так, 2 — ні, 3 — ні); потестово, як на I–II етапах: 64/100
    big-small-a: перевищено обмеження часу (понад 5 с > 1 с)
      підказка (крок 3 — оцінка складності): Тут n = q = 2·10⁵: скільки операцій робить програма на
        всі запитання разом і чи швидко вона читає та виводить дані?
    big-int-edge: перевищено обмеження часу (понад 5 с > 1 с)
    …
```

Розв'язок проходить усі малі тести, але не встигає на великих: за підзадачами це 30 балів, а потестово — 64. Під непройденими тестами скрипт показує **підказку**: що особливого в цьому тесті і на якому кроці розв'язання ([за класифікацією помилок](../вчителю/АНАЛІЗ-ПОМИЛОК.md#класифікація)) варто шукати проблему. Підказка не розкриває алгоритму. Якщо хочете шукати помилку зовсім самостійно, додайте `--без-підказок`.

Ще три режими для учня:

```
python інструменти/перевірити.py 13 мій.cpp --приклади   # лише приклади з умови, без балів («наосліп», як на II етапі)
python інструменти/перевірити.py --stress 13 мій.cpp     # ваш розв'язок проти повільного на сотнях випадкових тестів
python інструменти/перевірити.py --зламати 13 тест.in    # режим «Злам»: чи ламає ваш тест хибні розв'язки
```

- `--приклади` — для тренування [туру «наосліп»](../учням/ПРОБНИЙ-ТУР.md#режим-наосліп-як-на-ii-етапі).
- `--stress` знаходить маленький тест, на якому ваш розв'язок розходиться з повільним, але правильним (див. [розділ 4](#4-як-перевірити-розвязок-самостійно-стрес-тестування)).
- `--зламати` — гра «знайди тест, який ламає чужий розв'язок». У кожній задачі є кілька **хибних розв'язків** з типовими помилками (`вчителю/розбори/NN-назва/хибні/`). Складіть коректний тест (вручну або своєю програмою-генератором), і скрипт перевірить, що він відповідає обмеженням умови, порахує правильну відповідь еталоном і покаже, які хибні розв'язки на ньому помиляються: «х1.cpp: ЗЛАМАНО — неправильна відповідь», «х2.cpp: вистояв». Читати код хибних розв'язків можна й треба: на олімпіаді так само доводиться шукати помилку у власному коді. Описи помилок для вчителя — у `хибні/README.md`.

Інші режими (переважно для вчителя):

```
python інструменти/перевірити.py                # усі еталонні розв'язки на всіх тестах
python інструменти/перевірити.py --stress 13    # еталони проти повільного розв'язку на випадкових тестах
python інструменти/перевірити.py --no-cpp       # лише Python
python інструменти/перевірити-посилання.py      # перевірка посилань у документації
```

Важливо:

- Відповіді порівнюються без урахування зайвих пробілів і порожніх рядків.
- Час вимірюється на вашому комп'ютері й лише приблизно відповідає часу на олімпіадному сервері.
- Якщо C++ запускається через WSL, кожен запуск має накладні витрати близько 0,1–0,3 с. Скрипт дає на це допуск 0,5 с.
- **Обмеження пам'яті скрипт не перевіряє.** Розв'язок, що використовує гігабайти пам'яті, на вашому комп'ютері «пройде», а на олімпіаді отримає вердикт «перевищено пам'ять». Оцінюйте пам'ять самі: масив з `10⁶` чисел `int` займає 4 МБ, `long long` — 8 МБ, список Python з `10⁶` цілих — десятки мегабайтів.

## 4. Як перевірити розв'язок самостійно: стрес-тестування

Коли розв'язок проходить приклади, але ви в ньому не впевнені:

1. Напишіть **повільний, але очевидно правильний** розв'язок (перебір).
2. Напишіть генератор малих випадкових тестів.
3. У циклі генеруйте тест, запускайте обидва розв'язки і порівнюйте відповіді. Перша розбіжність дає маленький тест, на якому видно помилку.

Так перевірено еталонні розв'язки репозиторію. Приклади генератора і повільного розв'язку див. у [вчителю/розбори/13-опади/](../вчителю/розбори/13-опади/розбір.md).

Для задач репозиторію все це вже готово: `python інструменти/перевірити.py --stress 13 мій.cpp` порівняє ваш розв'язок з повільним на 200 випадкових малих тестах і покаже перший тест, на якому відповіді розійшлися. Як за 5 хвилин написати такий стрес-тест самому, на олімпіаді чи в Colab, — у [РЕПЕРТУАР-CPP.md](../учням/РЕПЕРТУАР-CPP.md).

## 5. Пошук помилок у C++

- Компілюйте з `-Wall -Wextra` і виправляйте попередження.
- У Linux/WSL (але не в MinGW у Windows) прапорці `-fsanitize=address,undefined -g` змушують програму повідомляти про вихід за межі масиву та переповнення знакових цілих замість «тихої» неправильної відповіді.
- `-D_GLIBCXX_DEBUG` вмикає перевірку індексів у `vector` (лише для налагодження, програма стає повільнішою).
- Виводьте проміжні значення в потік помилок `cerr`. Перевірка враховує лише стандартне виведення, але перед відправленням на олімпіаді налагоджувальне виведення все одно краще прибрати.

## 6. Google Colab

II етап 2025/2026 з інформатики проходив у [Google Colab](https://colab.research.google.com/), де організатори дали готовий блокнот-інтерфейс для тестування й підготовки відправлення (див. [довідка/ОЛІМПІАДИ.md](ОЛІМПІАДИ.md#попередній-рік-20252026-у-дніпропетровській-області)). Яку платформу використають у 2026/2027, станом на 12.10.2026 не оголошено. Тому варто заздалегідь:

- навчитися відкривати блокнот Colab, запускати комірки й завантажувати та вивантажувати файли (потрібен обліковий запис Google);
- писати й налагоджувати розв'язок у звичному редакторі на своєму комп'ютері і зберігати там копії. Так радять і організатори, бо зміни в Colab легко втратити;
- пам'ятати, що вбудовані в Colab функції штучного інтелекту на олімпіаді заборонені.

Як це працювало у 2025/2026 (за офіційною пам'яткою):

1. Учасник отримав блокнот Colab із готовим інтерфейсом і набором тестів від журі для самоперевірки. Під час основного тестування тестів більше.
2. Розв'язок перевіряли в інтерфейсі на виданих тестах. Код платформи в блокноті змінювати можна, але не рекомендовано.
3. Інтерфейс створював zip-архів, який учасник відправляв через Google-форму. Відправляти можна було скільки завгодно разів, але перевірялася **лише остання** спроба.
4. Запитання до журі ставили через Google-форму, відповіді публікували в Google-документі.

Звідси практичні висновки: уважно прочитайте інструкцію інтерфейсу на початку туру (як саме програма отримує вхідні дані, як формується архів), тримайте робочу копію у файлі на комп'ютері і **не відправляйте наприкінці неперевірену версію**. Деталей формату вхідних даних у Colab-інтерфейсі пам'ятка не описує.

## 7. Відправлення на Eolymp

Задачі Всеукраїнської олімпіади та тренувальні набори розміщено на Eolymp (<https://uoi.eolymp.space/uk>). При відправленні оберіть мову зі списку системи. Станом на 12.10.2026 у списку Eolymp є «C++ 20 (gnu 14.2)», «C++ 23 (gnu 14.2)», «Python 3.14» і «Python 3.11 (PyPy)»; пункту C++17 немає. Еталонні розв'язки репозиторію написано на C++17 і Python 3, і код C++17 компілюється як C++20 без змін. Покроково — у [EOLYMP.md](EOLYMP.md#3-як-надіслати-розвязок).

Які мови дозволять на конкретному турі, вирішують організатори. На I етапі 2025–2026 умови двох задач радили обрати PyPy замість звичайного Python (див. [ОЛІМПІАДИ.md](ОЛІМПІАДИ.md#формат-і-оцінювання)). **PyPy** — швидша реалізація Python. Звичайні цикли в ній часто виконуються в кілька разів швидше, але деякі можливості (наприклад, глибока рекурсія) поводяться інакше. Якщо пишете на Python, потренуйтеся відправляти розв'язки і на Python, і на PyPy.
