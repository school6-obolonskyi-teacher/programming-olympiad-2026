# Розбір: 24. Наліпки

Умова: [задачі/24-наліпки/умова.md](../../../задачі/24-наліпки/умова.md) · Теми: [структури даних](../../../учням/теми/10-структури-даних.md), [сортування](../../../учням/теми/08-сортування.md)

## Ідея алгоритму

Обидві відповіді отримуємо з частот. Позначимо через `cnt[x]` частоту номера `x`. Тоді кількість різних номерів — це кількість таких `x`, що `cnt[x] > 0`. Найбільша частота `F` — найбільше з `cnt[x]`, а шуканий номер — найменший `x`, для якого `cnt[x] = F`.

Частоти можна порахувати трьома способами, і кожен відповідає своїй підзадачі.

**1. Перебір, O(n²) — підзадача 1.** Для кожного `i` проходимо весь масив і рахуємо, скільки разів трапляється `aᵢ`. Номер `aᵢ` новий, якщо його немає серед `a₁, …, aᵢ₋₁`. Найкращий номер оновлюємо умовою «частота більша **або** частота та сама, але номер менший»:

```cpp
if (c > bestCount || (c == bestCount && a[i] < bestValue)) { bestCount = c; bestValue = a[i]; }
```

**2. Масив частот, O(n + A) — підзадача 2.** Тут `A = 10⁶` — найбільший можливий номер. Заводимо масив `cnt` розміру `A + 1`, для кожної наліпки робимо `cnt[aᵢ]++`, а потім перебираємо `x` від 1 до `A` за зростанням. Це перша половина сортування підрахунком ([тема 08](../../../учням/теми/08-сортування.md)). Масив з `10⁶ + 1` чисел `int` займає 4 МБ. Для номерів до `10⁹` знадобилося б `4·10⁹` байтів, тобто майже 4 ГБ — приблизно в 15 разів більше за дозволені 256 МБ.

**3. Повний розв'язок, O(n log n).** Зберігаємо частоти лише тих номерів, що справді трапилися. Є два рівноцінні способи.

*(а) Сортування.* Після сортування однакові номери стоять поспіль і утворюють **серії**. Кількість серій — це кількість різних номерів, довжина серії — частота її номера. Серії йдуть за зростанням номерів, тому досить оновлювати відповідь лише при **строго** більшій довжині: при рівності залишиться раніша серія, тобто менший номер. Так зроблено в [еталон.cpp](еталон.cpp):

```cpp
sort(a.begin(), a.end());
for (int i = 0; i < n;) {
    int j = i;
    while (j < n && a[j] == a[i]) j++;   // a[i..j−1] — серія номера a[i]
    distinct++;
    if (j - i > bestCount) { bestCount = j - i; bestValue = a[i]; }
    i = j;
}
```

*(б) Асоціативний масив* (`map` або `unordered_map` у C++, `dict` або `Counter` у Python): для кожної наліпки `cnt[x] += 1`, а кількість різних номерів — це розмір словника. `map` перебирає ключі за зростанням, тож і тут досить строгого `>`:

```cpp
map<int, int> cnt;
for (int x : a) cnt[x]++;
for (auto& [v, c] : cnt)                 // ключі за зростанням
    if (c > bestCount) { bestCount = c; bestValue = v; }
// cnt.size() — кількість різних номерів
```

`unordered_map` і `dict` перебирають ключі в іншому порядку (`dict` — у порядку першої появи), тому найменший номер серед найчастіших треба шукати явно. Так зроблено в [еталон.py](еталон.py):

```python
cnt = Counter(map(int, data[1:1 + n]))
best_count = max(cnt.values())
best_value = min(v for v, c in cnt.items() if c == best_count)
print(len(cnt))
print(best_value, best_count)
```

**Чому не `Counter.most_common(1)`.** Документація Python ([collections.Counter](https://docs.python.org/3/library/collections.html#collections.Counter.most_common)) прямо каже, що елементи з однаковою кількістю впорядковуються в порядку першої появи («in the order first encountered»). У прикладі 2 `most_common(1)` повертає `(10, 2)`, бо номер 10 стоїть першим, а правильна відповідь — `4 2`.

## Обґрунтування правильності

Доведемо правильність розв'язку із сортуванням.

**1. Кожен номер утворює рівно одну серію.** Нехай у відсортованому масиві `a[i] = a[k] = x` і `i < j < k`. Тоді `x = a[i] ≤ a[j] ≤ a[k] = x`, тобто `a[j] = x`. Отже, всі входження `x` стоять поспіль. Тому кількість серій дорівнює кількості різних номерів, а довжина серії номера `x` дорівнює `cnt[x]`.

**2. Алгоритм вибирає найменший з найчастіших номерів.** Нехай `F` — найбільша частота, а `v*` — найменший номер з частотою `F`. Серії перед серією `v*` належать меншим номерам, тому за вибором `v*` їхні довжини менші за `F`. Отже, коли алгоритм доходить до серії `v*`, маємо `bestCount < F`, і відповідь стає `(v*, F)`. Кожна наступна серія має довжину не більшу за `F`, тому строге `>` її не вибере. Відповідь `(v*, F)` залишиться до кінця.

Якби замість `>` стояло `>=`, кожна наступна серія довжини `F` замінювала б відповідь, і в кінці лишився б **найбільший** з найчастіших номерів.

Для розв'язку зі словником майже нічого доводити не треба: `best_count` — найбільша частота за означенням, а `best_value` — мінімум серед номерів з цією частотою, тобто саме те, що вимагає умова.

## Складність

| Спосіб | Час | Пам'ять |
|---|---|---|
| Перебір | O(n²): при `n = 1000` — близько `10⁶` порівнянь, при `n = 2·10⁵` — `4·10¹⁰` | O(n) |
| Масив частот | O(n + A), `A = 10⁶` | O(A): 4 МБ |
| Сортування | O(n log n): близько `3,5·10⁶` порівнянь | O(n) |
| `map` | O(n log n) | O(d), де `d` — кількість різних номерів |
| `unordered_map`, `dict`, `Counter` | O(n) у середньому | O(d) |

Номери не перевищують `10⁹ < 2³¹ − 1 ≈ 2,1·10⁹`, а частоти — `n`, тому скрізь вистачає `int`.

На найбільших тестах еталон на C++ працює 0,03–0,04 с, еталон на Python — 0,18–0,27 с (у різних запусках). Розв'язки з `map` і `unordered_map` на C++ — 0,28 с і 0,10 с, сортування з підрахунком серій на Python — 0,37 с (усі виміряно скриптом перевірки в WSL).

Масив частот на `10⁶ + 1` падає з помилкою виконання на кожному тесті з номером понад `10⁶`: у Python — `IndexError`, у C++ — запис далеко за межі масиву. Тому він не проходить ні підзадачу 1, ні підзадачу 3, хоча на тестах підзадачі 2 працює не довше 0,15 с (C++).

Розв'язок `max(sorted(set(a)), key=a.count)` рахує `count` лише для різних номерів, тож його час — `n·d`. На тестах з малим `d` він устигає (`s2-same`, `b-same`, `b-tie-big`), але вже на `s2-pool` (`d = 1000`) працює 2,46 с, а на тестах з десятками тисяч різних номерів — понад 5 с.

Усі результати отримано запуском `інструменти/перевірити.py` на відповідних розв'язках, а не виведено теоретично.

У тестах `*-tie` генератор стежить, щоб найменший з найчастіших номерів за першою появою не стояв ні першим, ні останнім, а кількість цифр у найчастіших номерах вибирає випадково. Так ці тести ловлять «перший з рівних» і «останній з рівних», а `s2-tie`, `b-tie` і `b-tie-big` — ще й порівняння рядків (у `s1-tie` найменший з найчастіших номерів випадково виявився першим і за абеткою).

## Методичні примітки

1. Почніть із запитання «як би ви рахували наліпки вручну?». Зазвичай учні пропонують або «для кожної наліпки переглянути всі інші» (перебір), або «розкласти по купках» (масив частот, сортування). Кожен спосіб — окрема підзадача.
2. Сформулюйте правило вибору за обмеженнями: `n` до кількох тисяч — можна перебір; номери до `10⁶–10⁷` — масив частот; інакше — сортування або `map`/`dict`. Попросіть учнів самостійно порахувати, скільки пам'яті займе масив частот для `10⁶` і для `10⁹`.
3. Нічиї. Попросіть учнів передбачити, що виведуть на прикладі 2 `Counter.most_common(1)` і `map` з `>=`, а потім перевірити. Обговоріть, чому в розв'язку із сортуванням строге `>` само собою дає найменший номер, а `>=` — найбільший (пункт 2 обґрунтування).
4. Пастка Python: множина малих цілих чисел часто *виглядає* відсортованою, бо хеш цілого числа — це саме число. Але на прикладі 2 `set` перебирає номери в порядку 9, 10, 4, 25. Для порядку за зростанням потрібен `sorted`.
5. Продовження: AtCoder ABC 155 C «Poll» (вивести всі найчастіші слова за абеткою) і CSES 1621 «Distinct Numbers» — посилання в умові. На I етапі 2025–2026 (8–11 кл.) задача G «Множини» теж потребує швидкої перевірки «чи є число в масиві», для чого зручна множина ([тема 10](../../../учням/теми/10-структури-даних.md)).
