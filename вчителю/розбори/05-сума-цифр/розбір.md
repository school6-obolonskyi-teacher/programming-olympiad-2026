# Розбір: 05. Сума цифр

Умова: [задачі/05-сума-цифр/умова.md](../../../задачі/05-сума-цифр/умова.md) · Тема: [цикли](../../../учням/теми/03-цикли.md), [типи даних](../../../учням/теми/06-складність.md)

## Ідея алгоритму

Остання цифра числа `N` — це остача від ділення на 10: `N % 10`. Цілочисельне ділення на 10 (`N / 10` у C++, `N // 10` у Python) відкидає останню цифру. Повторюємо дві дії, доки число не стане нулем:

1. додаємо до суми `N % 10`;
2. замінюємо `N` на `N / 10`.

Трасування для `N = 123`:

```
Ітерація 1: N = 123, остання цифра = 123 % 10 = 3, сума = 3
            N = 123 / 10 = 12
Ітерація 2: N = 12,  остання цифра = 12 % 10 = 2,  сума = 3 + 2 = 5
            N = 12 / 10 = 1
Ітерація 3: N = 1,   остання цифра = 1 % 10 = 1,   сума = 5 + 1 = 6
            N = 1 / 10 = 0
N = 0, цикл завершується. Результат: 6
```

Інший правильний спосіб — прочитати `N` як рядок і додати цифри-символи (`c - '0'` у C++, `int(c)` у Python). Так влаштовано [повільний.py](повільний.py). Тоді тип даних узагалі не важить, але учень не тренує арифметику остач, заради якої задача потрібна.

## Обґрунтування правильності

Запишемо `N = 10·q + r`, де `0 ≤ r ≤ 9`. Тоді `r = N % 10` — остання цифра, а `q = N / 10` — число, утворене всіма цифрами, крім останньої. Отже, сума цифр `N` дорівнює `r` плюс сума цифр `q`. На кожній ітерації цикл додає одну цифру і переходить до числа, коротшого на одну цифру. Коли `q = 0`, цифр більше немає, і цикл зупиняється. Оскільки `N ≥ 1`, цикл виконається щонайменше один раз; окремо обробляти `N = 0` не потрібно (і такого входу не буває).

## Складність

- Час: O(кількість цифр) = O(log₁₀ N), тобто не більше 19 ітерацій при `N ≤ 10¹⁸`.
- Пам'ять: O(1).

Обмеження часу тут ні на що не впливає. Задача перевіряє лише правильність алгоритму і вибір типу.

## Вибір типу даних

| Тип у C++ | Найбільше значення | Чи вміщує `N ≤ 10¹⁸` |
|---|---|---|
| `int` | 2 147 483 647 ≈ 2,1·10⁹ | ні |
| `unsigned int` | 4 294 967 295 ≈ 4,3·10⁹ | ні |
| `long long` | 9 223 372 036 854 775 807 ≈ 9,2·10¹⁸ | так |

Сама сума цифр не перевищує `9 · 18 = 162`, тому для неї вистачає `int`.

У першій версії репозиторію обмеження було `N ≤ 10⁹`, а в розв'язку радили `long long`. Ця порада була зайвою, бо `10⁹` вміщується в `int`. Тепер `N` сягає `10¹⁸`, і `long long` справді потрібен. Підзадача 1 (`N ≤ 10⁹`) лишилася для тих, хто ще не знає про `long long`.

Що відбувається з `int` на великому числі: коли значення не вміщується в тип, `cin >> n` записує в `n` найбільше значення типу (`2147483647`) і переходить у стан помилки. Тому `int`-розв'язок на всіх тестах із `N > 2 147 483 647` виводить `46` — суму цифр числа `2147483647` (перевірено запуском). Для `unsigned int` так само виходить `57`, сума цифр `4294967295`.

## Часткові розв'язки за підзадачами

| Розв'язок | Підзадачі | Бали |
|---|---|---|
| `int n` у C++ | 1 | 50 |
| `unsigned int n` у C++ | 1 | 50 |
| Читання в `double` і перетворення в `long long` | 1 | 50 |
| Python, `n = int(n / 10)` замість `n //= 10` | 1 | 50 |
| `long long n` (еталон) | 1, 2 | 100 |
| Читання як рядка і сума символів | 1, 2 | 100 |
| Старий розв'язок із першої версії репозиторію (`long long`, `endl`) | 1, 2 | 100 |

Усі результати отримано запуском `інструменти/перевірити.py` на навмисно недосконалих розв'язках.

Чому `double` і `n / 10` у Python ламаються лише на великих `N`: тип `double` зберігає приблизно 15–16 значущих цифр (точно — цілі числа до `2⁵³ ≈ 9·10¹⁵`). Число з 17–18 цифр округлюється, і далі цикл розбирає вже інше число. Наприклад, для `999999999999999999` (сума 162) `double`-версія видала `1`, бо прочитала `10¹⁸`. Python-версія з `int(n / 10)` видала `10`. На `N ≤ 10⁹` обидві працюють правильно.

## Типові помилки учнів

| Помилка | Симптом | Як виявити |
|---|---|---|
| `int` замість `long long` для `N` (C++) | на всіх великих `N` виводиться `46` | тести 04, 10, 12–15 |
| `n / 10` у Python (дійсне ділення) | з `int(n / 10)` — неправильна відповідь лише на 17–18 цифрах; з `n = n / 10` число стає дробовим і для `123` виводиться `6.666666666666668` | тести 10, 13; приклад 1 |
| Забули `n /= 10` | нескінченний цикл, перевищення часу | будь-який тест |
| `% 100` замість `% 10` | додаються двоцифрові «шматки» числа | приклад 1: `23 + 12 + 1 = 36` замість `6` |
| Умова циклу `while (n > 9)` | губиться перша цифра | приклад 1 дає `5` |
| Сума `sum` не обнулена перед циклом (локальна змінна в C++) | випадкове «сміття» у відповіді | будь-який тест |

## Методичні примітки

1. Почніть із трасування на дошці (таблиця вище для `N = 123`): учні мають самі побачити, що `%` дає цифру, а ділення її «з'їдає». Корисно спитати, у якому порядку цикл перебирає цифри (з кінця).
2. Порівняйте два способи: арифметичний і через рядок. Арифметичний знадобиться в задачах, де з цифрами треба рахувати (перевернути число, перевірити подільність, перевести в іншу систему числення).
3. Дайте учням здати `int`-версію і подивитися, що вона набирає 50 балів і на всіх великих тестах друкує `46`. Попросіть пояснити, звідки береться саме `46`. Так учні запам'ятовують межу `int` краще, ніж із попередження.
4. Для Python-учнів окремо наголосіть на різниці `/` і `//`: на малих числах помилки не видно, вона з'являється лише після 16 цифр.
5. Продовження: цифровий корінь (сума цифр, поки не залишиться одна цифра), кількість цифр числа, перевертання числа, задачі AtCoder ABC 101 B і ABC 083 B з умови.
