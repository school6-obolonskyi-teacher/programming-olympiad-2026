# Розбір: 23. Вище середнього

Умова: [задачі/23-вище-середнього/умова.md](../../../задачі/23-вище-середнього/умова.md) · Тема: [масиви](../../../учням/теми/04-масиви.md), [типи даних](../../../учням/теми/06-складність.md#типи-даних-і-переповнення)

## Ідея алгоритму

Розв'язок має два проходи:

1. Читаємо всі бали в масив і рахуємо їхню суму `S`.
2. Проходимо масивом ще раз і рахуємо учнів, для яких `aᵢ · n > S`.

Масив потрібен, бо середній бал залежить від **усіх** балів, зокрема від останнього. Поки вхід не прочитано до кінця, не можна сказати, чи перший учень вище середнього. Отже, бали треба зберегти й переглянути ще раз.

Порівняння `aᵢ · n > S` — це та сама умова «`aᵢ` більше за середнє», записана без ділення.

## Обґрунтування правильності

**Рівносильність.** Учень вище середнього, якщо `aᵢ > S / n`. Множимо обидві частини на `n`. Оскільки `n > 0`, знак нерівності зберігається: `aᵢ > S / n ⇔ aᵢ · n > S`. Обидві частини останньої нерівності — цілі числа, тож порівняння точне: жодних округлень.

**Типи даних.** `S ≤ n · max aᵢ = 2·10⁵ · 10⁹ = 2·10¹⁴`, і так само `aᵢ · n ≤ 2·10¹⁴`. Це більше за `2³¹ − 1 ≈ 2,1·10⁹`, але значно менше за межу `long long` (`≈ 9,2·10¹⁸`). Тому і сума, і добуток мають обчислюватися в `long long`. Важливо, щоб у `long long` був хоча б один множник: у [еталон.cpp](еталон.cpp) масив має тип `vector<long long>`. Якщо `a[i]` і `n` обидва типу `int`, то добуток `a[i] * n` обчислюється в `int` і переповнюється, хоч би куди записали результат.

### А якщо все-таки ділити?

Учні часто обчислюють середнє діленням. Ось що з цього працює в межах цієї задачі, а що ні (кожне твердження перевірено запуском, див. «Часткові розв'язки»).

- **Цілочисельне ділення працює.** Порівняння `aᵢ > ⌊S / n⌋` (у C++ `s / n` для невід'ємних `long long`, у Python `s // n`) рівносильне `aᵢ > S / n`. Нехай `q = ⌊S / n⌋`, тоді `q ≤ S / n < q + 1`. Якщо `aᵢ > S / n`, то й поготів `aᵢ > q`. Навпаки, якщо `aᵢ > q`, то `aᵢ ≥ q + 1`, бо обидва числа цілі, а `q + 1 > S / n`. Але з `≥` цей прийом ламається: `aᵢ ≥ q` виконується і для `aᵢ = q`, хоча `q` може бути меншим за середнє (бали `1 2 2`: `q = 1`, середнє 1,67). Для від'ємних чисел (їх у цій задачі немає) прийом ламається і в C++, бо там ділення округлює до нуля, а не вниз: для `−1 −2` маємо `s / n = −1`, і бал `−1` «не вище» середнього `−1,5`. Порівняння `aᵢ · n > S` правильне завжди, якщо немає переповнення.
- **`double` (64 біти) тут працює, але лише завдяки обмеженням.** `S ≤ 2·10¹⁴ < 2⁵³`, тому сума і бали зберігаються в `double` точно. Частку `S / n` комп'ютер округлює до найближчого `double`, з відносною похибкою не більше `2⁻⁵³`. Отже, абсолютна похибка — не більше `10⁹ · 2⁻⁵³ ≈ 1,1·10⁻⁷`. Якщо ж середнє не дорівнює `aᵢ`, то воно відрізняється від `aᵢ` щонайменше на `1/n ≥ 5·10⁻⁶`, бо `aᵢ − S/n = (aᵢ · n − S) / n`, а чисельник — ціле число, не рівне нулю. Похибка в 45 разів менша за цей проміжок, тож порівняння не помиляється. Якщо `S / n = aᵢ` точно, ділення теж дає `aᵢ` точно. У Python звичайне ділення `sum(a) / n` теж дає `double`, і такий розв'язок набирає 100 балів. Проте при сумах понад `2⁵³ ≈ 9·10¹⁵` це міркування вже не працює, тому надійніше звикати до цілих чисел.
- **`float` (32 біти) помиляється.** У `float` лише 24 двійкові цифри мантиси, приблизно 7 десяткових. Для чисел від 8192 до 16384 сусідні значення `float` відстоять на `2⁻¹⁰ ≈ 0,001`, а середнє може відрізнятися від цілого лише на `1/n = 5·10⁻⁶`. Тест `s2-int-below`: усі бали `10⁴`, крім одного `9999`, `n = 2·10⁵`. Середнє `9999,999995` у `float` округлюється до `10000`, і розв'язок виводить 0 замість 199999. У підзадачі 1 `float` не помиляється: там `S ≤ 10⁴` зберігається точно, проміжок `1/n ≥ 0,01`, а похибка не перевищує `100 · 2⁻²⁴ ≈ 6·10⁻⁶`.
- **Округлене середнє помиляється.** Бали `1 2 2`: середнє 1,67 округлюється до 2, і жоден бал не «більший за 2», хоча правильна відповідь 2. Те саме з округленням угору.

## Складність

- Час: O(n) — два проходи масивом.
- Пам'ять: O(n) — масив із `n` чисел (`2·10⁵` чисел `long long` — це 1,6 МБ).
- На найбільших тестах еталон на C++ працює 0,02–0,03 с, на Python — 0,12–0,16 с (вимірювання скриптом `перевірити.py` у WSL).

Чому `int` проходить підзадачу 2: там `aᵢ ≤ 10⁴`, тож `S ≤ 2·10⁵ · 10⁴ = 2·10⁹ < 2³¹ − 1 = 2 147 483 647`, і добутки `aᵢ · n` теж не більші за `2·10⁹`. Тест `s2-int-edge` дає рівно `S = 2·10⁹`, тест `s2-int-below` — `S = 2·10⁹ − 1`.

Деталі запуску:

- «усе в `int`» помиляється на тестах 03, `m-random`, `b-random`, `b-exact`, `b-below`, `b-above`, `b-onebig`, `b-onebig-zero`. На тесті 03 (`10⁹ 10⁹ 0`) сума `2·10⁹` ще вміщується в `int`, але `10⁹ · 3` — ні. Зате тести 11, 12, `b-max` і `b-max-below` цей розв'язок випадково проходить: коли всі бали однакові або майже однакові, сума і добутки «переповнюються однаково», і порівняння лишається правильним. Тому одного тесту на великі числа замало;
- «сума в `long long`, добуток у `int`» на всіх 10 тестах, де помиляється (03, 12, `m-random`, `b-random`, `b-exact`, `b-below`, `b-above`, `b-onebig`, `b-onebig-zero`, `b-max-below`), виводить 0;
- «сума в `int`, середнє в `double`» і «цілочисельне ділення в `int`» помиляються на тестах 11, 12, `m-random`, `b-random`, `b-exact`, `b-below`, `b-above`, `b-onebig`, `b-max`, `b-max-below`: сума переповнюється й стає від'ємною, і «вище середнього» опиняються всі (на тесті 11 — 3 замість 0);
- `float` із сумою в `long long` помиляється на тестах 12, `s2-below`, `s2-int-below`, `b-exact`, `b-below`, `b-above`, `b-max-below`; із сумою у `float` — ще й на `s2-exact`, `s2-above` і `s2-int-edge`;
- `≥` помиляється на всіх тестах, де хтось має рівно середній бал: 01, 02, 04, 05, 10, 11, `s1-exact`, `s2-exact`, `s2-int-edge`, `b-exact`, `b-max`;
- округлене середнє помиляється на тестах 07, 08, 09, 12, `s1-below`, `s1-max`, `s2-below`, `s2-onebig`, `s2-int-below`, `b-below`, `b-onebig`, `b-max-below`;

| Помилка | Симптом | Як виявити |

## Методичні примітки

1. Почніть із запитання: чи можна відповісти, читаючи бали по одному і нічого не запам'ятовуючи? Нехай учні спробують і знайдуть контрприклад. Приклад 3 підходить: поки не прочитано останній нуль, жоден із балів `10⁹` не вищий за середнє. Це природна мотивація для масиву.
2. Рівносильність `aᵢ > S / n ⇔ aᵢ · n > S` пояснюйте через властивість нерівностей: якщо обидві частини помножити на додатне число, знак не зміниться. Попросіть учнів пояснити, чому тут важливо, що `n > 0`.
3. Дайте учням здати розв'язок з `int` і переконатися, що він набирає 60 балів. Потім покажіть, що на тесті «усі бали `10⁹`» він випадково дає правильну відповідь: переповнення не завжди видно, тому тести мають бути різноманітними.
4. Обговоріть дробові числа: `float` проти `double`, тест `s2-int-below`. Висновок: якщо задачу можна розв'язати в цілих числах, розв'язуйте в цілих. `double` тут працює лише завдяки обмеженням (сума менша за `2⁵³`, похибка набагато менша за `1/n`), а в іншій задачі це може бути вже не так.
5. Цілочисельне ділення `aᵢ > ⌊S/n⌋` теж правильне. Нехай учні самі доведуть чому і знайдуть, чому не працює `aᵢ ≥ ⌊S/n⌋`.
6. Продовження: Eolymp 7833 (сума й кількість чисел, більших за середнє, числа можуть бути від'ємними — у C++ прийом із `s / n` для від'ємних уже не працює, а `a[i] * n > s` працює); «Above Average» з Kattis (відсоток із трьома знаками після коми, кілька класів в одному тесті); учні, вищі за **медіану**, — для цього знадобиться сортування ([тема 08](../../../учням/теми/08-сортування.md)).
