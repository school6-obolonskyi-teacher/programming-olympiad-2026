# Розбір: 08. Фібоначчі

Умова: [задачі/08-фібоначчі/умова.md](../../../задачі/08-фібоначчі/умова.md) · Тема: [цикли](../../../учням/теми/03-цикли.md), [складність і переповнення](../../../учням/теми/06-складність.md)

## Що змінено порівняно з першою версією

У першій версії репозиторію умова дозволяла `N ≤ 1000`, а C++-розв'язок рахував у `long long`. Таке поєднання хибне: `long long` вміщує числа Фібоначчі лише до `F(92)`. При `N = 94` старий розв'язок друкує останнім числом `−6246583658587674878` (перевірено запуском). Це `F(93) − 2⁶⁴`, результат переповнення. Хибним було й твердження «для `N > 90` числа можуть перевищити `10⁹`»: насправді `10⁹` перевищує вже `F(45) = 1 134 903 170`.

Тепер `N ≤ 90`, а підзадачі розділяють розв'язки з `int` і з `long long`.

## Ідея алгоритму

Тримаємо дві змінні: `a = F(i)` і `b = F(i+1)`. На кожному кроці виводимо `a`, а потім зсуваємо пару на одну позицію: нова пара — `(b, a + b)`. У C++ для цього потрібна тимчасова змінна, у Python — одночасне присвоєння `a, b = b, a + b`.

Трасування для `N = 5`:

```
Ітерація 0: вивести 0 (a = 0, b = 1); нова пара a = 1, b = 0 + 1 = 1
Ітерація 1: вивести 1 (a = 1, b = 1); нова пара a = 1, b = 1 + 1 = 2
Ітерація 2: вивести 1 (a = 1, b = 2); нова пара a = 2, b = 1 + 2 = 3
Ітерація 3: вивести 2 (a = 2, b = 3); нова пара a = 3, b = 2 + 3 = 5
Ітерація 4: вивести 3 (a = 3, b = 5); нова пара a = 5, b = 3 + 5 = 8
Результат: 0 1 1 2 3
```

## Обґрунтування правильності

Інваріант: перед ітерацією з номером `i` виконується `a = F(i)`, `b = F(i+1)`. Перед першою ітерацією `a = 0 = F(0)`, `b = 1 = F(1)`. Якщо інваріант правильний перед ітерацією `i`, то після неї `a = F(i+1)` і `b = F(i) + F(i+1) = F(i+2)` за означенням. Отже, на ітерації `i` виводиться саме `F(i)`, і за `N` ітерацій виводяться `F(0), …, F(N−1)`.

## Складність

- Час: O(N), одне додавання на число.
- Пам'ять: O(1) у C++. Python-еталон збирає числа в список для виведення, це O(N).

## Чому межа саме 90 і які типи потрібні

| Число | Значення | Порівняння з межею типу |
|---|---|---|
| `F(44)` | 701 408 733 | останнє число при `N = 45` (підзадача 1) |
| `F(45)` | 1 134 903 170 | перше число, більше за `10⁹` |
| `F(46)` | 1 836 311 903 | найбільше, що вміщується в `int` (`2³¹ − 1 = 2 147 483 647`) |
| `F(47)` | 2 971 215 073 | переповнює `int` |
| `F(89)` | 1 779 979 416 004 714 189 | останнє число при `N = 90` |
| `F(91)` | 4 660 046 610 375 530 309 | найбільше значення, яке обчислює цикл при `N = 90` |
| `F(92)` | 7 540 113 804 746 346 429 | найбільше, що вміщується в `long long` (`2⁶³ − 1 ≈ 9,22·10¹⁸`) |
| `F(93)` | 12 200 160 415 121 876 738 | переповнює `long long`, але вміщується в `unsigned long long` (`2⁶⁴ − 1 ≈ 1,84·10¹⁹`) |
| `F(94)` | 19 740 274 219 868 223 167 | переповнює і `unsigned long long` |

Цикл у розв'язку рахує **наперед**: на останній ітерації при виведенні `F(N−1)` він обчислює ще й `b = F(N+1)`. Звідси дві межі:

- **93** — найбільше `N`, при якому всі *виведені* числа (до `F(92)`) вміщуються в `long long`;
- **90** — межа з запасом, при якій навіть обчислене наперед `F(91)` вміщується в `long long`. При `N = 92` або `93` виведені числа правильні, але проміжне `F(93)` переповнює знаковий тип, а знакове переповнення в C++ — це невизначена поведінка. Обмеження `N ≤ 90` дозволяє не думати про цю тонкість у задачі рівня 3.

З тієї ж причини підзадача 1 має межу `N ≤ 45`: `int`-розв'язок тоді обчислює щонайбільше `F(46)`, тож переповнення немає взагалі. На `N = 48` `int`-розв'язок виводить останнім числом `−1323752223` замість `F(47) = 2971215073` (перевірено запуском).

### А якщо `N` до 1000?

`F(999)` має 209 цифр, жоден вбудований цілий тип C++ його не вмістить. Потрібна «довга арифметика»: число зберігають як рядок або масив цифр і додають «стовпчиком». У Python цілі числа не мають верхньої межі, тому [еталон.py](еталон.py) без жодних змін працює і для `N = 1000` (перевірено: останнє число має 209 цифр). Це гарна задача-продовження для сильних учнів, які пишуть на C++.

## Наївна рекурсія

Пряме перенесення означення в код

```cpp
long long fib(int k) { return k < 2 ? k : fib(k - 1) + fib(k - 2); }
```

обчислює ті самі значення багато разів. Кількість викликів для `fib(k)` дорівнює `2·F(k+1) − 1`, тобто росте як `φᵏ`, де `φ = (1 + √5)/2 ≈ 1,618`. Якщо так обчислювати кожне з чисел `F(0), …, F(N−1)`, загальна кількість викликів дорівнює `2·(F(N+2) − 1) − N`: близько `4,4·10⁶` при `N = 30`, `3,7·10⁹` при `N = 44` і `5,9·10⁹` при `N = 45`.

| Метод | Час | Пам'ять | Примітка |
|---|---|---|---|
| Ітеративно, дві змінні | O(N) | O(1) | еталон |
| Масив `f[0..N−1]` («динамічне програмування») | O(N) | O(N) | теж правильно |
| Рекурсія із запам'ятовуванням | O(N) | O(N) | [повільний.py](повільний.py) |
| Наївна рекурсія | O(φᴺ) | O(N) глибина стека | не проходить навіть підзадачу 1 |

## Типові помилки учнів

| Помилка | Симптом | Як виявити |
|---|---|---|
| `int` замість `long long` | від'ємні або дивні числа в кінці рядка | тести 12–15 (`N ≥ 48`) |
| Неправильний порядок присвоєнь: `a = b; b = a + b;` | `0 1 2 4 8 16 …` (степені двійки) | приклад 1 |
| Виводяться `F(1), …, F(N)` замість `F(0), …, F(N−1)` | рядок починається з `1` | приклад 2 |
| Перші два числа виводяться до циклу без перевірки `N` | при `N = 1` виводиться `0 1` | приклад 2 (тест 02) |
| Наївна рекурсія | перевищення часу | тести 08–15 |
| `double` | експоненційний запис `1.34627e+06` | тести 08–15 |

## Методичні примітки

1. Почніть із трасування на дошці (див. вище) і запитайте: «Скільки чисел треба пам'ятати, щоб отримати наступне?». Варто окремо показати помилку з порядком присвоєнь: `a = b; b = a + b;` дає степені двійки.
2. Попросіть учнів здати `int`-версію і подивитися, як у кінці рядка з'являються від'ємні числа. Потім знайти, на якому `N` це починається (`N = 48`), і пояснити, чому саме там. Це найкраща ілюстрація до теми 06.
3. Для порівняння дайте наївну рекурсію з `N = 30, 35, 40, 44` і поміряйте час: кожні 5 кроків час зростає приблизно в `φ⁵ ≈ 11` разів. Це наочне знайомство з експоненційною складністю і мотивація для запам'ятовування (тема 14, динамічне програмування).
4. Сильним учням запропонуйте продовження: `N ≤ 1000` на C++ із довгою арифметикою або задачу CSES 1722 (матриці, II етап).
5. Числа Фібоначчі трапляються в природі: кількість спіралей у суцвітті соняшника чи на шишці часто є числом Фібоначчі. Це зручний привід для короткої розмови на початку заняття.
