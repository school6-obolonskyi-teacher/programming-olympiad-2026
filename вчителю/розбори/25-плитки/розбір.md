# Розбір: 25. Плитки

Умова: [задачі/25-плитки/умова.md](../../../задачі/25-плитки/умова.md) · Тема: [теорія чисел: дільники за O(√n)](../../../учням/теми/11-теорія-чисел.md)

## Ідея алгоритму

Прямокутник з `a` рядів по `b` плиток існує тоді й лише тоді, коли `a` ділить `n`, і тоді `b = n / a`. Отже:

1. **кількість прямокутників** — це кількість дільників числа `n`;
2. **найменший периметр** `2 · (a + b)` дає пара сторін, найближчих одна до одної, тобто найбільший дільник `a`, що не перевищує `√n`.

Обидві відповіді знаходимо одним циклом за `i` від 1, поки `i · i ≤ n`:

- якщо `n % i == 0`, то `i` і `n / i` — пара дільників. Вона дає 2 прямокутники (`i × n/i` і `n/i × i`), а якщо `i = n / i` (точний квадрат) — лише 1;
- останнє знайдене таке `i` — найбільший дільник, що не перевищує `√n`; з ним периметр `2 · (i + n / i)` найменший.

## Обґрунтування правильності

**Кількість.** Відповідність «прямокутник `a × b` ↔ дільник `a`» взаємно однозначна: за `a` сторона `b = n / a` визначена однозначно, а різні `a` дають різні прямокутники. Тож прямокутників стільки, скільки дільників.

Дільники розбиваються на пари `(d, n / d)`. Якщо `d < √n`, то `n / d > √n`, тому в кожній парі рівно один дільник менший за `√n`, і цикл до `√n` знаходить кожну пару рівно один раз. Виняток — `d = n / d`, тобто `d² = n`: такий дільник утворює «пару» сам із собою і рахується один раз. Тому відповідь дорівнює `2 · k`, якщо `n` не точний квадрат, і `2 · k − 1`, якщо точний, де `k` — кількість дільників, що не перевищують `√n`.

**Найменший периметр.** Для сторін `a ≤ b` з `a · b = n` маємо

```
(a + b)² = (b − a)² + 4ab = (b − a)² + 4n.
```

Число `n` фіксоване, тож сума `a + b` (а з нею і периметр) тим менша, чим менша різниця `b − a`. Коли менша сторона `a ≤ √n` зростає, більша `b = n / a` спадає, тож різниця `b − a` строго зменшується. Отже, найменший периметр дає **найбільший** дільник `a ≤ √n`. Цикл іде за зростанням `i`, тому останній знайдений дільник — саме він. Для `n = 1` це `a = b = 1` і периметр 4; для простого `n` — лише `a = 1`, периметр `2 · (n + 1)`.

**Умова циклу `i · i ≤ n`** рівносильна `i ≤ √n` для цілих невід'ємних `i`, але обчислюється точно, у цілих числах. `sqrt` з `double` на цих межах теж працює правильно: ми перевірили, що `(long long)sqrt((double)m)` дає точну цілу частину кореня для всіх `m = k² − 1, k², k² + 1` при `k ≤ 10⁶`. Уперше він помиляється при `k = 67 108 865` (`m = k² − 1 ≈ 4,5·10¹⁵`): повертає `k` замість `k − 1`. Тож для більших чисел (наприклад, до `10¹⁸`) дійсний корінь уже небезпечний.

**Типи.** `n ≤ 10¹²` не вміщується в `int` (до `2³¹ − 1 ≈ 2,1·10⁹`). Лічильник `i` сягає `10⁶`, і `i · i` — `10¹²`, тож і `i` має бути `long long`, інакше добуток переповнюється вже при `i = 46 341`. Найбільший периметр — для простого `n`: `2 · (n + 1) ≈ 2·10¹²`. Кількість дільників мала: найбільша серед чисел до `10¹²` — 6720 (у числа 963 761 198 400 з тесту 20; це рекорд для 12-значних чисел за [OEIS A066150](https://oeis.org/A066150)).

Зверніть увагу: **у підзадачі 2 периметр ще вміщується в `int`**. Найбільший периметр там — `2 · (999 999 937 + 1) = 1 999 999 876 < 2³¹ − 1` (тест 12). Периметр простого `n` перевищує `2³¹ − 1` лише при `n ≥ 1 073 741 823`, тобто тільки в підзадачі 3.

## Складність

- Час: O(√n) — до `10⁶` кроків циклу при `n = 10¹²`.
- Пам'ять: O(1).
- У нашому запуску на найбільших тестах еталон на C++ працює 0,01–0,02 с, на Python — 0,14–0,19 с (цикл `for i in range(1, math.isqrt(n) + 1)`). Варіант на Python із циклом `while i * i <= n`, як у темі 11, повільніший — 0,24–0,30 с, але теж укладається в 1 с.

Перебір усіх `a` від 1 до `n` робить до `10¹²` кроків і не встигає навіть на C++: у нашому запуску (версія з `long long`) при `n` від 4,5·10⁸ до 10⁹ він працював 1,3–3,1 с.

Перебір до `n` на C++ з `int` швидший, ніж з `long long` (32-бітне ділення дешевше): у нашому запуску 1,7–2,0 с при `n ≈ 10⁹` (тести 11, 12, 14), а на тесті 15 (`n ≈ 5,4·10⁸`) — 1,05 с, майже на межі. Тести з `n` близько `10⁹` він на нашому комп'ютері не проходить, але запас лише приблизно вдвічі: на значно швидшому комп'ютері такий розв'язок може встигнути в підзадачі 2. Перебір до `n` на Python не встигає на жодному тесті з `n > 10⁶` (понад 5 с).

Чому три різні помилки з типами дають однакові 60 балів: у підзадачах 1 і 2 усі величини — `n ≤ 10⁹`, `i · i ≤ 31 623² = 1 000 014 129`, периметр `≤ 1 999 999 876` — вміщуються в `int`. Підзадача 3 ламає кожну з них:

- `int i` з `i * i <= n`: при `n > 2³¹ − 1` добуток `i * i` переповнюється раніше, ніж стане більшим за `n` (у `int` він узагалі не може перевищити `2³¹ − 1`), і цикл не зупиняється — перевищення часу на всіх тестах з `n > 2³¹ − 1` і на тесті 21 (`n = 2³¹ − 1`);
- усі змінні `int`: число `n > 2³¹ − 1` не читається в `int` (після невдалого читання в `n` опиняється `2³¹ − 1`), а умова `i * i <= n` в `int` завжди істинна — теж перевищення часу;
- периметр у `int`: неправильна відповідь лише там, де периметр більший за `2³¹ − 1` (тести 19, 21, `b-prime`). Наприклад, тест 21 (`n = 2³¹ − 1`, просте) дає периметр 0 замість `4 294 967 296 = 2³²`.

Ці результати отримано запуском `інструменти/перевірити.py` на відповідних розв'язках, а не виведено теоретично.

## Методичні примітки

1. Почніть із квадратних плиток або клітинок у зошиті: нехай учні викладуть усі прямокутники з 12 і з 36 клітинок. Вони самі помітять, що прямокутники йдуть парами `a × b` і `b × a`, а квадрат 6 × 6 пари не має.
2. Випишіть пари для 36 у стовпчик: `1 × 36, 2 × 18, 3 × 12, 4 × 9, 6 × 6`. Менша сторона зростає, більша спадає, і вони «зустрічаються» біля `√36 = 6`. Звідси і межа циклу, і те, що найменший периметр — в останньої пари. Для 8–9 класів можна показати тотожність `(a + b)² = (b − a)² + 4n`.
3. Попросіть оцінити кількість кроків перебору до `n` при `n = 10¹²` і до `√n`. Дайте здати перебір до `n` (30 балів) і версію з `int` (60 балів). Важливо показати, що `int i` ламає навіть правильну ідею: `i * i` переповнюється раніше, ніж стає більшим за `n`.
4. Окремо обговоріть тест 21 (`n = 2³¹ − 1`): периметр `2³²` у 32-бітному `int` перетворюється на 0.
5. Продовження: сума дільників; вивести всі дільники за зростанням (AtCoder ABC 180 C — дві половини списку); кількість дільників багатьох чисел (CSES 1713); тривимірний варіант — скільки є прямокутних паралелепіпедів `a × b × c` з `n` кубиків і яка в них найменша площа поверхні.
