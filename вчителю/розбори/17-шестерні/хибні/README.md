# 17. Шестерні — хибні розв'язки для режиму «Злам»

Кожен файл тут проходить усі приклади з умови, але містить типову помилку учнів. Завдання учня — скласти **коректний** тест, на якому розв'язок помиляється або не встигає. Перевірка тесту:

```
python інструменти/перевірити.py --зламати 17 мій-тест.in          # проти всіх хибних розв'язків
python інструменти/перевірити.py --зламати 17 мій-тест.in х1.cpp   # лише проти одного
```

Скрипт спершу перевіряє тест [валідатором](../валідатор.py): тест, що порушує обмеження умови, нічого не доводить. Правильну відповідь дає еталон. Крок помилки — за таблицею з [АНАЛІЗ-ПОМИЛОК](../../../АНАЛІЗ-ПОМИЛОК.md).

| Файл | Що не так | Крок за АНАЛІЗ-ПОМИЛОК | Найменший ламаючий тест (вхід → правильна відповідь / що виводить хибний) | Які тести репозиторію його ловлять | Бали на тестах репозиторію (за підзадачами) |
|---|---|---|---|---|---|
| [х1.cpp](х1.cpp) | `int a, b; long long l = a * b / g;` — добуток обчислюється в `int` ще до присвоювання в `long long`. | 4 — типи даних | `46341 46341` → `46341 46341` / `46341 -46340` | неправильна відповідь: `10`, `11`, `14`, `15`, `16`, `17`, `b-rand1`, `b-rand2`, `b-rand3`, `b-common`, `b-mult`, `b-coprime` | **30** (підзадачі: 1 — так, 2 — ні) |
| [х2.cpp](х2.cpp) | НСК шукається перебором кратних `max(a, b)`: до 10⁹ кроків для взаємно простих чисел. | 3 — оцінка складності | `999999999 1000000000` → перевищено час (2.74 с) | час: `10`, `11`, `17`*, `b-rand3`*, `b-coprime` | **30** (підзадачі: 1 — так, 2 — ні) |

Бали й списки тестів отримано запуском `python інструменти/перевірити.py 17 вчителю/розбори/17-шестерні/хибні/<файл>` (g++ 13, Python 3.12, WSL); ламаючі тести перевірено режимом `--зламати`.
`*` — перевищення часу менш ніж удвічі: на швидшому комп'ютері цей тест може й пройти.
