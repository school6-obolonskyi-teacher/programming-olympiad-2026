# Розбір: 20. Цукерки навпіл

Умова: [задачі/20-цукерки-навпіл/умова.md](../../../задачі/20-цукерки-навпіл/умова.md) · Тема: [рекурсія та перебір](../../../учням/теми/13-рекурсія-та-перебір.md)

## Ідея алгоритму

Кожен розподіл пакетиків однозначно задається множиною пакетиків, які дісталися Данилові. Таких множин `2ⁿ`: для кожного з `n` пакетиків є два варіанти. Якщо Данило отримав `s` цукерок, а всього їх `total`, то в Марка `total − s`, і різниця дорівнює

```
|s − (total − s)| = |total − 2s|.
```

Отже, достатньо перебрати всі `2ⁿ` розподілів, для кожного знати `s` і взяти найменше `|total − 2s|`. При `n ≤ 20` це щонайбільше `2²⁰ = 1 048 576` розподілів.

### Спосіб 1: рекурсія (еталон.cpp)

Функція `go(i, sumA)` знає, що пакетики `0 … i−1` уже розподілено і Данило має `sumA` цукерок. Вона пробує віддати пакетик `i` Данилові (`go(i+1, sumA + pᵢ)`) і Маркові (`go(i+1, sumA)`). Коли `i = n`, розподіл завершено, і оновлюється відповідь.

Дерево викликів — повне двійкове дерево глибини `n`: `2ⁿ` листків і `2ⁿ⁺¹ − 1` викликів, тобто близько `2,1·10⁶` при `n = 20`.

### Спосіб 2: бітові маски

Числа від `0` до `2ⁿ − 1` — це рівно всі набори з `n` бітів. Біт `i` числа `mask` (`mask >> i & 1`) показує, чи дістався пакетик `i` Данилові. Для кожної маски сума рахується циклом по бітах за `O(n)`, усього `O(2ⁿ · n) ≈ 2·10⁷` операцій. Для C++ це дрібниці (0,08 с на наших тестах), для Python — ні (див. таблицю нижче).

### Спосіб 3: список сум, що подвоюється (еталон.py)

Спочатку список сум `[0]` (ще жодного пакетика не розподілено). Обробляючи пакетик `x`, до кожної наявної суми додаємо варіант «з цим пакетиком»:

```
sums = sums + [s + x for s in sums]
```

Після `k` пакетиків у списку `2ᵏ` сум — суми всіх підмножин перших `k` пакетиків. Загальна робота `1 + 2 + 4 + … + 2ⁿ⁻¹ < 2ⁿ` додавань. Це той самий перебір, тільки без викликів функцій: у Python генератор списку працює значно швидше, ніж мільйони рекурсивних викликів.

## Обґрунтування правильності

Усі три способи розглядають **кожен** із `2ⁿ` розподілів рівно один раз і для кожного обчислюють точну різницю `|total − 2s|`. Тому знайдений мінімум — справжній мінімум. Розподіли «Данилові множина `A`» і «Данилові доповнення `A`» дають однакову різницю. Перебір розглядає обидва, що зайве, але не шкодить. Окремий випадок `n = 1` обробляється сам собою: розподіли «усе Данилові» і «усе Маркові» теж перебираються.

### Чому не працює жадібне правило

Правило «перебирати пакетики від найбільшого до найменшого і віддавати черговий тому, у кого зараз менше» природне, але хибне. Перевірено запуском:

| Пакетики | Жадібний розподіл | Різниця | Оптимум |
|---|---|---|---|
| `3 3 2 2 2` (тест `03`) | `3+2+2 = 7` і `3+2 = 5` | 2 | `3+3` і `2+2+2` — **0** |
| `8 7 6 5 4` (тест `12`) | `8+5+4 = 17` і `7+6 = 13` | 4 | `8+7` і `6+5+4` — **0** |

Задача про поділ на дві рівні частини (англ. *partition problem*) не має відомого швидкого точного алгоритму для довільних великих чисел. Саме тому обмеження `n ≤ 20` підказує перебір.

## Складність

- Рекурсія: час `O(2ⁿ)`, пам'ять `O(n)` (глибина рекурсії `n ≤ 20` — безпечна навіть для Python).
- Маски: час `O(2ⁿ · n)`, пам'ять `O(n)`.
- Подвоєння списку: час `O(2ⁿ)`, пам'ять `O(2ⁿ)` — близько 75 МБ у Python при `n = 20` (виміряно), що вкладається в 256 МБ.

Чому `2²⁰` устигає: `2²⁰ ≈ 10⁶`, а за 1 с C++ виконує порядку `10⁸` простих операцій. Навіть `2²⁰ · 20 ≈ 2·10⁷` (маски з внутрішнім циклом) устигає із запасом. А от `2⁴⁰ ≈ 10¹²` уже не встигне ніде. Тому перебір підмножин — інструмент для `n` приблизно до 20–25.

Виміряний час на найбільших тестах (`n = 20`): еталон на C++ — 0,01 с; еталон на Python (подвоєння списку) — 0,2–0,5 с; рекурсія на Python — 0,3–0,8 с у різних запусках.

**Тип даних.** Сума всіх цукерок сягає `20 · 10⁹ = 2·10¹⁰ > 2³¹ − 1 ≈ 2,1·10⁹`, тож у C++ потрібен `long long`. У підзадачі 1 сума не більша за `10 · 1000 = 10⁴`.

## Часткові розв'язки за підзадачами

| Розв'язок | Підзадачі | Бали |
|---|---|---|
| Рекурсія (C++) із сумами в `int` | 1 | 40 |
| ДП «які суми можна набрати» (рюкзак) з масивом розміру `total + 1` | 1 | 40 |
| Маски з циклом по бітах на Python, `O(2ⁿ · n)` | 1 | 40 |
| Жадібне правило «найбільший — тому, у кого менше» | — | 0 |
| Перебір лише розподілів, де кожен отримує хоча б один пакетик | — | 0 |
| Маски з циклом по бітах на C++ | 1, 2 | 100 |
| Рекурсія на Python | 1, 2 | 100 |
| Еталон (C++ або Python) | 1, 2 | 100 |

Подробиці (усе перевірено запуском `інструменти/перевірити.py`):

- **`int`.** Розв'язок не пройшов `full-a`, `full-c`, `full-f`. Цікаво, що на тестах `06` (двадцять пакетиків по `10⁹`) і `07` він випадково видав правильні відповіді, хоча сума там переповнюється. Переповнення не завжди проявляється, тому тестів на нього має бути кілька.
- **ДП за сумою.** Масив розміру `total + 1` при `total` до `2·10¹⁰` не вміщається в пам'ять. На наших тестах були перевищення часу та `std::bad_alloc`; запускали з обмеженням віртуальної пам'яті 1,5 ГБ, на олімпіаді обмеження 256 МБ. Для підзадачі 1 (сума до `10⁴`) такий розв'язок працює миттєво. Це хороший місток до [теми 14](../../../учням/теми/14-динамічне-програмування.md).
- **Маски на Python** працювали 1,7–2,3 с на тестах із `n = 20`.
- **Рекурсія на Python** у наших запусках укладалася в 1 с (0,3–0,8 с), але із малим запасом. На повільнішому сервері результат може бути іншим. Тому еталон на Python використовує подвоєння списку.
- **«Кожному хоча б один пакетик»** (маски від `1` до `2ⁿ − 2`) при `n = 1` не розглядає жодного розподілу і виводить «нескінченність». Тест `13` (`n = 1`) входить до підзадачі 1, тому такий розв'язок отримує 0.

## Типові помилки учнів

| Помилка | Симптом | Як виявити |
|---|---|---|
| Сума в `int` | Неправильні відповіді, але не на всіх великих тестах | `full-a`, `full-c`, `full-f` |
| Жадібний розподіл | Різниця більша за оптимальну | Тести `03`, `12`, більшість випадкових |
| Вимога «кожному хоча б один пакетик» | Неправильна відповідь при `n = 1` | Тести `02`, `13` |
| Повільний перебір на Python (маски з циклом по бітах) | Перевищення часу при `n = 20` | Тести `06`, `08`–`10`, `full-*` (частина з них — залежно від швидкості комп'ютера) |

## Методичні примітки

1. Почніть із питання «скільки способів поділити 3 пакетики?» і намалюйте дерево рішень: на кожному рівні — «Данилові» чи «Маркові». Дерево рекурсії і є цим малюнком.
2. Покажіть, що листки дерева відповідають числам від `000` до `111` у двійковому записі. Це природний перехід від рекурсії до бітових масок.
3. Запропонуйте класу знайти контрприклад до жадібного правила. `3 3 2 2 2` знаходять за кілька хвилин, і це добре закріплює думку з [теми 12](../../../учням/теми/12-два-вказівники-та-жадібні.md): жадібне правило треба доводити.
4. Порівняйте на уроці час рекурсії, масок і подвоєння списку в Python при `n = 20`. Учні наочно бачать, що в Python виклик функції і внутрішній цикл «коштують» дорого.
5. Продовження: якщо `pᵢ` маленькі, а `n` велике, працює ДП за сумою ([тема 14](../../../учням/теми/14-динамічне-програмування.md)). Якщо `n ≤ 40`, допомагає прийом «зустріч посередині»: перебрати окремо дві половини і поєднати відсортовані списки сум.
