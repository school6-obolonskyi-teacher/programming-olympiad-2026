# 11. Анаграми — хибні розв'язки для режиму «Злам»

Кожен файл тут проходить усі приклади з умови, але містить типову помилку учнів. Завдання учня — скласти **коректний** тест, на якому розв'язок помиляється або не встигає. Перевірка тесту:

```
python інструменти/перевірити.py --зламати 11 мій-тест.in          # проти всіх хибних розв'язків
python інструменти/перевірити.py --зламати 11 мій-тест.in х1.cpp   # лише проти одного
```

Скрипт спершу перевіряє тест [валідатором](../валідатор.py): тест, що порушує обмеження умови, нічого не доводить. Правильну відповідь дає еталон. Крок помилки — за таблицею з [АНАЛІЗ-ПОМИЛОК](../../../АНАЛІЗ-ПОМИЛОК.md).

| Файл | Що не так | Крок за АНАЛІЗ-ПОМИЛОК | Найменший ламаючий тест (вхід → правильна відповідь / що виводить хибний) | Які тести репозиторію його ловлять | Бали на тестах репозиторію (за підзадачами) |
|---|---|---|---|---|---|
| [х1.cpp](х1.cpp) | Порівнюються довжини й суми кодів літер: різні набори літер можуть мати однакову суму. | 2 — ідея | `ac`<br>`bb` → `NO` / `YES` | неправильна відповідь: `10`, `17`, `r1000-sumtrap-lower`, `r1000-sumtrap-mixed`, `big-sumtrap` | **0** (підзадачі: 1 — ні, 2 — ні, 3 — ні) |
| [х2.cpp](х2.cpp) | Перевірка лише в один бік: кожна літера `s` є в `t` не менше разів; зайвих літер у `t` не помічено. | 2 — ідея | `a`<br>`ab` → `NO` / `YES` | неправильна відповідь: `05`, `13`, `big-difflen` | **0** (підзадачі: 1 — ні, 2 — ні, 3 — ні) |
| [х3.cpp](х3.cpp) | «Знайти й викреслити» через `find` + `erase`: правильно, але O(n²) при довжині до 10⁶. | 3 — оцінка складності | **великий тест:** два слова по 10⁶ літер `a` (команда нижче) → перевищено час (понад 3 с) | час: `big-yes-lower`, `big-yes-mixed`, `big-yes-small`, `big-no-mixed`, `big-sumtrap`, `big-set` | **60** (підзадачі: 1 — так, 2 — так, 3 — ні) |

Бали й списки тестів отримано запуском `python інструменти/перевірити.py 11 вчителю/розбори/11-анаграми/хибні/<файл>` (g++ 13, Python 3.12, WSL); ламаючі тести перевірено режимом `--зламати`.

## Як створити довгі тести

Довгий тест зручно створити однорядковою командою Python, що сама записує файл `t.in` (перенаправлення `>` у Windows PowerShell 5.1 записує файл у кодуванні UTF-16, і валідатор його не прийме).

- [х3.cpp](х3.cpp) — два слова по 10⁶ літер `a`:

  ```
  python -c "open('t.in','w').write('a' * 10**6 + '\n' + 'a' * 10**6 + '\n')"
  ```
