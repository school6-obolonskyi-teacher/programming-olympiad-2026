# Розбір: 03. Трикутник

Умова: [задачі/03-трикутник/умова.md](../../../задачі/03-трикутник/умова.md) · Тема: [розгалуження](../../../учням/теми/02-розгалуження.md)

## Ідея алгоритму

Трикутник з ненульовою площею зі сторонами `a`, `b`, `c` існує тоді й лише тоді, коли виконуються три **строгі** нерівності трикутника:

```
a + b > c   і   a + c > b   і   b + c > a
```

Їх записуємо однією складною умовою через `&&` (`and`). Інший варіант — упорядкувати сторони за зростанням і перевірити лише одну нерівність: сума двох менших більша за найбільшу.

У C++ суми обчислюємо в `long long`, бо `a + b` може сягати `4·10⁹`.

## Обґрунтування правильності

**Якщо трикутник існує**, то кожна його сторона коротша за ламану з двох інших сторін (відрізок — найкоротший шлях між двома точками), а рівність можлива лише тоді, коли третя вершина лежить на відрізку, тобто трикутник плаский і має нульову площу. Тому всі три нерівності строгі.

**Якщо всі три нерівності виконуються**, трикутник можна побудувати: покладемо сторону `c` на пряму, проведемо з її кінців кола радіусів `b` і `a`. Кола перетинаються поза прямою саме тоді, коли `|a − b| < c < a + b`, а це і є наші три нерівності.

Чому достатньо однієї нерівності для найбільшої сторони: якщо `c` — найбільша, то `a + c > b` і `b + c > a` виконуються автоматично (`c ≥ b`, `a ≥ 1`). Тому, наприклад, перевірка лише `a + b > c` без визначення найбільшої сторони — помилка: вона пропускає випадок, коли найбільша сторона стоїть першою чи другою.

**Про тип даних.** Сторони до `2·10⁹` уміщуються в `int` (`2³¹ − 1 ≈ 2,147·10⁹`), а їхні суми — ні. Можна залишитися в `int`, якщо переписати нерівності через різниці: `c − a < b` тощо. Різниця двох чисел від 1 до `2·10⁹` лежить у межах `±2·10⁹` і переповнення не дає.

Повільний розв'язок незалежно перевіряє відповідь за формулою Герона: `16·S² = (a + b + c)(−a + b + c)(a − b + c)(a + b − c) > 0` (подробиці в коментарі до [повільний.py](повільний.py)).

## Складність

- Час: O(1).
- Пам'ять: O(1).

## Часткові розв'язки за підзадачами

| Розв'язок | Підзадачі | Бали |
|---|---|---|
| Три нерівності в `int` (C++) | 1 | 50 |
| Сортування і одна нерівність в `int` (C++) | 1 | 50 |
| Три нерівності через різниці (`c − a < b`) в `int` | 1, 2 | 100 |
| Нестрогі нерівності `≥` | — | 0 |
| Лише одна нерівність `a + b > c` без сортування | — | 0 |
| `\|\|` замість `&&` (`or` замість `and`) | — | 0 |
| Еталон: три нерівності в `long long`; або сортування в `long long`; або Python | 1, 2 | 100 |

`int`-версія з трьома нерівностями помиляється на тестах 15, 17, 18, 22, `big3`, `big4`. `int`-версія із сортуванням — лише на 15, 22, `big4`, бо після сортування додаються дві менші сторони, і в тестах 17 (`1` і `2·10⁹`) та 18 (`10⁹` і `10⁹`) сума ще вміщується в `int`. Саме для неї потрібні тести на кшталт 22 (`1,5·10⁹ 1,5·10⁹ 1,6·10⁹`) і `big4`, де навіть дві менші сторони разом перевищують `2³¹ − 1`.

Ці результати перевірено запуском `інструменти/перевірити.py` на навмисно недосконалих розв'язках, а не виведено теоретично.

## Методичні примітки

1. Почніть з експерименту: учні намагаються скласти трикутники з паличок чи смужок паперу довжиною 2, 3, 6 і 2, 3, 5. Нерівність трикутника вони сформулюють самі.
2. Обговоріть, чому нерівність строга: у пласкому «трикутнику» `1 2 3` третя вершина лежить на стороні.
3. Порівняйте два підходи: «перевірити всі три нерівності» і «знайти найбільшу сторону». Другий вимагає або сортування, або кількох `if` — гарна вправа на розгалуження.
4. Покажіть, що `int`-версія набирає 50 балів, і запропонуйте два виправлення: `long long` або нерівності через різниці.
5. Продовження: визначити вид трикутника (гострокутний, прямокутний, тупокутний) за знаком `a² + b² − c²` для найбільшої сторони `c`. Там при `c ≤ 2·10⁹` квадрати сягають `4·10¹⁸`, що ще вміщується в `long long`.
