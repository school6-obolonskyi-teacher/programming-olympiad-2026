# Розбір: 32. Опади з уточненнями

Умова: [задачі/32-опади-з-уточненнями/умова.md](../../../задачі/32-опади-з-уточненнями/умова.md) · Тема: [дерево Фенвіка](../../../учням/теми/20-дерево-фенвіка.md)

Задача продовжує [13. Опади](../13-опади/розбір.md). Запити типів 1 і 2 (присвоєння і сума) — у точності приклад із [теми 20](../../../учням/теми/20-дерево-фенвіка.md). Нове — запит типу 3: «перший день, коли сума з початку досягла `S`», тобто двійковий пошук ([тема 09](../../../учням/теми/09-двійковий-пошук.md)) по префіксних сумах масиву, що змінюється.

## Ідея алгоритму

**Структура.** Тримаємо дерево Фенвіка `t` над масивом `a` і копію самого масиву. Елемент `t[i]` зберігає суму `a[i − lowbit(i) + 1 .. i]`, де `lowbit(i) = i & −i`.

- **`1 i x`** — присвоєння `aᵢ := x` перетворюємо на додавання: `add(i, x − aᵢ)`, потім `aᵢ = x`. Без копії масиву старого значення не дізнатися.
- **`2 l r`** — `prefix(r) − prefix(l − 1)`, як у задачі 13.
- **`3 S`** — шукаємо найменше `r` з `prefix(r) ≥ S`. Усі `aᵢ ≥ 0`, тож `prefix(r)` не спадає зі зростанням `r`. Отже, умова «`prefix(r) ≥ S`» хибна для всіх `r` до якогось місця і істинна після нього — це класичний пошук першого `true` з теми 09. Два способи:

  1. **Двійковий пошук за `r`**, де кожна перевірка — `prefix(mid)`: O(log² n) на запит. Пошук має бути саме «перший `true`» (запам'ятати `mid` і йти ліворуч), а не «зупинитися, коли `prefix(mid) = S`».
  2. **Спуск по дереву** за O(log n). Підтримуємо `pos` — найбільший уже знайдений префікс із сумою, меншою за `S`, і залишок `S − prefix(pos)`. Перебираємо кроки `2^k` від найбільшого (`2^k ≤ n`) до 1: якщо `pos + 2^k ≤ n` і `t[pos + 2^k] < залишок`, то `pos += 2^k`, `залишок −= t[pos]`. Наприкінці відповідь — `pos + 1`, а якщо `pos = n` (навіть уся сума менша за `S`), то `−1`.

Еталони ([еталон.cpp](еталон.cpp), [еталон.py](еталон.py)) використовують спуск; варіант із двійковим пошуком на C++ теж набирає 100 балів (див. таблицю нижче). Спуску в темі 20 немає, тож на занятті його варто показати окремо.

## Обґрунтування правильності

**Присвоєння.** Після `add(i, x − aᵢ)` дерево описує масив, у якому `aᵢ` замінено на `x`, бо всі вузли, що містять позицію `i`, змінилися рівно на `x − aᵢ`. Копія `a` оновлюється одразу, тож наступне уточнення того самого дня візьме правильне старе значення.

**Перший день.** Якщо `aᵢ = 0`, кілька днів поспіль можуть мати однакову префіксну суму. Двійковий пошук, що зупиняється на рівності `prefix(mid) = S`, знайде якийсь день із такою сумою, але не обов'язково перший (тест 03: опади `5 0 0 0 0`, `S = 5`). Пошук «першого `true`» правильний, бо предикат `prefix(r) ≥ S` монотонний: хибний, а потім істинний.

**Спуск.** Перед кроком `2^k` число `pos` кратне `2^(k+1)` (до нього додавали лише більші степені двійки). Тоді `lowbit(pos + 2^k) = 2^k`, і `t[pos + 2^k]` — це рівно сума `a[pos + 1 .. pos + 2^k]`. Інваріант: `prefix(pos) < S`, а `prefix(pos + 2^(k+1)) ≥ S` (або `pos + 2^(k+1) > n`). На кроці `2^k` ми з'ясовуємо, у якій половині відрізка `(pos, pos + 2^(k+1)]` уперше досягається `S`, і після кроку `2^0 = 1` маємо `prefix(pos) < S ≤ prefix(pos + 1)`. Умова строга (`t[…] < залишок`): за рівності `prefix(pos + 2^k) = S` уже досягнуто, і відповідь лежить не правіше за `pos + 2^k`. Нулі цьому не заважають.

## Складність

- Час: O((n + q) · log n). Побудова дерева — O(n log n) через `add` (C++) або O(n), якщо кожен вузол передає суму батькові (Python).
- Пам'ять: O(n) — дерево і копія масиву.
- Суми — до `2·10⁵ · 10⁹ = 2·10¹⁴`, тож `long long`, у тому числі в масиві дерева. `S` теж до `2·10¹⁴`.
- У нашому запуску `інструменти/перевірити.py` еталон на C++ працював до 0,07 с, на Python — до 0,81 с (окремо на тих самих тестах — 0,57–0,74 с).

**Чому обмеження часу 2 с.** Python-еталон з деревом Фенвіка займає 0,6–0,8 с, тобто понад 60 % звичної 1 с: на повільнішому сервері правильний Python-розв'язок міг би не встигнути. Тому обмеження — 2 с, і воно записане в умові. На C++ ні наївні розв'язки, ні перерахунок префіксних сум від цього не встигають (див. таблицю). Якщо на олімпіаді для Python доступний PyPy, для задач із деревами Фенвіка і відрізків варто обирати його.

## Часткові розв'язки за підзадачами

Підзадачі: 1 — `n, q ≤ 1000`; 2 — уточнень немає; 3 — запитів типу 3 немає; 4 — усі тести. Бали «потестово» — як на I–II етапах 2025/2026, коли кожен тест оцінювали окремо.

| Розв'язок | Підзадачі | Бали за підзадачами | Потестово |
|---|---|---|---|
| Масив, сума і пошук дня — циклом, O(n) на запит (C++) | 1 | 20 | 63 |
| Те саме на Python (`sum` по зрізу, цикл по днях) | 1 | 20 | 49 |
| Префіксні суми, після кожного уточнення перераховуються від зміненого дня; день — `lower_bound` | 1, 2 | 45 | 71 |
| Дерево Фенвіка, але день шукається проходом по днях ([х4](хибні/х4.cpp)) | 1, 3 | 45 | 66 |
| Дерево Фенвіка і двійковий пошук за днем, O(log² n) (C++) | 1, 2, 3, 4 | 100 | 100 |
| Те саме на Python | 1, 3 | 45 | 86 |
| Уточнення як додавання ([х1](хибні/х1.cpp)) | 2 | 25 | 40 |
| Двійковий пошук зупиняється на рівності ([х2](хибні/х2.cpp)) | 3 | 25 | 71 |
| Масив дерева типу `int` ([х3](хибні/х3.cpp)) | — | 0 | 37 |
| Еталони (дерево Фенвіка і спуск; C++, Python) | 1, 2, 3, 4 | 100 | 100 |

Подробиці:

- Наївний розв'язок на C++ підсумовує відрізки дуже швидко (компілятор векторизує цикл), і на випадкових відрізках тестів `s3-*` він устигав. Тому в підзадачі 3 є тест `s3-full`, де всі суми — про весь сезон, а між ними уточнення: там наївний розв'язок працював 7,65 с.
- Префіксні суми з перерахунком після кожного уточнення встигають, лише коли уточнень мало (підзадача 2 — їх немає зовсім). На тестах з `10⁵` уточнень — 2,6–4,1 с.
- Двійковий пошук за днем у C++ (0,09 с) — повноцінна альтернатива спуску. На Python той самий розв'язок не встиг на тестах із великою кількістю запитів типу 3 (до 4,04 с при обмеженні 2 с) і набрав 45 балів: тут спуск по дереву справді потрібен.
- Хибні розв'язки докладно описано в [хибні/README.md](хибні/README.md).

Усі результати отримано запуском `інструменти/перевірити.py` на відповідних розв'язках.

## Типові помилки учнів

| Помилка | Симптом | Як виявити |
|---|---|---|
| Уточнення як додавання (`add(i, x)`) або копію масиву не оновлено | Суми завеликі; після другого уточнення того самого дня — неправильні | Тести 05, 06, 11 |
| Двійковий пошук зупиняється на `prefix(mid) = S` | Знайдено не перший день: після нього йдуть дні без опадів | Тести 03, 10, `s2-zero`, `big-exact` |
| Немає відповіді `-1` або `S` порівнюється строго (`>` замість `≥`) | Неправильна відповідь на межі | Тести 02, 04, `s1-over` |
| `int` для сум | Від'ємні або «дивні» суми | Тест 08 (сума `3·10⁹`), `big-max` |
| `int` для масиву дерева (суми в `long long`) | Те саме, але лише коли вузол покриває ≥ 4 днів по `~10⁹` | `s1-rand` і майже всі великі тести |
| Пошук дня проходом по днях | Перевищення часу | `s2-only3`, `big-over` |
| Перерахунок префіксних сум після кожного уточнення | Перевищення часу | `s3-*`, `big-*` |
| Індекс 0 у дереві Фенвіка (нумерація з 0) | Нескінченний цикл в `add` | Будь-який тест з уточненням першого дня |
| `input()` для 2·10⁵ рядків у Python | Повільно | Великі тести |

## Методичні примітки

1. Почніть із підзадач: наївний масив (підзадача 1), задача 13 плюс двійковий пошук по префіксних сумах (підзадача 2), приклад із теми 20 (підзадача 3). Попросіть учнів пояснити, чому підзадача 2 розв'язується без жодної нової структури: префіксні суми не спадають, бо `aᵢ ≥ 0`.
2. Запитайте, що зміниться, якщо дозволити від'ємні `aᵢ`. Префіксні суми перестануть бути монотонними, і двійковий пошук зламається. Це хороший спосіб пояснити, звідки взялася умова `aᵢ ≥ 0`.
3. Тест 03 (`5 0 0 0 0`, `S = 5`) дайте як «злам» для двійкового пошуку з `if (s == S) return mid;`. Висновок для теми 09: шукати треба межу «хибно → істинно», а не рівність.
4. Спуск по дереву пояснюйте через двійковий запис відповіді: старші біти `pos` визначаються першими, як у двійковому пошуку, але кожен крок коштує одне звернення до `t`, а не цілу префіксну суму. Порівняйте на Python O(log² n) і O(log n): у нашому запуску різниця вирішила 55 балів.
5. Продовження: CSES 1143 «Hotel Queries» — той самий спуск, але для максимуму в дереві відрізків; «k-та одиниця в масиві з 0 і 1» — спуск по Фенвіку за кількістю.
