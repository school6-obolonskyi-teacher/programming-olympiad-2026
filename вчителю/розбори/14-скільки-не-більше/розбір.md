# Розбір: 14. Скільки не більше

Умова: [задачі/14-скільки-не-більше/умова.md](../../../задачі/14-скільки-не-більше/умова.md) · Теми: [сортування](../../../учням/теми/08-сортування.md), [двійковий пошук](../../../учням/теми/09-двійковий-пошук.md)

## Ідея алгоритму

Відповідь на запит — кількість чисел `aᵢ ≤ x` — не залежить від порядку чисел. Тому спершу один раз сортуємо масив за неспаданням.

У відсортованому масиві всі числа `≤ x` стоять на початку, а всі числа `> x` — у кінці. Отже, відповідь — це **номер (індекс від 0) першого числа, строго більшого за `x`**, а якщо такого немає, то `n`. Цю межу знаходимо двійковим пошуком за O(log n):

- у C++ — `upper_bound(a.begin(), a.end(), x) - a.begin()`;
- у Python — `bisect_right(a, x)`.

### Двійковий пошук власноруч

На олімпіаді варто вміти написати пошук самостійно: готова функція є не для кожної задачі. Найнадійніший шаблон тримає **інваріант** — твердження, яке істинне перед кожним кроком циклу:

```cpp
// Інваріант: a[lo] <= x (або lo = -1), a[hi] > x (або hi = n).
// Тобто межа між «≤ x» і «> x» лежить між lo і hi.
int lo = -1, hi = n;
while (hi - lo > 1) {
    int mid = lo + (hi - lo) / 2;   // lo < mid < hi
    if (a[mid] <= x) lo = mid;      // a[mid] ≤ x — межа правіше за mid
    else hi = mid;                  // a[mid] > x — межа не правіше за mid
}
// тепер hi = lo + 1: a[lo] ≤ x < a[hi], відповідь — hi
```

- Індекси `−1` і `n` — уявні «стовпчики» поза масивом: `a[−1] = −∞`, `a[n] = +∞`. Їх ніколи не читаємо, бо `mid` завжди строго між `lo` і `hi`.
- Цикл завершується: поки `hi − lo > 1`, маємо `lo < mid < hi`, тож відстань `hi − lo` щоразу зменшується приблизно вдвічі.
- Після циклу `hi = lo + 1`, і за інваріантом рівно `hi` перших чисел (з індексами `0…lo`) не більші за `x`.

Цей код перевірено: як окремий розв'язок він набирає 100 балів.

## Обґрунтування правильності

1. Сортування не змінює набору чисел, отже не змінює відповідь.
2. У відсортованому масиві числа `≤ x` утворюють **префікс**: якщо `a[i] ≤ x` і `j < i`, то `a[j] ≤ a[i] ≤ x`. Тому довжина цього префікса і є відповіддю.
3. Довжина префікса дорівнює індексу першого елемента `> x` — саме його повертають `upper_bound` / `bisect_right` / ручний пошук вище.

## Складність

- Сортування: O(n log n). Кожен запит: O(log n), близько 18 порівнянь при `n = 2·10⁵`.
- Разом O((n + q) log n) часу і O(n) пам'яті.
- На найбільших тестах (`n = q = 2·10⁵`) еталон на C++ працює близько 0,1 с, на Python — близько 0,4 с (з них більшість — читання входу і сортування).

Наївний розв'язок виконує `n · q = 4·10¹⁰` порівнянь і не вкладається в 1 с навіть на C++.

## Типові помилки учнів

| Помилка | Симптом | Як виявити |
|---|---|---|
| `lower_bound` замість `upper_bound` (`bisect_left` замість `bisect_right`), тобто порахували числа `< x`, а не `≤ x` | Перший приклад дає `2 0 6 2` замість `4 0 6 2`: точки з висотою рівно 3 не враховано | Тести 01–05, `s-dup`: рівень води дорівнює висоті, що повторюється |
| Зациклення власного пошуку: `mid = (l + r) / 2` разом із `l = mid` | При `r = l + 1` маємо `mid = l`, і `l` не змінюється — програма не завершується навіть на першому прикладі (перевищення часу на 12 тестах із 13) | Майже будь-який тест з `n ≥ 2`. Виправлення: шаблон `lo/hi` з умовою `hi − lo > 1` або `mid = (l + r + 1) / 2` |
| Забули відсортувати масив | Двійковий пошук на невпорядкованому масиві дає випадкову відповідь (перший приклад: `5 0 6 2`) | Тести 01, 04, 05 (масив за спаданням) |
| Наївний перебір | Перевищення часу | Тести `b-*` |

### Чи страшне переповнення `(l + r) / 2`?

У цій задачі — ні: `l` і `r` — індекси масиву, тож `l + r ≤ 4·10⁵`, що далеко від межі `int` (`2³¹ − 1 ≈ 2,1·10⁹`).

Переповнення стає реальним, коли двійковий пошук ведеться **за значеннями**, а не за індексами (так званий «двійковий пошук за відповіддю»), і межі близькі до `2·10⁹`. Ми перевірили запуском (g++ -O2): для `int l = 1 500 000 000, r = 2 000 000 000` вираз `(l + r) / 2` дав `−397483648`, а `l + (r − l) / 2` — правильні `1750000000`. Формально переповнення знакового `int` — невизначена поведінка, тож результат може бути й іншим. Звідси дві звички: записувати середину як `l + (r − l) / 2` і тримати межі пошуку за значеннями в `long long`.

## Методичні примітки

1. Почніть із наївного розв'язку та оцінки `n · q`. Потім запитайте: «Що, якби висоти були впорядковані?» — учні самі побачать, що затоплені точки утворюють префікс.
2. Ручний двійковий пошук пишіть на дошці разом з інваріантом і уявними елементами `a[−1] = −∞`, `a[n] = +∞`. Попросіть учнів пояснити, чому цикл завершується і чому `mid` ніколи не дорівнює `−1` чи `n`.
3. Дайте здати версію з `lower_bound` — вона набирає 0 балів. Розберіть на першому прикладі, чим відрізняються «перше `≥ x`» і «перше `> x`».
4. Продовження: «скільки чисел на відрізку `[L, R]`» — це `upper_bound(R) − lower_bound(L)`; «скільки чисел строго менших за `x`» — `lower_bound(x)`. Далі — двійковий пошук за відповіддю ([тема 09](../../../учням/теми/09-двійковий-пошук.md)), де й з'являється ризик переповнення `(l + r) / 2`.
