# Розбір: 21. Сходинки

Умова: [задачі/21-сходинки/умова.md](../../../задачі/21-сходинки/умова.md) · Теми: [динамічне програмування](../../../учням/теми/14-динамічне-програмування.md), [рекурсія та перебір](../../../учням/теми/13-рекурсія-та-перебір.md)

## Ідея алгоритму

Це «перша задача» на одновимірне ДП. Чотири складники розв'язку варто проговорити окремо.

- **Стан.** `dp[i]` — найменша енергія, з якою можна дійти зі сходинки `1` до сходинки `i`, з урахуванням цін обох сходинок.
- **Перехід.** На сходинку `i` (при `i ≥ 3`) Іринка потрапляє останнім кроком або зі сходинки `i − 1`, або зі сходинки `i − 2`:

  ```
  dp[i] = cᵢ + min(dp[i − 1], dp[i − 2]).
  ```

- **База.** `dp[1] = c₁` (Іринка вже стоїть на першій сходинці і платить за неї). `dp[2] = c₁ + c₂`, бо на другу сходинку можна потрапити лише з першої. Інший варіант — завести фіктивне `dp[0] = +∞`.
- **Порядок обчислення.** За зростанням `i`: щоб обчислити `dp[i]`, потрібні вже готові `dp[i − 1]` і `dp[i − 2]`.
- **Відповідь.** `dp[n]`.

## Обґрунтування правильності

Доведемо індукцією за `i`, що `dp[i]` дорівнює найменшій вартості шляху від `1` до `i`.

База очевидна: до сходинки `1` є лише «порожній» шлях (вартість `c₁`), до сходинки `2` — лише шлях `1 → 2`.

Крок. Розгляньмо будь-який шлях до сходинки `i ≥ 3`. Його передостання сходинка — `i − 1` або `i − 2`, бо крок має довжину 1 або 2. Частина шляху до передостанньої сходинки `j` — це шлях від `1` до `j`, і за припущенням індукції його вартість не менша за `dp[j]`. Тому вартість усього шляху не менша за `cᵢ + dp[j] ≥ cᵢ + min(dp[i−1], dp[i−2])`. З іншого боку, ця величина досягається: беремо найкращий шлях до кращої з двох сходинок і робимо один крок. Отже, формула дає точний мінімум.

Ключове спостереження (**оптимальна підструктура**): майбутнім крокам байдуже, яким шляхом Іринка дійшла до сходинки `j`, важить лише вартість. Тому досить пам'ятати одне число на сходинку.

### Чому не працює жадібне правило

Правило «щоразу ступати на дешевшу з двох наступних сходинок» хибне. На тесті `03` (`0 1 2 100 0`) воно йде `1 → 2 → 3 → 5` і витрачає `3`, хоча шлях `1 → 3 → 5` коштує `2`. Перевірено запуском: жадібний розв'язок набирає 0 балів.

### Відновлення шляху (вправа для учнів)

Після заповнення `dp` шлях відновлюється з кінця: стоячи на сходинці `i > 1`, переходимо на `i − 1`, якщо `dp[i] − cᵢ = dp[i − 1]`, інакше на `i − 2`. Перевірений фрагмент (масив з індексами від 1):

```python
path = [n]
i = n
while i > 1:
    i = i - 1 if dp[i] - c[i] == dp[i - 1] else i - 2
    path.append(i)
path.reverse()          # для прикладу 1: 1 3 4 6
```

Інший спосіб — під час обчислення зберігати в масиві `prev[i]`, звідки прийшов мінімум.

## Порівняння: рекурсія, рекурсія із запам'ятовуванням, цикл

| Підхід | Час | Що відбувається на практиці |
|---|---|---|
| Рекурсивний перебір усіх шляхів або `f(i) = cᵢ + min(f(i−1), f(i−2))` без запам'ятовування | Експоненційний (≈ `1,62ⁿ`) | Шляхів від `1` до `n` стільки, скільки чисел Фібоначчі: при `n = 20` їх `6765`. Функція `f` робить `13 529` викликів при `n = 20` і `1 664 079` при `n = 30` (пораховано програмою). При `n = 2·10⁵` — безнадійно |
| Рекурсія із запам'ятовуванням (`memo[i]`) | O(n) | Кожне `f(i)` обчислюється один раз, але глибина рекурсії дорівнює `n` — до `2·10⁵` |
| Цикл за зростанням `i` (еталон) | O(n) | Ні рекурсії, ні проблем зі стеком |

Рекурсія із запам'ятовуванням — це те саме ДП, тільки порядок обчислення визначає рекурсія, а не цикл. Учням корисно побачити обидва записи поруч.

**Пастка Python: глибина рекурсії.** За замовчуванням Python дозволяє близько 1000 вкладених викликів. Ось що показали наші запуски на Python 3.12.3:

- запам'ятовування в словнику без `sys.setrecursionlimit` — `RecursionError` уже на `n = 5000`;
- запам'ятовування в словнику і `sys.setrecursionlimit(10**6)` — 100 балів (до 0,36 с);
- `@functools.lru_cache` і `sys.setrecursionlimit(10**6)` — `RecursionError`: `n = 3000` ще працював, `n = 5000` — уже ні. Виклики через `lru_cache` проходять через функцію, написану на C, а для таких викликів у Python 3.12 діє окреме обмеження глибини, яке `setrecursionlimit` не знімає.

Висновок для учнів: у Python для ДП з `n` до `10⁵`–`10⁶` пишіть цикл.

У C++ рекурсія із запам'ятовуванням глибини `2·10⁵` на нашій системі (Linux, стек 8 МБ) пройшла всі тести. Розмір стека на сервері перевірки може бути іншим, тож цикл і тут надійніший.

## Складність

- Час: O(n). Пам'ять: O(n), але можна обійтися двома змінними (`dp[i−1]` і `dp[i−2]`), якщо шлях відновлювати не треба.
- Виміряний час на найбільших тестах (`n = 2·10⁵`): еталон на C++ — 0,01 с, на Python — 0,12–0,16 с у різних запусках.
- Тип даних: шлях `1, 3, 5, …` містить не більше `n/2 + 2` сходинок, тому кожне `dp[i] ≤ (10⁵ + 2) · 10⁴ ≈ 1,00002·10⁹ < 2³¹ − 1`. У C++ достатньо `int`. Переповнення тут не є пасткою, пасткою є час і глибина рекурсії.

Усі бали отримано запуском `інструменти/перевірити.py` на навмисно недосконалих розв'язках. Рекурсія без запам'ятовування на C++ перевищує обмеження часу вже на `n = 5000` (тест `mid-rand`). На Python на тестах з `n ≥ 5000` вона падає з `RecursionError` (глибина понад 1000 викликів), а на проміжних `n` просто не встигає.

## Типові помилки учнів

| Помилка | Симптом | Як виявити |
|---|---|---|
| Жадібний вибір дешевшої сходинки | Переплата | Тест `03` і більшість випадкових |
| Не сплачено `c₁` або неправильна база | Другий приклад дає `7` замість `12` | Тести `02`, `06` |
| Відповідь `min(dp[n−1], dp[n])` (плутанина з іншою відомою задачею, де можна «вийти» за останню сходинку) | Другий приклад дає `5` | Тести `02`, `06`, `07` |
| Рекурсія без запам'ятовування | Перевищення часу | `mid-rand` і великі тести |
| Глибока рекурсія в Python | `RecursionError` | `mid-rand` (`n = 5000`) і великі тести |

## Методичні примітки

1. Почніть із рекурсивного перебору шляхів і намалюйте дерево викликів для `n = 6`. Учні самі помітять, що `f(3)` обчислюється кілька разів. Це і є мотивація запам'ятовування.
2. Запам'ятовування → цикл: покажіть, що масив `memo` заповнюється рівно в порядку `i = 1, 2, 3, …`, тож рекурсія не потрібна.
3. Чотири питання ДП (стан, перехід, база, порядок) запишіть на дошці як шаблон для всіх наступних задач теми 14.
4. Дайте учням на Python здати рекурсію з `lru_cache` і переконатися, що вона падає навіть із `setrecursionlimit` (перевірено на Python 3.12; на Eolymp зараз Python 3.14 і PyPy, тож перед заняттям перевірте там). Цей досвід запам'ятовується краще за попередження.
5. Вправи-продовження: відновити шлях; дозволити кроки на 1, 2 або 3 сходинки; порахувати **кількість** найдешевших шляхів; зробити так, щоб певні сходинки були зламані (на них ставати не можна).
