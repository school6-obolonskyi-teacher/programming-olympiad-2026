# Розбір: 18. Рюкзак з книжками

Умова: [задачі/18-рюкзак-з-книжками/умова.md](../../../задачі/18-рюкзак-з-книжками/умова.md) · Тема: [два вказівники та жадібні алгоритми](../../../учням/теми/12-два-вказівники-та-жадібні.md)

## Ідея алгоритму

Треба знайти найдовший відрізок `w[l..r]` із сумою `≤ S`.

**Метод двох вказівників («гусениця»).** Тримаємо вікно `[l, r]` і його суму `sum`. Права межа `r` (голова гусениці) проходить по черзі всі книжки:

1. додаємо `w[r]` до `sum`;
2. поки `sum > S`, виймаємо крайню ліву книжку: `sum −= w[l]`, `l += 1`;
3. оновлюємо відповідь довжиною вікна `r − l + 1`.

Якщо книжка `w[r]` сама важча за `S`, цикл у кроці 2 вийме і її: тоді `l = r + 1`, `sum = 0`, довжина вікна 0. Тому окремо розглядати цей випадок не треба, а відповідь 0 виходить сама собою.

**Альтернатива: префіксні суми + двійковий пошук.** `p[0] = 0`, `p[i] = w₁ + … + wᵢ`. Оскільки ваги додатні, `p` строго зростає. Для кожного `r` шукаємо найменше `j` з `p[j] ≥ p[r] − S` (це `lower_bound` / `bisect_left`), і відрізок `w[j + 1..r]` — найдовший, що закінчується на `r`. Час O(n log n). Такий розв'язок ми перевірили на C++ і Python: 100 балів (Python — 0,37 с на найбільшому тесті).

## Обґрунтування правильності

Позначимо через `L(r)` найменше `l`, для якого `w[l] + … + w[r] ≤ S` (або `r + 1`, якщо не поміщається навіть `w[r]`).

**1. Для фіксованого `r` найкращий відрізок — `[L(r), r]`.** Якщо відрізок `[l, r]` поміщається, то поміщається і будь-який коротший `[l', r]` з `l' > l` — бо ми прибираємо книжки з додатною вагою. Отже, відрізки, що закінчуються на `r` і поміщаються, — це рівно `[l, r]` з `l ≥ L(r)`, і найдовший серед них — `[L(r), r]`.

**2. Лівий вказівник ніколи не повертається назад: `L(r + 1) ≥ L(r)`.** Візьмемо будь-яке `l < L(r)`. За означенням `L(r)` відрізок `[l, r]` не поміщається: `w[l] + … + w[r] > S`. Тоді `w[l] + … + w[r + 1] = (w[l] + … + w[r]) + w[r + 1] > S`, бо `w[r + 1] > 0`. Отже, жодне `l < L(r)` не годиться і для `r + 1`.

**3. Алгоритм знаходить саме `L(r)`.** За пунктом 2, коли голова переходить на `r + 1`, хвіст можна не повертати, а лише рухати вперед, поки сума більша за `S`. Він зупиниться на першому `l`, для якого сума `≤ S`, — тобто на `L(r + 1)`.

Відповідь — найбільше `r − L(r) + 1` за всіма `r`, саме її і рахує алгоритм.

### Чому метод не працює для від'ємних чисел

У пункті 2 ми скористалися тим, що `w[r + 1] > 0`: додавання книжки не може зробити переповнений рюкзак легшим. (Для ваг `≥ 0` міркування теж правильне.) Якщо ж числа можуть бути від'ємними, то відрізок, що «не поміщався», після додавання від'ємного числа може почати поміщатися — і хвіст, який уже пішов уперед, треба було б повертати.

Приклад: `w = [1, 1, −2]`, `S = 0`. Два вказівники дають відповідь 1 (хвіст іде вперед уже на першому елементі, бо `1 > 0`), а правильна відповідь — 3: `1 + 1 + (−2) = 0 ≤ 0`. Ми перевірили це запуском. Для довільних знаків потрібні інші методи (наприклад, префіксні суми з упорядкованою структурою даних).

## Складність

- Час O(n): `r` робить `n` кроків, `l` теж зсувається не більше ніж `n` разів за весь час роботи, тож внутрішній цикл `while` загалом виконується не більше `n` разів, хоч і вкладений у зовнішній.
- Пам'ять O(n) на масив ваг.
- Типи: сума ваг досягає `2·10⁵ · 10⁹ = 2·10¹⁴`, а `S` — `10¹⁸`, тому і `sum`, і `S` — `long long`.
- На найбільших тестах еталон на C++ працює кілька сотих секунди, на Python — менше 0,2 с.

## Часткові розв'язки за підзадачами

| Розв'язок | Підзадачі | Бали |
|---|---|---|
| O(n³): для кожної пари `(l, r)` вага рахується заново (C++) | 1 | 20 |
| O(n²): для кожного `l` розширюємо відрізок вправо, зупиняючись при переповненні (C++) | 1, 2 | 50 |
| Те саме O(n²) на Python | 1 | 20 |
| Префіксні суми + двійковий пошук, O(n log n) (C++, Python) | 1, 2, 3 | 100 |
| Два вказівники, O(n) (C++, Python) | 1, 2, 3 | 100 |
| Два вказівники, але `sum` типу `int` | — | 0 |
| Два вказівники, усі змінні (і `S`) типу `int` | — | 0 |
| Два вказівники з умовою `while (sum > S && l < r)` (вікно не може спорожніти) | — | 0 |
| Два вказівники зі строгою нерівністю (`while (sum >= S)`) | — | 0 |
| «Жадібне скидання»: при переповненні починати заново з поточної книжки | — | 0 |

Розв'язок O(n²) зупиняється, щойно рюкзак переповнюється, тож його час — це `n` помножити на довжину відповіді. На тестах із короткими відповідями (`b-small`, `b-tiny`, `b-mixed`) він встигає, але на тестах із довгими відповідями (`b-rand`, `b-half`, `b-huge`, `b-exact`, `b-ones`) — ні. На Python той самий розв'язок не встигає вже при `n = 5000` (1,36–2,38 с на тестах `s2-rand`, `s2-half`, `s2-huge`).

Усі результати отримано запуском `інструменти/перевірити.py` на відповідних розв'язках.

## Типові помилки учнів

| Помилка | Симптом | Як виявити |
|---|---|---|
| `sum` типу `int` | Сума переповнюється і «не перевищує» `S`: на тесті `s1-rand` відповідь 100 замість 64 | `s1-rand`, `s2-rand`, `s2-half`, `b-rand`, `b-half` |
| `S` типу `int` | `10¹⁸` не вміщується в `int`, читання ламається: неправильні відповіді | Ті самі тести |
| `while (sum > S && l < r)` | Книжка, важча за `S`, залишається у вікні: відповідь 1 замість 0 | Тести 02, 05, `s1-tiny`, `b-tiny` |
| «Жадібне скидання» замість зсуву хвоста | Втрачаються відрізки, що починаються всередині скинутого вікна: приклад 1 дає 3 замість 4, тест 06 (`2 3 1 1`, `S = 5`) — 2 замість 3 | Тести 01, 06 і більшість випадкових |
| Строга нерівність `sum < S` замість `sum ≤ S` | Губляться відрізки з вагою рівно `S` | Тести 01, 04, 06, 08, 09, 11, `b-ones` |
| O(n²) з великим `S` | Перевищення часу | `b-huge`, `b-half`, `b-ones` |

## Методичні примітки

1. Пройдіть шлях O(n³) → O(n²) → O(n) і для кожного кроку оцініть кількість операцій при `n = 5000` і `n = 2·10⁵`. Перехід O(n³) → O(n²) — «не рахувати суму заново», O(n²) → O(n) — «не повертати хвіст».
2. Гусеницю зручно показати на смужці паперу з вагами: два пальці — голова і хвіст. Учні мають самі помітити, що хвіст рухається лише вперед, і пояснити чому (пункт 2 обґрунтування).
3. Обов'язково розберіть контрприклад із від'ємними числами `[1, 1, −2]`, `S = 0`. Це вчить перевіряти умови застосовності методу, а не лише запам'ятовувати шаблон.
4. Порівняйте з задачею F «Мобільна гра» I етапу 2025–2026 (8–11 класи): там двома вказівниками шукають найдовший відрізок із двійок.
5. Продовження: кількість відрізків із сумою `≤ S` (додавати до відповіді `r − l + 1` для кожного `r`), найкоротший відрізок із сумою `≥ S`, CSES 1660 «Subarray Sums I».
