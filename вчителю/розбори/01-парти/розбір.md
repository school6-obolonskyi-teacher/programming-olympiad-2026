# Розбір: 01. Парти

Умова: [задачі/01-парти/умова.md](../../../задачі/01-парти/умова.md) · Тема: [перші програми](../../../учням/теми/01-перші-програми.md)

## Ідея алгоритму

Відповідь — це `n / k`, округлене **вгору**: `⌈n / k⌉`. Цілочисельне ділення округлює вниз, тому перед діленням до `n` додаємо `k − 1`:

```
відповідь = (n + k − 1) / k      (ділення цілочисельне)
```

Жодного `if` не потрібно. Через межу `n, k ≤ 2·10⁹` у C++ обчислення треба вести в `long long`.

## Обґрунтування правильності

Запишемо `n = q·k + r`, де `q = n / k` (цілочисельна частка), а `0 ≤ r ≤ k − 1` — остача.

- Якщо `r = 0` (`n` ділиться на `k`), то потрібно рівно `q` парт. Формула дає `(q·k + k − 1) / k = q`, бо `k − 1 < k`.
- Якщо `1 ≤ r ≤ k − 1`, то `q` парт уміщують лише `q·k < n` учнів, а `q + 1` парта — уже `(q + 1)·k ≥ n`. Отже, відповідь `q + 1`. Формула дає `(q·k + r + k − 1) / k = q + 1`, бо `k ≤ r + k − 1 ≤ 2k − 2 < 2k`.

В обох випадках формула дає найменшу кількість парт `d`, для якої `d·k ≥ n`.

**Про тип даних.** Найбільше проміжне значення `n + k − 1 = 2·10⁹ + 2·10⁹ − 1 ≈ 4·10⁹` більше за `2³¹ − 1 = 2 147 483 647`, тож у 32-бітному `int` воно переповнюється. Самі числа `n` і `k` у `int` уміщуються, тому існують правильні формули без `long long`:

- `(n − 1) / k + 1` — при `n ≥ 1` дає те саме, а проміжні значення не перевищують `n`;
- `n / k + (n % k != 0)` — порівняння в C++ дає `0` або `1`, тому `if` теж не потрібен.

## Складність

- Час: O(1) — кілька арифметичних операцій.
- Пам'ять: O(1).

## Часткові розв'язки за підзадачами

| Розв'язок | Підзадачі | Бали |
|---|---|---|
| `(n + k − 1) / k` у типі `int` (C++) | 1 | 50 |
| `(n + k − 1) / k` у `long long` (еталон) | 1, 2 | 100 |
| `(n − 1) / k + 1` у `int` | 1, 2 | 100 |
| `n / k + (n % k != 0)` у `int` | 1, 2 | 100 |
| `(long long)ceil((double)n / k)` | 1, 2 | 100 |
| `ceil((double)n / k)` без приведення до цілого | — | 0 |
| `(long long)ceil((float)n / k)` | — | 0 |
| `ceil(n / k)` для `int n, k` | — | 0 |
| `n / k + 1` (C++ або Python `int(n / k) + 1`) | — | 0 |
| Python: `math.ceil(n / k)` | 1, 2 | 100 |
| Python: `(n + k − 1) / k` (дробове ділення, виводить `13.0`) | — | 0 |
| `if (n % k == 0) … else …` у `long long` | 1, 2 | 100 |

Чому `int`-версія формули проходить підзадачу 1: там `n, k ≤ 10⁹`, тож `n + k − 1 ≤ 1 999 999 999 < 2³¹ − 1`. У підзадачі 2 на тестах 11, 12, 13, 16, `big2`, `big4` вона виводить `0`, `−1` або `−2`.

Чому `double` тут не підводить: частка `n / k` при `n ≤ 2·10⁹` обчислюється з відносною похибкою не більше `2⁻⁵³`, тобто абсолютною меншою за `2,3·10⁻⁷ / k`, а дробова частина справжньої частки (якщо вона не нульова) не менша за `1 / k`. Тому `ceil` округлює правильно. Але цей запас зникає для чисел порядку `10¹⁸`, а 24-бітний `float` помиляється вже тут (тести 09, `r2`, `big3`). Учням варто радити цілочисельну формулу.

Окрема пастка C++: `cout << ceil(...)` виводить дійсне число, і великі відповіді друкуються як `1e+09` чи `2.26052e+08` (тести 06, 10, 14, `big3`).

Ці результати перевірено запуском `інструменти/перевірити.py` на навмисно недосконалих розв'язках, а не виведено теоретично.

## Типові помилки учнів

| Помилка | Симптом | Як виявити |
|---|---|---|
| `int` замість `long long` для `n + k − 1` | Відповідь `0` або від'ємна | Тест 11: `2000000000 2000000000` |
| `n / k + 1` завжди | На 1 більше, коли `n` ділиться на `k` | Приклад 2: `30 3` |
| `ceil(n / k)` для цілих `n`, `k` | Цілочисельне ділення вже округлило вниз, `ceil` нічого не змінює | Приклад 1: `25 2` дає `12` |
| `/` замість `//` у Python | Виводить `12.5` або `13.0` | Будь-який приклад |
| `ceil` без приведення до цілого (C++) | Виводить `1e+09` | Тест 06: `1000000000 1` |
| `float` замість `double` | Похибка в останніх цифрах | Тест 09: `1000000000 999999999` |
| Розв'язок через `if (n % k == 0)` | Правильно, але це не те, чого вчить задача типу C | — |

## Методичні примітки

1. Почніть із ручного рахунку на кількох парах: `7 3`, `6 3`, `1 5`. Учні самі помітять, що «просто поділити» не завжди достатньо.
2. Попросіть знайти розв'язок **без `if`**. Це тренує мислення формулами, яке потрібне для задач типу C молодшої ліги.
3. Дайте здати `int`-версію і переконатися, що вона набирає лише 50 балів, а потім знайти, на якому тесті і чому. Варто показати і безпечну формулу `(n − 1) / k + 1`.
4. Обговоріть, чому `ceil(n / k)` для цілих `n` і `k` не працює: спершу виконується цілочисельне ділення, а `ceil` отримує вже округлене число.
5. Продовження: Codeforces 1A «Theatre Square» — та сама формула двічі, а добуток двох відповідей до `10¹⁸` вимагає `long long` навіть при вхідних даних у межах `int`.
