# Розбір: 13. Опади

Умова: [задачі/13-опади/умова.md](../../../задачі/13-опади/умова.md) · Тема: [префіксні суми](../../../учням/теми/07-префіксні-суми.md)

## Ідея алгоритму

Позначимо `pref[i] = a₁ + a₂ + … + aᵢ`, причому `pref[0] = 0`. Цей масив будується одним проходом: `pref[i] = pref[i−1] + aᵢ`.

Сума на відрізку `[l, r]` дорівнює

```
a_l + … + a_r = (a₁ + … + a_r) − (a₁ + … + a_(l−1)) = pref[r] − pref[l−1].
```

Отже, після підготовки за O(n) кожна відповідь обчислюється за O(1).

## Обґрунтування правильності

Сума `a₁ + … + a_r` складається з двох частин, що не перетинаються: `a₁ + … + a_(l−1)` і `a_l + … + a_r`. Віднімаючи першу частину від усієї суми, отримуємо рівно другу. При `l = 1` віднімається `pref[0] = 0`, тому окремий випадок не потрібен. Саме для цього масив індексується з 1 і має «зайвий» нульовий елемент.

## Складність

- Час: O(n + q). Побудова масиву займає n кроків, кожне запитання — O(1).
- Пам'ять: O(n) на масив `pref`.
- При `n = q = 2·10⁵` це близько 4·10⁵ простих операцій плюс читання входу. Еталон на C++ працює за соті частки секунди, на Python близько 0,4 с.

Наївний розв'язок (сумувати циклом для кожного запитання) виконує до `n·q = 4·10¹⁰` додавань і не вкладається в 1 с навіть на C++.

## Часткові розв'язки за підзадачами

| Розв'язок | Підзадачі | Бали |
|---|---|---|
| Цикл від `l` до `r` для кожного запитання, сума в `long long` | 1 | 30 |
| Префіксні суми в `int` (32 біти) | 2 | 30 |
| Префіксні суми в `long long` | 1, 2, 3 | 100 |

Чому `int` проходить підзадачу 2: там `aᵢ ≤ 10⁴`, тож найбільша сума — `2·10⁵ · 10⁴ = 2·10⁹ < 2³¹ − 1 = 2 147 483 647`. Тест `big-int-edge` дає рівно `2·10⁹`. У підзадачах 1 і 3 суми сягають `10¹²` і `2·10¹⁴`.

Ці результати перевірено запуском `інструменти/перевірити.py` на навмисно недосконалих розв'язках, а не виведено теоретично.

## Типові помилки учнів

| Помилка | Симптом | Як виявити |
|---|---|---|
| `int` замість `long long` для сум | Неправильна (часто від'ємна) відповідь на великих числах | Тест з усіма `aᵢ = 10⁹` |
| `pref[r] − pref[l]` замість `pref[r] − pref[l−1]` | Втрачається `a_l`, приклад 1 дає `11 7 0` замість `15 7 1` | Запитання з `l = r` |
| Індексація з 0 без зсуву | Вихід за межі масиву або зсув на 1 | Запитання з `l = 1` |
| `endl` після кожної відповіді (C++) | Повільно при `q = 2·10⁵` через скидання буфера | Великі тести |
| `input()` у циклі (Python) | Близько 1–2 с на великих тестах | Великі тести, порівняння з `sys.stdin.buffer.read()` |
| Сумування `sum(a[l-1:r])` у Python | Те саме, що й наївний розв'язок: O(n·q) | Великі тести |

## Методичні примітки

1. Почніть заняття з наївного розв'язку і попросіть учнів оцінити кількість операцій. Це природна мотивація для префіксних сум.
2. Намалюйте на дошці масив і під ним `pref`. Запитання «сума з 2 по 4» учні мають побачити як різницю двох «сходинок».
3. Дайте учням здати `int`-версію і переконатися, що вона набирає лише 30 балів. Це запам'ятовується краще за будь-яке попередження про переповнення.
4. Продовження: двовимірні префіксні суми (сума в прямокутнику) і різницевий масив («додати x на відрізку»). Задача H «Виставка» I етапу 2025–2026 (8–11 кл.) поєднує префіксні суми з префіксними мінімумами.
