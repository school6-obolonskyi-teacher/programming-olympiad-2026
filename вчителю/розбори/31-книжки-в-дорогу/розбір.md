# Розбір: 31. Книжки в дорогу

Умова: [задачі/31-книжки-в-дорогу/умова.md](../../../задачі/31-книжки-в-дорогу/умова.md) · Тема: [двовимірне ДП](../../../учням/теми/19-двовимірне-дп.md)

Задача продовжує [18. Рюкзак з книжками](../18-рюкзак-з-книжками/розбір.md): там книжки мали стояти поспіль, і вистачало двох вказівників. Тут можна брати будь-які книжки, і це класичний рюкзак 0/1. Сам рюкзак повністю розібрано в [темі 19](../../../учням/теми/19-двовимірне-дп.md), тож нове в задачі — **відновлення набору** (`t = 1`).

## Ідея алгоритму

**Значення.** Нехай `dp[i][j]` — найбільша сумарна цікавість, яку можна набрати з перших `i` книжок за сумарної ваги не більше `j`. Тоді `dp[0][j] = 0` і

```
dp[i][j] = max(dp[i−1][j],                    // книжку i не беремо
               dp[i−1][j − wᵢ] + vᵢ)          // беремо, якщо j ≥ wᵢ
```

Відповідь — `dp[n][W]`. Рядок `i` залежить лише від рядка `i − 1`, тож можна тримати один масив `dp[j]` і оновлювати його на місці, перебираючи `j` **справа наліво**: тоді `dp[j − wᵢ]` ще не оновлено і належить «старому» рядку.

**Набір.** Після обробки всіх книжок одновимірний масив зберігає лише значення: з нього вже не видно, яку книжку взяли для якої ваги. Тому під час заповнення запам'ятовуємо одне рішення на кожну пару «книжка, ємність»:

```
take[i][j] = 1, якщо dp[i−1][j − wᵢ] + vᵢ > dp[i−1][j]   (книжку i вигідно взяти)
```

Це `n · (W + 1)` байтів, а не `n · (W + 1)` чисел `long long`. Відновлення — від останньої книжки до першої:

```
j = W
для i = n, n−1, …, 1:
    якщо take[i][j]: книжку i беремо, j −= wᵢ
```

Еталони роблять саме так: [еталон.cpp](еталон.cpp) зберігає рішення в `vector<char>` розміру `n · (W + 1)`, [еталон.py](еталон.py) — по одному рядку `bytes` на книжку.

## Обґрунтування правильності

**Переходи.** Оптимальний набір із перших `i` книжок для ємності `j` або не містить книжки `i` (тоді це оптимальний набір із перших `i − 1` книжок для тієї самої ємності), або містить (тоді решта — оптимальний набір із перших `i − 1` книжок для ємності `j − wᵢ`: якби існував кращий, заміна дала б кращий набір для `(i, j)`). Отже, формула перебирає обидва можливі випадки, і `dp[i][j]` — справді найбільше значення.

**Чому справа наліво.** Коли обчислюємо `dp[j]` для книжки `i`, клітинка `dp[j − wᵢ]` лежить лівіше і при обході справа наліво ще містить значення рядка `i − 1`. Якщо йти зліва направо, `dp[j − wᵢ]` уже може містити книжку `i`, і вона «візьметься» вдруге — це розв'язок іншої задачі, де кожну книжку можна брати скільки завгодно разів.

**Відновлення.** Інваріант: перед розглядом книжки `i` у залишку ємності `j` книжки `1..i` можуть дати цікавість `dp[i][j]`, і саме стільки нам ще бракує. Якщо `take[i][j] = 1`, то `dp[i][j] = dp[i−1][j − wᵢ] + vᵢ`: беремо книжку `i`, і бракує `dp[i−1][j − wᵢ]` з книжок `1..i−1`. Інакше `dp[i][j] = dp[i−1][j]`, і книжку `i` пропускаємо. На кінці (`i = 0`) бракує `dp[0][j] = 0`. Отже, сумарна цікавість вибраних книжок дорівнює `dp[n][W]`, а їхня вага не перевищує `W`, бо `j` не стає від'ємним. Кожну книжку розглядаємо один раз, тож повторів немає.

Чому не можна відновлювати з одновимірного масиву: після всіх книжок `dp[j]` дорівнює `dp[n][j]`, а для перевірки «чи брали книжку `i`» потрібне `dp[i−1][…]`. Наприклад, для однієї книжки вагою 1 і `W = 2` маємо `dp = [0, 1, 1]`; умова `dp[2] = dp[2 − 1] + 1` хибна, і набір виходить порожнім, хоча цікавість 1 (хибний розв'язок [х3](хибні/х3.cpp)).

## Складність

- Час: O(n · W) — до `500 · 5000 = 2,5·10⁶` простих кроків.
- Пам'ять: `W + 1` чисел `long long` для значень і `n · (W + 1)` байтів (до 2,5 МБ) для рішень. Повна двовимірна таблиця `long long` теж уміщується (`501 · 5001 · 8` байтів ≈ 20 МБ), але для `W = 10⁵`, як у CSES 1158, уже ні (400 МБ) — тоді й потрібен «бітовий» варіант.
- У нашому запуску `інструменти/перевірити.py` еталон на C++ працював до 0,01 с, на Python — до 0,46 с (на незавантаженій машині близько 0,3 с) при обмеженні 1 с.

Чому `W ≤ 5000`, а не `10⁴`: при `n · W = 5·10⁶` еталон на Python із відновленням працював 0,6–1,2 с, тобто понад 60 % обмеження в 1 с. На C++ і `n · W = 10⁷` — соті частки секунди. Ми зменшили `W`, а не збільшили обмеження часу, щоб учні, які пишуть на Python, теж могли набрати повні бали без особливих прийомів (див. таблицю нижче).

Цікавість не вміщується в `int`: до `500 · 10⁹ = 5·10¹¹`.

## Методичні примітки

1. Почніть з перебору масок для `n ≤ 20` і з жадібного «за цікавістю на грам». Попросіть учнів самих знайти контрприклад до жадібного (тест 06 або `2 3 / 1 2 / 3 3`): це найкраща мотивація для ДП.
2. Таблицю `dp[i][j]` заповніть на дошці для прикладу 1. Потім покажіть, що рядок залежить лише від попереднього, і перейдіть до одного масиву. Дайте учням самим зламати обхід зліва направо на одній книжці вагою 2 і `W = 4`.
3. Головне нове — відновлення. Спитайте: «Масив `dp` після всіх книжок — як дізнатися, які книжки взято?» Учні зазвичай пропонують перевіряти `dp[j] = dp[j − wᵢ] + vᵢ` в останньому масиві; тест `1 2 1 / 1 1` показує, чому так не можна. Висновок: що забули при стисканні таблиці, доведеться зберегти окремо, але досить одного біта на клітинку.
4. Обговоріть пам'ять: `n · W` чисел `long long` проти `n · W` байтів. У CSES 1158 (`n ≤ 1000`, `x ≤ 10⁵`) таблиця чисел займала б 800 МБ, а таблиця байтів — 100 МБ; без відновлення досить одного рядка.
5. Продовження: рюкзак з необмеженою кількістю предметів (той самий «хибний» обхід зліва направо стає правильним), «чи можна набрати суму рівно S» (`bool` замість цінностей, CSES 1745), ДП за масками ([тема 19](../../../учням/теми/19-двовимірне-дп.md)).
