# 15. Дужки — хибні розв'язки для режиму «Злам»

Кожен файл тут проходить усі приклади з умови, але містить типову помилку учнів. Завдання учня — скласти **коректний** тест, на якому розв'язок помиляється або не встигає. Перевірка тесту:

```
python інструменти/перевірити.py --зламати 15 мій-тест.in          # проти всіх хибних розв'язків
python інструменти/перевірити.py --зламати 15 мій-тест.in х1.cpp   # лише проти одного
```

Скрипт спершу перевіряє тест [валідатором](../валідатор.py): тест, що порушує обмеження умови, нічого не доводить. Правильну відповідь дає еталон. Крок помилки — за таблицею з [АНАЛІЗ-ПОМИЛОК](../../../АНАЛІЗ-ПОМИЛОК.md).

| Файл | Що не так | Крок за АНАЛІЗ-ПОМИЛОК | Найменший ламаючий тест (вхід → правильна відповідь / що виводить хибний) | Які тести репозиторію його ловлять | Бали на тестах репозиторію (за підзадачами) |
|---|---|---|---|---|---|
| [х1.cpp](х1.cpp) | Наприкінці не перевіряється, що стек порожній: незакриті дужки не помічаються. | 5 — реалізація | `(` → `NO` / `YES` | неправильна відповідь: `05`, `09`, `r-open`, `m-open` | **0** (підзадачі: 1 — ні, 2 — ні) |
| [х2.py](х2.py) | Рекурсивний розбір: при глибині вкладення близько 1000 — `RecursionError`. | 3 — оцінка складності | **тест:** 999 дужок `(`, потім 999 дужок `)` (з глибиною 998 — ще проходить) (команда нижче) → помилка виконання (`RecursionError`) | помилка виконання: `r-deep`, `m-valid`, `m-deep`, `m-swap-deep` | **0** (підзадачі: 1 — ні, 2 — ні) |
| [х3.cpp](х3.cpp) | Викреслювання пар `()`, `[]`, `{}` через `find` + `erase`: правильно, але O(n²). | 3 — оцінка складності | **великий тест:** 10⁵ дужок `(`, потім 10⁵ дужок `)` (команда нижче) → перевищено час (понад 3 с) | час: `r-deep`, `m-valid`, `m-deep`, `m-swap`, `m-swap-deep`, `m-retype`, `m-shift`, `m-open`, `m-close`, `m-random` | **0** (підзадачі: 1 — ні, 2 — ні) |

Бали й списки тестів отримано запуском `python інструменти/перевірити.py 15 вчителю/розбори/15-дужки/хибні/<файл>` (g++ 13, Python 3.12, WSL); ламаючі тести перевірено режимом `--зламати`.

## Як створити довгі тести

Довгий тест зручно створити однорядковою командою Python, що сама записує файл `t.in` (перенаправлення `>` у Windows PowerShell 5.1 записує файл у кодуванні UTF-16, і валідатор його не прийме).

- [х2.py](х2.py) — 999 дужок `(`, потім 999 дужок `)` (з глибиною 998 — ще проходить):

  ```
  python -c "open('t.in','w').write('(' * 999 + ')' * 999 + '\n')"
  ```

- [х3.cpp](х3.cpp) — 10⁵ дужок `(`, потім 10⁵ дужок `)`:

  ```
  python -c "open('t.in','w').write('(' * 10**5 + ')' * 10**5 + '\n')"
  ```
