# Розбір: 27. Стрічки

Умова: [задачі/27-стрічки/умова.md](../../../задачі/27-стрічки/умова.md) · Тема: [двійковий пошук](../../../учням/теми/09-двійковий-пошук.md)

## Ідея алгоритму

Позначимо через `pieces(L)` кількість шматків довжиною `L`, які можна нарізати з усіх стрічок:

```
pieces(L) = ⌊a₁ / L⌋ + ⌊a₂ / L⌋ + … + ⌊aₙ / L⌋.
```

Перевірка `can(L)` — «чи `pieces(L) ≥ k`» — виконується одним проходом за O(n).

Якщо `can(L)` істинне, то `can(L − 1)` теж істинне. Тому довжини від 1 до деякого `A` підходять, а всі більші — ні, і відповідь `A` можна знайти **двійковим пошуком за відповіддю** ([тема 09](../../../учням/теми/09-двійковий-пошук.md#двійковий-пошук-за-відповіддю)).

Інваріант: `can(lo)` істинне, `can(hi)` хибне.

- `hi = max aᵢ + 1`: шматок, довший за найдовшу стрічку, не вирізати, тож `pieces(hi) = 0 < k`.
- `lo = 0`: уявна межа «довжину 0 можна завжди». Значення `can(0)` ніколи не обчислюється (там було б ділення на нуль), бо `mid` завжди лежить строго між `lo` і `hi`.

Поки `hi − lo > 1`, беремо `mid = (lo + hi) / 2` і зсуваємо ту межу, на місце якої стає `mid`. Наприкінці `hi = lo + 1`, і відповідь — `lo`. Якщо не підходить жодна довжина, `lo` так і лишається 0, і це саме та відповідь, якої вимагає умова. Окремо розглядати випадок «відповідь 0» не треба.

Інший правильний варіант, ближчий до прикладу в темі 09: спершу перевірити `can(1)` (або `сума aᵢ < k`) і вивести 0, а потім шукати з `lo = 1`. Тоді сума й лічильник мають бути `long long`, див. «Типові помилки».

## Обґрунтування правильності

**1. Скільки шматків дає одна стрічка.** Зі стрічки довжиною `a` можна вирізати `⌊a / L⌋` шматків довжиною `L`: стільки разів `L` вміщується в `a`, а залишок, коротший за `L`, — обрізок. Склеювати не можна, тож шматки з різних стрічок рахуються окремо, і загальна кількість — сума `⌊aᵢ / L⌋`. Через це не можна просто поділити загальну довжину на `k`: у прикладі 1 вийшло б `227 / 8 = 28`, а з `L = 28` нарізається лише `3 + 2 + 1 = 6` шматків.

**2. Монотонність.** Якщо `L' < L`, то `⌊a / L'⌋ ≥ ⌊a / L⌋` для кожної стрічки, тож `pieces(L') ≥ pieces(L)`. Отже, з `can(L)` випливає `can(L')`. Довжини, що підходять, утворюють проміжок `1, 2, …, A` (або їх немає зовсім), і відповідь — його правий кінець.

**3. Інваріант зберігається.** На початку він виконується: `can(0)` істинне за домовленістю, а `pieces(max aᵢ + 1) = 0 < k`, бо `k ≥ 1`. На кожному кроці `lo < mid < hi`, і ми присвоюємо `mid` тій межі, для якої інваріант залишається правильним. Відстань `hi − lo` щоразу зменшується, тож цикл завершується.

**4. Відповідь.** Після циклу `hi = lo + 1`, `can(lo)` істинне, `can(lo + 1)` хибне. За пунктом 2 усі довжини, більші за `lo`, теж не підходять, отже `lo` — найбільша довжина, що підходить. Якщо `lo = 0`, то не підходить навіть `L = 1`, і за умовою треба вивести 0.

## Складність

- Час: O(n · log(max aᵢ)). Пошук робить `⌈log₂(max aᵢ + 1)⌉ ≤ 30` перевірок, кожна — `n` ділень. При `n = 2·10⁵` це близько 6·10⁶ ділень.
- Пам'ять: O(n) на масив довжин.
- Типи: при `L = 1` шматків може бути `2·10⁵ · 10⁹ = 2·10¹⁴`, тому лічильник — `long long`. Межі пошуку не перевищують `10⁹ + 1`, і навіть `lo + hi ≤ 2·10⁹ + 1` ще вміщується в `int`, але в еталоні для одноманітності всі ці змінні — `long long`.
- Виміряний час на найбільших тестах (`n = 2·10⁵`, `aᵢ` до 10⁹): еталон на C++ — до 0,08 с, на Python — від 0,3 до 0,5 с у різних запусках (сам пошук — близько 0,25–0,3 с, решта — запуск інтерпретатора й читання входу).

Перебір усіх `L` від 1 до `max aᵢ` виконує `n · max aᵢ` ділень: у підзадачі 1 це до 10⁶ (встигає навіть на Python), у підзадачі 2 — до `2·10⁵ · 10⁴ = 2·10⁹` (не встигає навіть на C++), у підзадачі 3 — до 2·10¹⁴.

Чому `int` проходить підзадачу 2: там `pieces(L) ≤ a₁ + … + aₙ ≤ 2·10⁵ · 10⁴ = 2·10⁹ < 2³¹ − 1 = 2 147 483 647`. Тест `s2-int` дає рівно 2·10⁹ шматків при `L = 1`. У підзадачі 3 при `L = 1` шматків буває до 2·10¹⁴.

Чому дострокова зупинка рятує `int`: перед черговим додаванням `pieces < k ≤ 10⁹`, а одна стрічка додає не більше `10⁹` шматків, тож лічильник не перевищує `2·10⁹ − 1`.

Усі результати в таблиці отримано запуском `інструменти/перевірити.py` на відповідних розв'язках, а не виведено теоретично.

## Типові помилки учнів

| Помилка | Симптом | Як виявити |
|---|---|---|
| Ділити загальну довжину на `k` (ніби стрічки можна склеювати) | Завелика відповідь: приклад 1 дає 28 замість 25 | Приклад 1, тести 06, 09, 10, 14 |
| Лічильник шматків `int` (межі `lo = 0`, `hi = max aᵢ + 1` або `lo = 1`, `hi = max aᵢ`, `while (lo <= hi)`) | Переповнення, коли пошук перевіряє малу довжину при великій сумі: відповідь 0 замість 2 і 6 | `b-ovf`, `b-ovf6` |
| Окрема перевірка `can(1)` з `int`-лічильником або сума довжин у `int` | Кількість шматків при `L = 1` (до 2·10¹⁴) переповнюється і «стає» меншою за `k`: відповідь 0 | `b-max`, `b-rand`, `b-small` та інші великі тести підзадачі 3 |
| `lo = 1` без перевірки, що `L = 1` підходить | Відповідь 1 замість 0 | Тести 02, 05, 08, 13, `s1-over`, `s2-over` |
| `hi = max aᵢ` замість `max aᵢ + 1` (порушено інваріант «`can(hi)` хибне») | Відповідь на 1 менша, коли відповідь — найдовша стрічка | Тести 04, 06, 11, 14, `s1-one`, `s2-one`, `b-one` |
| Вивести `hi` замість `lo` | Відповідь на 1 більша | Усі тести |
| `while (lo < hi)`, `mid = (lo + hi) / 2`, `lo = mid` | Зациклення, коли `hi = lo + 1` | Приклад 1 і більшість тестів |
| `lo = 0` і `while (lo <= hi)`: `mid` може стати 0 | Ділення на нуль, помилка виконання | Тести 02, 04, 05, 07, 08 та інші з відповіддю 0 або 1 |
| Перебір усіх довжин | Перевищення часу | Перебір згори вниз — тести з малою відповіддю (`s2-small`, `s2-int`); знизу вгору — з великою (`s2-one`, `s2-eq`) |

Про `int`-лічильник варто знати ще одне. Він переповнюється, лише якщо пошук перевіряє довжину, для якої шматків понад `2³¹ − 1`. Які довжини перевіряє пошук, залежить від того, як саме його написано. Варіант `lo = 1`, `hi = max aᵢ`, `mid = (lo + hi + 1) / 2` з перевіркою `can(lo)` наприкінці перевіряє лише довжини, не менші за `(A + 1) / 2`, де `A` — відповідь. А оскільки `pieces(A + 1) < k`, сума довжин менша за `(k + n)(A + 1)`, і для таких довжин шматків менше ніж `2(k + n) ≤ 2 000 400 000 < 2³¹ − 1`. Тому цей варіант з `int`-лічильником не переповнюється на жодному допустимому тесті й набирає 100 балів. Це щасливий збіг, а не правильний вибір типу: досить узяти інші межі (як у варіанті `lo = 0`, `hi = max aᵢ + 1`, що набирає 60 балів) чи змінити обмеження задачі, і розв'язок зламається. Якщо учень здав такий розв'язок, варто розібрати з ним цю оцінку.

## Методичні примітки

1. Почніть із перебору довжин і попросіть учнів оцінити кількість операцій для кожної підзадачі. Потім поставте запитання з підказки 2: «Якщо `L` підходить, чи підходить `L − 1`?» Учні мають самі сформулювати монотонність.
2. Намалюйте на дошці числову вісь довжин: ліворуч «так», праворуч «ні», одна межа. Покажіть, що двійковий пошук шукає саме цю межу, а не елемент масиву. Це той самий шаблон з інваріантом, що й у задачі [14](../../../задачі/14-скільки-не-більше/умова.md), лише замість `a[mid] ≥ x` стоїть `can(mid)`.
3. Обговоріть межі: чому `hi = max aᵢ + 1`, а не `max aᵢ`, і чому `lo = 0` позбавляє від окремого випадку «відповідь 0». Дайте учням здати варіант з `hi = max aᵢ` — він набирає 0 балів через тести з `k = 1`.
4. Дайте учням здати розв'язок з `int`-лічильником і окремою перевіркою `can(1)` — 60 балів. Потім обговоріть два виправлення: `long long` або дострокова зупинка, щойно набрано `k` шматків.
5. Продовження: CSES 1620 «Factory Machines» (найменший час, перевірка з переповненням) і CSES 1085 «Array Division» («мінімізувати найбільшу суму»), обидві є в [темі 09](../../../учням/теми/09-двійковий-пошук.md).
