# 27. Стрічки — хибні розв'язки для режиму «Злам»

Кожен файл тут проходить усі приклади з умови, але містить типову помилку учнів. Завдання учня — скласти **коректний** тест, на якому розв'язок помиляється або не встигає. Перевірка тесту:

```
python інструменти/перевірити.py --зламати 27 мій-тест.in          # проти всіх хибних розв'язків
python інструменти/перевірити.py --зламати 27 мій-тест.in х1.cpp   # лише проти одного
```

Скрипт спершу перевіряє тест [валідатором](../валідатор.py): тест, що порушує обмеження умови, нічого не доводить. Правильну відповідь дає еталон. Крок помилки — за таблицею з [АНАЛІЗ-ПОМИЛОК](../../../АНАЛІЗ-ПОМИЛОК.md).

| Файл | Що не так | Крок за АНАЛІЗ-ПОМИЛОК | Найменший ламаючий тест (вхід → правильна відповідь / що виводить хибний) | Які тести репозиторію його ловлять | Бали на тестах репозиторію (за підзадачами) |
|---|---|---|---|---|---|
| [х1.cpp](х1.cpp) | Лічильник шматків `int`: коли пошук перевіряє малу довжину, кількість шматків понад `2³¹ − 1` переповнюється. | 4 — типи даних | `3 1000000000`<br>`1000000000 1000000000 1000000000` → `2` / `0` | неправильна відповідь: `b-ovf`, `b-ovf6` | **60** (підзадачі: 1 — так, 2 — так, 3 — ні) |
| [х2.cpp](х2.cpp) | `hi = max aᵢ` замість `max aᵢ + 1`: порушено інваріант «`can(hi)` хибне», відповідь «найдовша стрічка» недосяжна. | 5 — реалізація | `1 1`<br>`5` → `5` / `4` | неправильна відповідь: `04`, `06`, `11`, `14`, `s1-one`, `s2-one`, `s2-eq`, `b-one` | **0** (підзадачі: 1 — ні, 2 — ні, 3 — ні) |
| [х3.cpp](х3.cpp) | Перебір `L` згори вниз до першої, що підходить: O(max aᵢ · n), коли відповідь мала. | 3 — оцінка складності | **великий тест:** n = 2·10⁵, `k = 10⁹`, усі `aᵢ = 10⁹` (відповідь 200000) (команда нижче) → перевищено час (понад 3 с) | час: `03`, `12`, `13`, `s2-rand`, `s2-tight`*, `s2-small`, `s2-int`, `s2-int1`, `s2-over`, `s2-sum`, `b-rand`, `b-tight` та ще 6 | **30** (підзадачі: 1 — так, 2 — ні, 3 — ні) |

Бали й списки тестів отримано запуском `python інструменти/перевірити.py 27 вчителю/розбори/27-стрічки/хибні/<файл>` (g++ 13, Python 3.12, WSL); ламаючі тести перевірено режимом `--зламати`.
`*` — перевищення часу менш ніж удвічі: на швидшому комп'ютері цей тест може й пройти.

## Як створити довгі тести

Довгий тест зручно створити однорядковою командою Python, що сама записує файл `t.in` (перенаправлення `>` у Windows PowerShell 5.1 записує файл у кодуванні UTF-16, і валідатор його не прийме).

- [х3.cpp](х3.cpp) — n = 2·10⁵, `k = 10⁹`, усі `aᵢ = 10⁹` (відповідь 200000):

  ```
  python -c "n=200000; open('t.in','w').write(f'{n} {10**9}\n' + ' '.join([str(10**9)] * n) + '\n')"
  ```
