# Індивідуальні заняття з сильним учнем

Структура заняття в [ПЛАН-ЗАНЯТЬ.md](ПЛАН-ЗАНЯТЬ.md#структура-заняття-90-хв) розрахована на гурток. Ця сторінка — для іншого формату: учитель працює з 1–3 сильними учнями (рівні 4–6 [маршруту](../учням/МАРШРУТ.md)), найчастіше на C++.

Сильному учневі бракує не стільки знань, скільки **процесу**: він береться писати код, не оцінивши складності; не пише перебору; не тестує сам; годину сидить над однією задачею. На гуртку цього не видно. Сам на сам видно все — якщо вчитель дивиться на процес, а не лише на вердикт.

## Заняття 90 хвилин

| Хв | Що відбувається | Що робить учитель |
|---|---|---|
| 0–5 | Зошит помилок з домашньої роботи: одна найцікавіша помилка | Питає «на якому кроці?» за [АНАЛІЗ-ПОМИЛОК.md](АНАЛІЗ-ПОМИЛОК.md#класифікація) |
| 5–45 | **Задача «вголос».** Учень розв'язує нову задачу й проговорює все, що думає | Мовчить. Заповнює [бланк спостереження](#бланк-спостереження) |
| 45–55 | **Три питання:** чому розв'язок правильний; яка складність і чому встигне; на якому тесті він міг би помилитися | Слухає, не підказує. Слабке місце записує в бланк |
| 55–75 | **Учитель-суперник.** Учитель складає 2–3 тести проти розв'язку учня (граничні, великі, «злі»). Потім ролі міняються: учень ламає хибні розв'язки (режим [«Злам»](#злам-і-дуель)) | Шукає тест, на якому розв'язок помиляється. Учень пояснює, чому |
| 75–85 | **Хроніка.** Разом дивляться бланк: куди пішов час, де було рішення | Обирає **одну** навичку на тиждень (див. [таблицю](#що-шукати-в-хроніці)) |
| 85–90 | Домашнє завдання | 3–5 задач на цю навичку, раз на два тижні — [віртуальний тур](../учням/СЕЗОН-ТУРІВ.md) |

**Яку задачу брати для частини «вголос».** Нову для учня і **не з репозиторію**: розбори в репозиторії відкриті. Підійдуть задачі з [архіву олімпіад](../довідка/АРХІВ-ЗАДАЧ.md) на Eolymp на рівень вище за впевнений, щоб за 40 хвилин учень дійшов хоча б до часткового розв'язку. Задачі репозиторію лишаються для домашньої роботи й самоперевірки.

**Якщо учнів двоє-троє.** Частину «вголос» проводьте по черзі або паралельно з різними задачами, бланк — на кожного. Частину «суперник» перетворіть на [дуель](#злам-і-дуель).

## Бланк спостереження

Роздрукуйте або скопіюйте у свій файл. Час — хвилини від початку роботи над задачею.

```
Учень: ________   Дата: ________   Задача: ______________________

Хв   Подія                                         Примітка
___  прочитав умову, переказав своїми словами      ________________
___  розв'язав приклад вручну                       ________________
___  назвав обмеження і потрібну складність         ________________
___  перша ідея (яка?)                              ________________
___  почав писати код                               ________________
___  перший власний тест (який?)                    ________________
___  перше відправлення / перевірка скриптом        вердикт: _______
___  написав перебір або стрес-тест                 ________________
___  застряг (на чому?) / змінив ідею                ________________
___  повний розв'язок                               бали: __________

Три питання:  правильність ___  складність ___  злий тест ___   (так / частково / ні)
Навичка на тиждень: _____________________________________________
```

## Що шукати в хроніці

| Що видно в бланку | Навичка на тиждень | Вправа |
|---|---|---|
| Код почався раніше, ніж названо складність | Оцінка складності за обмеженнями | Перед кожною задачею — рядок «n ≤ …, отже O(…)»; [тема 06](../учням/теми/06-складність.md) |
| Немає жодного власного тесту до відправлення | Тестування граничних випадків | Список «Самоперевірка» з умови — до коду; режим «Злам» |
| Немає перебору, хоча повний розв'язок не виходить | Часткові бали | [Потестова стратегія](../учням/ПОРАДИ.md#потестове-оцінювання-не-залишайте-тестів-порожніми): спершу перебір, потім ідея |
| Довгий пошук помилки «очима» | Стрес-тестування | `python інструменти/перевірити.py --stress NN мій.cpp`; [стрес-тест за 5 хвилин](../учням/РЕПЕРТУАР-CPP.md) |
| Ідея є, але реалізація займає вдвічі довше | Репертуар | 3 фрагменти на тиждень «закритою книгою» з [РЕПЕРТУАР-CPP.md](../учням/РЕПЕРТУАР-CPP.md) |
| Понад 25 хвилин без прогресу і без зміни плану | Стратегія туру | [Картка туру](../учням/КАРТКА-ТУРУ.md) на кожному віртуальному турі |
| Правильно, але не може пояснити, чому | Обґрунтування | Після кожної задачі — два речення «чому це правильно» в зошит |

Один тиждень — одна навичка. Через місяць порівняйте бланки: час до першого власного тесту й до першого відправлення має скорочуватися.

## «Злам» і дуель

У репозиторії для кожної задачі є хибні розв'язки з типовими помилками учнів. Учень отримує файл (без опису помилки) і має скласти **коректний** тест, на якому той помиляється:

```
python інструменти/перевірити.py --зламати 13 мій-тест.in
```

Скрипт перевірить, що тест відповідає обмеженням умови, і покаже, які хибні розв'язки зламано. Опис помилок для вчителя — у теках `вчителю/розбори/NN-назва/хибні/`.

**Дуель для двох учнів.** Обидва розв'язують ту саму задачу 30 хвилин. Потім 15 хвилин кожен складає тести проти розв'язку суперника. Бал — за кожен тест, на якому розв'язок суперника помиляється, і мінус бал — за некоректний тест (його відкидає перевірка обмежень). Переможець — той, хто знайшов більше «дірок». Дуель тренує те, чого не тренує жодна кількість розв'язаних задач: шукати помилку в коді, а не лише писати код.

Тест проти розв'язку суперника перевіряє той самий режим: після тесту вкажіть файл суперника (шлях до нього чи назву з теки `хибні/`):

```
python інструменти/перевірити.py --зламати 13 мій-тест.in ../дуель/розвязок-суперника.cpp
```

Скрипт так само спершу перевірить тест валідатором, а правильну відповідь візьме з еталона.

## Індивідуальний план на сезон

Заповнюйте на початку сезону й переглядайте раз на місяць.

| Місяць | Ціль | Що робимо | Контрольна точка |
|---|---|---|---|
| Жовтень | I етап (25.10) | [План на два тижні](../учням/ПЕРЕД-ОЛІМПІАДОЮ.md), трек 3 | Результат I етапу; розбір кожної нерозв'язаної задачі |
| Листопад | Рівень 5 повністю | Слабкі теми рівня 5 за зошитом помилок; репертуар | Віртуальний тур; відбір юніорської олімпіади, якщо учень має право ([ЮНІОРСЬКА.md](../учням/ЮНІОРСЬКА.md)) |
| Грудень–січень | II етап | Рівень 6: графи й теми типу F; тури у форматі II етапу, зокрема [«наосліп»](../учням/ПРОБНИЙ-ТУР.md#режим-наосліп-як-на-ii-етапі) | II етап |
| Лютий–травень | III етап або наступний рік | Глибина рівня 6, CSES, архів III етапу | Віртуальні тури; повторна діагностика |

Що записувати після кожного туру: бали (потестово), час на кожну задачу, одна причина втрачених балів за [кроками](АНАЛІЗ-ПОМИЛОК.md#класифікація). За три-чотири тури видно, що саме стримує учня: знання, швидкість чи стратегія.
