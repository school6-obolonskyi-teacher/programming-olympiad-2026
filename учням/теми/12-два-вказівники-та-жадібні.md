# 12. Два вказівники та жадібні алгоритми

## Що треба зрозуміти

Після цієї теми ви зможете:

1. Застосовувати метод двох вказівників: два індекси рухаються лише вперед, тому замість O(n²) пар розглядається O(n) станів.
2. Розпізнавати типові схеми: найдовший (найкоротший) відрізок з умовою на суму при додатних числах; пара з заданою сумою у відсортованому масиві (вказівники з двох кінців); злиття двох відсортованих масивів.
3. Будувати жадібний алгоритм: на кожному кроці робити вибір, найкращий саме зараз (найчастіше — після сортування).
4. Перевіряти жадібну ідею: шукати контрприклад, доводити аргументом обміну, звіряти з перебором на малих тестах.

## Теорія

### Два вказівники: найкоротший відрізок із сумою не менше S

Дано n **додатних** чисел і S. Знайти найкоротший відрізок підряд, сума якого не менша за S.

Перебір усіх відрізків — O(n²). Але помітимо: якщо праву межу `r` зсунути праворуч, то ліву межу `l` теж вигідно зсувати лише праворуч — повертатися назад немає сенсу, бо відрізок тільки подовжиться. Тож обидві межі рухаються тільки вперед, і між ними завжди лежить «вікно» `[l, r]`.

C++:

```cpp
vector<long long> a = {2, 1, 3, 1, 1, 4, 2};
long long S = 7, sum = 0;
int n = a.size(), best = n + 1, l = 0;   // n + 1 означає «ще не знайдено»
for (int r = 0; r < n; r++) {
    sum += a[r];                         // додали a[r] до вікна [l, r]
    while (sum >= S) {                   // вікно підходить — пробуємо його вкоротити
        best = min(best, r - l + 1);
        sum -= a[l];
        l++;
    }
}
cout << (best == n + 1 ? 0 : best) << '\n';   // 3: відрізок 1 4 2
```

Python:

```python
a = [2, 1, 3, 1, 1, 4, 2]
S = 7
n = len(a)
best = n + 1                             # n + 1 означає «ще не знайдено»
s = 0
l = 0
for r in range(n):
    s += a[r]                            # додали a[r] до вікна [l, r]
    while s >= S:                        # вікно підходить — пробуємо його вкоротити
        best = min(best, r - l + 1)
        s -= a[l]
        l += 1
print(0 if best == n + 1 else best)      # 3
```

Чому це O(n), хоча є вкладений `while`? Кожен елемент один раз входить у вікно (`r++`) і щонайбільше один раз виходить з нього (`l++`). Разом не більше 2n кроків. Тим самим «вікном» розв'язуються й споріднені задачі, наприклад пошук найдовшого відрізка із сумою не більше S. Подумайте, що в коді зміниться.

<details>
<summary>Відповідь</summary>

Тепер вікно підходить, коли його сума **не більша** за S, а шукаємо найдовше. Тому змінюються три місця: вікно вкорочуємо, поки сума **завелика** (`while (sum > S)`); відповідь оновлюємо **після** цього циклу, коли вікно вже підходить: `best = max(best, r - l + 1)`; початкове `best = 0`. Для того самого масиву і S = 7 відповідь 4 (наприклад, відрізок `2 1 3 1`). Саме про це задача [18. Рюкзак з книжками](../../задачі/18-рюкзак-з-книжками/умова.md): спершу спробуйте написати код самостійно.

</details>

Якщо числа бувають від'ємні, сума при зсуві `l` може зрости, і метод не працює. Тоді допомагають префіксні суми ([тема 07](07-префіксні-суми.md)).

### Два вказівники з двох кінців

У відсортованому масиві знайти два числа із сумою x. Поставимо `i` на початок, `j` у кінець. Якщо `a[i] + a[j]` замала — збільшуємо `i`, завелика — зменшуємо `j`.

C++:

```cpp
vector<int> a = {1, 2, 4, 7, 11, 15};      // відсортовано
int x = 15, i = 0, j = (int)a.size() - 1;
while (i < j && a[i] + a[j] != x) {
    if (a[i] + a[j] < x) i++;
    else j--;
}
if (i < j) cout << a[i] << " + " << a[j] << '\n';   // 4 + 11
else cout << "NO\n";
```

Python:

```python
a = [1, 2, 4, 7, 11, 15]                   # відсортовано
x = 15
i, j = 0, len(a) - 1
while i < j and a[i] + a[j] != x:
    if a[i] + a[j] < x:
        i += 1
    else:
        j -= 1
print(f"{a[i]} + {a[j]}" if i < j else "NO")   # 4 + 11
```

Чому нічого не пропускаємо: якщо `a[i] + a[j] < x`, то `a[i]` не утворить потрібну пару ні з яким елементом, бо `a[j]` — найбільший з тих, що залишились. Тож `a[i]` можна відкинути. Аналогічно для `a[j]`.

Третя типова схема — **два вказівники на два відсортовані масиви**: по одному вказівнику на кожен масив, і на кожному кроці зсувається той, що вказує на менший елемент. Так за O(n + m) зливають два відсортовані масиви в один або шукають пари «елемент першого масиву — елемент другого».

### Жадібні алгоритми

Жадібний алгоритм будує відповідь крок за кроком і на кожному кроці бере те, що найвигідніше **зараз**, не повертаючись назад. Він простий і швидкий, але **правильний не завжди**.

**Приклад, де жадібність працює.** У черзі до лікаря n людей, обслуговування i-ї триває tᵢ хвилин. У якому порядку їх приймати, щоб сума часів, коли кожен закінчить обслуговування, була найменшою? Жадібно: спершу найкоротших.

Аргумент обміну: нехай у якомусь порядку двоє сусідів стоять так, що довший іде перед коротшим. Поміняємо їх місцями. Для всіх інших людей нічого не зміниться, а для цієї пари сума зменшиться (коротший закінчить раніше на довжину довшого, а довший — пізніше лише на довжину коротшого). Отже, в найкращому порядку довший ніколи не стоїть перед коротшим.

C++:

```cpp
vector<long long> t = {5, 2, 8, 1};
sort(t.begin(), t.end());              // 1 2 5 8
long long now = 0, total = 0;
for (long long x : t) {
    now += x;                          // момент, коли закінчить ця людина
    total += now;
}
cout << total << '\n';                 // 1 + 3 + 8 + 16 = 28
```

Python:

```python
t = sorted([5, 2, 8, 1])               # [1, 2, 5, 8]
now = total = 0
for x in t:
    now += x                           # момент, коли закінчить ця людина
    total += now
print(total)                           # 28
```

**Приклад, де жадібність не працює.** Видати суму найменшою кількістю монет і купюр. Для гривневих номіналів 1, 2, 5, 10, 20, 50 правило «щоразу бери найбільший номінал, що не перевищує суми, яку ще треба видати» дає оптимум: 87 = 50 + 20 + 10 + 5 + 2 — п'ять монет і купюр. Але для номіналів 1, 3, 4 і суми 6 жадібно виходить 4 + 1 + 1 — три монети, а оптимум 3 + 3 — дві. Такі задачі розв'язує динамічне програмування ([тема 14](14-динамічне-програмування.md)).

## Типові задачі

- «Найдовший (найкоротший) відрізок, сума якого не більша (не менша) за S» при додатних числах — два вказівники.
- «Скільки відрізків мають суму не більше S», «найдовший відрізок, де не більше k різних значень» — два вказівники.
- «Чи є дві позиції з сумою x», «скільки пар з різницею не більше d» — сортування й два вказівники.
- «Вибрати найбільше подій, що не перетинаються в часі» — класична жадібна задача про розклад (див. підрозділ 6.2 «Scheduling» у «Competitive Programmer's Handbook»). Перш ніж читати розв'язок, спробуйте самі знайти контрприклади до правил «спершу найкоротші» і «спершу ті, що раніше починаються».

<details>
<summary>Відповідь</summary>

- «Спершу найкоротші» помиляється на подіях [1, 5], [4, 7], [6, 10]. Найкоротша [4, 7] перетинається з обома іншими, тож вибрано одну подію, а можна дві: [1, 5] і [6, 10].
- «Спершу ті, що раніше починаються» помиляється на подіях [0, 10], [1, 2], [3, 4]. Першою береться довга [0, 10] і закриває решту, а можна взяти дві короткі.

Правильне правило — у підрозділі 6.2 «Competitive Programmer's Handbook» і в підказках до задачі [19. Гуртки](../../задачі/19-гуртки/умова.md).

</details>

- «Розсадити, розподілити, упакувати так, щоб використати найменше…» — сортування й жадібний вибір.
- «Мінімізувати сумарний час (штраф)» — часто жадібне впорядкування.

## Типові помилки

1. **Два вказівники з від'ємними числами.** Монотонність порушується. Як виявити: тест з від'ємними числами проти перебору.
2. **Вказівник не зсувається** в якійсь гілці — нескінченний цикл.
3. **Неправильна довжина вікна:** `r - l` замість `r - l + 1`.
4. **Жадібність без доведення.** Як виявити: стрес-тест проти перебору на малих n.
5. **Сортування не за тією ознакою** (за початком замість кінця, за спаданням замість зростання).
6. **Переповнення сум** у вікні чи в сумарному часі.
