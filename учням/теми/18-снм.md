2. Писати СНМ зі стисненням шляхів і об'єднанням за розміром і пояснювати, чому без цих прийомів вона повільна.
3. Підтримувати кількість компонент і розміри груп, поки ребра додаються.
4. Розв'язувати задачі з видаленням ребер «від кінця» (офлайн).
5. Зберігати в СНМ парність і перевіряти, чи можна поділити вершини на дві команди.

## Теорія

### Навіщо СНМ

Ребра графа додаються по одному, і після кожного треба відповісти: чи з'єднані вершини u і v, скільки зараз компонент, якого розміру найбільша. Запускати BFS після кожного ребра — O(m · (n + m)), забагато. **Система неперетинних множин** (англ. disjoint set union, DSU, або union-find) робить обидві операції майже за O(1).

Кожна група — дерево, у якого кожен елемент знає свого батька `parent[x]`, а корінь — сам собі батько. Корінь — «представник» групи.

- `find(x)` — піднятися від x до кореня. Два елементи в одній групі тоді й лише тоді, коли в них однаковий корінь.
- `unite(a, b)` — знайти корені обох і підвісити один корінь під інший.

### Два прийоми, без яких СНМ повільна

Без прийомів дерево може вирости в довгий ланцюжок, і кожен `find` проходитиме його весь. Ми перевірили: 5·10⁴ запитів `find` на ланцюжку з 5·10⁴ елементів працювали 3,8 с (це 2,5·10⁹ кроків).

1. **Об'єднання за розміром:** менше дерево підвішуємо під більше. Тоді глибина дерева не перевищує log₂ n: щоразу, коли елемент опускається на рівень нижче, розмір його групи щонайменше подвоюється.
2. **Стиснення шляхів:** у `find` кожну вершину на шляху одразу підвішуємо до кореня. Наступні запити до неї — за один крок.

Разом вони дають час, який на практиці не відрізнити від O(1) на операцію.

Програма читає `n`, `m` і `m` ребер; після кожного ребра виводить кількість компонент і розмір групи, у якій тепер перша вершина ребра. Структура `DSU` — та сама, що у [фрагменті 13 репертуару](../РЕПЕРТУАР-CPP.md#13-система-неперетинних-множин-dsu).

```cpp
#include <bits/stdc++.h>
using namespace std;

struct DSU {
    vector<int> parent, sz;
    DSU(int n) : parent(n), sz(n, 1) {
        iota(parent.begin(), parent.end(), 0);  // кожен — сам собі корінь
    }
    int find(int x) {                       // зі стисненням шляху
        if (parent[x] == x) return x;
        return parent[x] = find(parent[x]);
    }
    bool unite(int a, int b) {              // false — уже в одній множині
        a = find(a);
        b = find(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) swap(a, b);      // менше дерево — під більше
        parent[b] = a;
        sz[a] += sz[b];
        return true;
    }
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    cin >> n >> m;
    DSU d(n + 1);                    // вершини 1..n
    int components = n;
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        if (d.unite(a, b)) components--;     // з'єднали дві різні групи
        cout << components << ' ' << d.sz[d.find(a)] << '\n';   // розмір групи a — у корені
    }
}
```

import sys

def main():
    data = sys.stdin.buffer.read().split()
    n, m = int(data[0]), int(data[1])

### Видалення ребер: від кінця до початку

СНМ уміє лише **об'єднувати**. Якщо ребра в задачі **видаляються** («дороги закривають по одній; скільки компонент після кожного закриття?»), а всі запити відомі заздалегідь, ідемо в зворотному порядку: починаємо зі стану «після всіх видалень», а потім повертаємо ребра від останнього видаленого до першого. Повертання ребра — це звичайний `unite`. Відповіді записуємо в масив і виводимо в правильному порядку. Такий спосіб називають **офлайн**: спершу читаємо всі запити, потім відповідаємо.

Вхід: `n`, `m`, `m` ребер, `q` і номери ребер у порядку видалення. Вихід: кількість компонент після кожного видалення.

```cpp
#include <bits/stdc++.h>
using namespace std;

// struct DSU — як у прикладі вище
struct DSU {
    vector<int> parent, sz;
    DSU(int n) : parent(n), sz(n, 1) { iota(parent.begin(), parent.end(), 0); }
    int find(int x) { return parent[x] == x ? x : parent[x] = find(parent[x]); }
    bool unite(int a, int b) {
        a = find(a);
        b = find(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) swap(a, b);
        parent[b] = a;
        sz[a] += sz[b];
        return true;
    }
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    cin >> n >> m;
    vector<int> ea(m + 1), eb(m + 1);          // ребра 1..m
    for (int i = 1; i <= m; i++) cin >> ea[i] >> eb[i];
    int q;
    cin >> q;
    vector<int> del(q);                        // номери ребер у порядку видалення
    vector<bool> removed(m + 1, false);
    for (auto& e : del) {
        cin >> e;
        removed[e] = true;
    }

    // Стан «після всіх видалень»: додаємо лише ребра, які ніхто не видаляв.
    DSU d(n + 1);
    int components = n;
    for (int i = 1; i <= m; i++)
        if (!removed[i] && d.unite(ea[i], eb[i])) components--;

    // Ідемо від кінця: відповідь після видалення j — це стан до повернення ребра del[j].
    vector<int> answer(q);
    for (int j = q - 1; j >= 0; j--) {
        answer[j] = components;
        if (d.unite(ea[del[j]], eb[del[j]])) components--;
    }
    for (int x : answer) cout << x << '\n';
}
```

    for e in dele:

    parent = list(range(n + 1))
    sz = [1] * (n + 1)

        while parent[x] != root:

        a, b = find(a), find(b)

            return False

### СНМ з парністю: дві команди

Задача: m пар «u і v — суперники, мають грати в різних командах». Після якої пари поділ на дві команди стає неможливим? Це перевірка графа на двочастковість, але ребра додаються по одному.

Для кожного елемента зберігаємо `par[x]` — чи в тій самій команді x, що й його батько (0), чи в іншій (1). Парність шляху від x до кореня — XOR усіх `par` на шляху — каже, чи x у команді кореня. Тоді:

- якщо a і b в одній групі (спільний корінь), їхні команди вже визначені: суперечність, якщо парності `pa` і `pb` однакові;
- інакше підвішуємо корінь `rb` під `ra` і підбираємо `par[rb]` так, щоб a і b опинилися в різних командах: `par[rb] = pa ^ pb ^ 1`.

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> parent, sz, par;         // par[x] — парність шляху від x до parent[x]

pair<int, int> find(int x) {         // (корінь, парність шляху від x до кореня)
    if (parent[x] == x) return {x, 0};
    auto [root, p] = find(parent[x]);
    parent[x] = root;                // стискаємо шлях...
    par[x] ^= p;                     // ...і перераховуємо парність уже до кореня
    return {root, par[x]};
}

bool addEnemies(int a, int b) {      // a і b мають бути в різних командах
    auto [ra, pa] = find(a);
    auto [rb, pb] = find(b);
    if (ra == rb) return pa != pb;   // уже в одній множині: колір відомий, перевіряємо
    if (sz[ra] < sz[rb]) swap(ra, rb);
    parent[rb] = ra;
    par[rb] = pa ^ pb ^ 1;           // тоді парність b відносно ra = pb ^ par[rb] = pa ^ 1
    sz[ra] += sz[rb];
    return true;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    cin >> n >> m;
    parent.resize(n + 1);
    iota(parent.begin(), parent.end(), 0);
    sz.assign(n + 1, 1);
    par.assign(n + 1, 0);
    for (int i = 1; i <= m; i++) {
        int a, b;
        cin >> a >> b;
        if (!addEnemies(a, b)) {     // перша пара, після якої поділ неможливий
            cout << i << '\n';
            return 0;
        }
    }
    cout << 0 << '\n';               // поділити можна, хоч би якими були всі m пар
}
```

import sys

def main():
    data = sys.stdin.buffer.read().split()
    n, m = int(data[0]), int(data[1])
    parent = list(range(n + 1))
    sz = [1] * (n + 1)
    par = [0] * (n + 1)              # парність шляху від x до parent[x]

    def find(x):                     # (корінь, парність x відносно кореня), без рекурсії
        path = []
        while parent[x] != x:
            path.append(x)
            x = parent[x]
        root = x
        p = 0
        for v in reversed(path):     # від найближчих до кореня — до x
            p ^= par[v]
            par[v] = p
            parent[v] = root
        return root, (par[path[0]] if path else 0)

    for i in range(1, m + 1):
        a, b = int(data[2 * i]), int(data[2 * i + 1])
        ra, pa = find(a)
        rb, pb = find(b)
        if ra == rb:
            if pa == pb:             # мають бути в різних командах, а колір однаковий
                print(i)
                return
            continue
        if sz[ra] < sz[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        par[rb] = pa ^ pb ^ 1
        sz[ra] += sz[rb]
    print(0)

main()

## Типові задачі

- «Дороги будують по одній; скільки після кожної окремих областей / якого розміру найбільша» — СНМ з лічильниками.
- «Чи можна дістатися з u у v» для багатьох запитів, коли ребра лише додаються — СНМ.
- Найменше кістякове дерево (алгоритм Краскала): ребра сортуємо за вагою і беремо ті, що з'єднують різні групи.
- «Ребра видаляються, запити відомі наперед» — офлайн, від кінця.
- «Поділити на дві команди», «u і v однакові / різні — чи немає суперечності» — СНМ з парністю.
- Двійковий пошук за моментом часу, коли дві вершини вперше з'єднуються, — або просто СНМ, що проходить події по порядку.

## Типові помилки

1. **Порівнюють `parent[u] == parent[v]`** замість `find(u) == find(v)`.
2. **`unite` підвішує вершину, а не корінь:** `parent[a] = b` без `find`. Групи «розвалюються».
3. **Немає жодного прийому:** ланцюжок, O(n) на запит. Як виявити: тест, де ребра йдуть ланцюжком `1–2, 2–3, …`, і запити до першої вершини.
4. **Розмір беруть не в корені:** `sz[a]` для довільної вершини актуальний лише тоді, коли a — корінь.
5. **Лічильник компонент зменшують навіть тоді, коли `unite` нічого не з'єднав** (вершини вже в одній групі).
6. **Рекурсивний `find` у Python** на великих тестах повільний і впирається в ліміт рекурсії; пишіть циклом.
7. **СНМ з парністю: забули перерахувати `par` під час стиснення шляху** — парність починає рахуватися відносно старого батька.
