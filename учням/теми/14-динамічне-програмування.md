## Що треба зрозуміти

Після цієї теми ви зможете:

1. Описувати розв'язок динамічним програмуванням (ДП) чотирма складниками: **стан** (що означає `dp[i]`), **перехід** (як `dp[i]` виражається через попередні значення), **база** (початкові значення), **порядок** обчислення — і знати, де в таблиці відповідь.
2. Пояснювати, чому рекурсія без запам'ятовування експоненційна, а ДП — ні: кожна підзадача розв'язується один раз.
3. Рахувати ДП двох видів: найкраще значення (мінімум або максимум) і кількість способів (часто за модулем).
4. Писати ДП як таблицю знизу вгору і як рекурсію з запам'ятовуванням.
5. Розпізнавати класичні одновимірні ДП.

## Теорія

### Звідки береться ДП

Жабка стоїть на камені 1, а треба потрапити на камінь n. За один стрибок вона переходить на наступний камінь або через один. Камені мають висоти hᵢ, і стрибок з каменя i на камінь j коштує |hᵢ − hⱼ| енергії. Яка найменша сумарна витрата?

Жадібно («стрибати туди, де дешевше зараз») не вийде: дешевий стрибок зараз може змусити зробити дорогий потім. Перебрати всі шляхи — їх експоненційно багато. Але помітимо: щоб найдешевше дістатися каменя i, жабка мусила перед цим найдешевше дістатися каменя i − 1 або i − 2. Отже:

- **стан:** `dp[i]` — найменша витрата, щоб дістатися каменя i;
- **перехід:** `dp[i] = min(dp[i−1] + |h[i] − h[i−1]|, dp[i−2] + |h[i] − h[i−2]|)`;
- **база:** `dp[1] = 0`; для `i = 2` можливий лише перший варіант;
- **порядок:** i зростає, бо `dp[i]` залежить від менших індексів;
- **відповідь:** `dp[n]`.

C++:

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> h(n + 1), dp(n + 1);
    for (int i = 1; i <= n; i++) cin >> h[i];
    dp[1] = 0;                                         // база
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + abs(h[i] - h[i - 1]);      // прийшли з i − 1
        if (i >= 3)                                    // з i − 2 можна лише при i >= 3
            dp[i] = min(dp[i], dp[i - 2] + abs(h[i] - h[i - 2]));
    }
    cout << dp[n] << '\n';
}
```

Python:

```python
n = int(input())
h = [0] + list(map(int, input().split()))   # нумерація з 1
dp = [0] * (n + 1)                          # dp[1] = 0 — база
for i in range(2, n + 1):
    dp[i] = dp[i - 1] + abs(h[i] - h[i - 1])          # прийшли з i − 1
    if i >= 3:                                         # з i − 2 можна лише при i >= 3
        dp[i] = min(dp[i], dp[i - 2] + abs(h[i] - h[i - 2]))
print(dp[n])
```

Для висот `10 30 40 20` відповідь 30: шлях 1 → 2 → 4 коштує 20 + 10. Складність O(n).

### Кількість способів

Скількома способами можна записати n як суму доданків 1, 3 і 4, якщо порядок доданків важливий? Наприклад, для n = 4: 1+1+1+1, 1+3, 3+1, 4 — чотири способи.

- **стан:** `ways[i]` — кількість способів набрати суму i;
- **перехід:** останній доданок — 1, 3 або 4, тому `ways[i] = ways[i−1] + ways[i−3] + ways[i−4]` (для індексів ≥ 0);
- **база:** `ways[0] = 1` — суму 0 можна набрати одним способом (нічого не брати);
- **порядок:** i зростає.

C++:

```cpp
const long long MOD = 1000000007;
int n = 10;
vector<long long> ways(n + 1, 0);
ways[0] = 1;                                     // база
for (int i = 1; i <= n; i++)
    for (int c : {1, 3, 4})
        if (i - c >= 0) ways[i] = (ways[i] + ways[i - c]) % MOD;
for (int i = 0; i <= 6; i++) cout << ways[i] << ' ';   // 1 1 1 2 4 6 9
cout << '\n';
```

Python:

```python
MOD = 10**9 + 7
n = 10
ways = [0] * (n + 1)
ways[0] = 1                                      # база
for i in range(1, n + 1):
    for c in (1, 3, 4):
        if i - c >= 0:
            ways[i] = (ways[i] + ways[i - c]) % MOD
print(*ways[:7])                                 # 1 1 1 2 4 6 9
```

Кількість способів росте дуже швидко, тому в задачах її зазвичай просять за модулем 10⁹ + 7 (див. [тему 03](03-цикли.md#остача-за-модулем)).

### Найбільша сума елементів, жодні два з яких не сусідні

- **стан:** `best[i]` — найбільша сума, яку можна набрати з перших i елементів;
- **перехід:** елемент i або не беремо (`best[i−1]`), або беремо, і тоді попередній брати не можна (`best[i−2] + a[i]`);
- **база:** `best[0] = 0`, `best[1] = max(0, a[1])`.

C++:

```cpp
vector<long long> a = {0, 2, 7, 9, 3, 1};        // a[0] не використовується
int n = 5;
vector<long long> best(n + 1, 0);
best[1] = max(0LL, a[1]);
for (int i = 2; i <= n; i++)
    best[i] = max(best[i - 1], best[i - 2] + a[i]);
cout << best[n] << '\n';                         // 12 = 2 + 9 + 1
```

Python:

```python
a = [0, 2, 7, 9, 3, 1]                           # a[0] не використовується
n = 5
best = [0] * (n + 1)
best[1] = max(0, a[1])
for i in range(2, n + 1):
    best[i] = max(best[i - 1], best[i - 2] + a[i])
print(best[n])                                   # 12
```

### Рекурсія з запам'ятовуванням

Той самий перехід можна записати рекурсивно. Але без запам'ятовування одна й та сама підзадача розв'язується знову і знову. Наприклад, наївна рекурсія `f(n) = f(n−1) + f(n−2)` для n = 30 робить 2 692 537 викликів, а різних підзадач лише 31. Якщо зберігати вже обчислені значення, кожну підзадачу розв'язуємо один раз.

Python:

```python
from functools import lru_cache

@lru_cache(maxsize=None)               # запам'ятовує результати для кожного n
def f(n):
    if n <= 1:
        return n
    return f(n - 1) + f(n - 2)

print(f(90))                           # 2880067194370816120 — миттєво
```

У C++ для цього заводять масив `memo`, заповнений позначкою «ще не обчислено» (наприклад, −1). Пам'ятайте про глибину рекурсії ([тема 13](13-рекурсія-та-перебір.md#глибина-рекурсії)); таблиця знизу вгору від цієї проблеми вільна.

### Як придумати ДП

1. Що треба знати про початок (префікс) задачі, щоб продовжити? Це і є стан.
2. Яким може бути **останній** крок (останній доданок, останній стрибок, чи взято останній елемент)? Перебір варіантів останнього кроку дає перехід.
3. Які стани найменші й очевидні? Це база.
4. Від яких станів залежить `dp[i]`? Вони мають бути обчислені раніше — це порядок.
5. Перевірте на прикладі вручну, виписавши таблицю `dp`.

## Типові задачі

- «Скількома способами можна…» (піднятися, набрати суму, розфарбувати) — кількість способів, часто за модулем.
- «Найменша вартість (найбільша сума), щоб дістатися до кінця», коли на кожному кроці кілька варіантів.
- «Найменша кількість монет (операцій), щоб отримати x».
- «Вибрати елементи з обмеженням на сусідів».
- Жадібний алгоритм має контрприклад ([тема 12](12-два-вказівники-та-жадібні.md)), а перебір не встигає.
- Найдовша зростаюча підпослідовність при n до кількох тисяч: `dp[i]` — довжина найдовшої зростаючої підпослідовності, що закінчується в i, O(n²).

## Типові помилки

1. **Нечітко визначений стан.** Запишіть словами, що означає `dp[i]`, до написання коду.
2. **Неправильна база:** `ways[0] = 0` замість 1, і всі кількості виходять нульовими.
3. **Неправильний порядок:** використовується значення, яке ще не обчислене.
4. **Вихід за межі** при `i − 2`, `i − 3` для малих i.
5. **Остача за модулем:** забули взяти її після додавання або взяли вже після переповнення. При відніманні додавайте MOD: `(x - y + MOD) % MOD`.
6. **Рекурсія без запам'ятовування** — експоненційний час.
7. **Жадібність замість ДП.** Як виявити: стрес-тест проти перебору.
