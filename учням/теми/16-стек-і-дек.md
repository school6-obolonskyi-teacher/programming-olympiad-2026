## Що треба зрозуміти

Після цієї теми ви зможете:

1. Для кожного елемента масиву знаходити найближчий більший (менший) елемент ліворуч і праворуч за O(n) **монотонним стеком**.
2. Знаходити мінімум або максимум кожного «вікна» фіксованої ширини за O(n) **монотонним деком**.
3. Поєднувати два вказівники з двома деками: вікно, у якому `max − min ≤ k`.
4. Пояснювати, чому вкладений `while` не робить алгоритм квадратичним: кожен індекс один раз додається і щонайбільше один раз видаляється.

## Теорія

### Ідея: викидати безнадійних кандидатів

Шукаємо для кожного `a[i]` найближчий ліворуч **більший** елемент. Простий спосіб — іти від `i` ліворуч, доки не трапиться більший: O(n²) на спадному масиві. Помітимо: якщо `j < i` і `a[j] <= a[i]`, то для всіх елементів правіше за `i` елемент `j` вже ніколи не буде відповіддю — `a[i]` ближчий і не менший. Такі кандидати безнадійні, і їх можна викинути назавжди.

Кандидатів зберігаємо в стеку **індексів**. Після викидання безнадійних значення в стеку строго спадають знизу вгору — звідси назва «монотонний стек». Для `a[i]` знімаємо з вершини всі елементи `<= a[i]`; що залишилося на вершині — і є відповідь.

### Найближчий більший ліворуч і праворуч

Вхід: `n` і масив. Вихід: для кожного елемента номер (з 1) найближчого більшого ліворуч (0, якщо такого немає), у другому рядку — те саме праворуч.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;

    // prevGreater[i] — номер (з 1) найближчого ліворуч елемента, більшого за a[i];
    // 0 — такого немає. nextGreater[i] — те саме праворуч.
    vector<int> prevGreater(n), nextGreater(n);
    vector<int> st;                  // індекси; a[st[...]] строго спадають знизу вгору
    for (int i = 0; i < n; i++) {
        while (!st.empty() && a[st.back()] <= a[i]) st.pop_back();
        prevGreater[i] = st.empty() ? 0 : st.back() + 1;
        st.push_back(i);
    }
    st.clear();
    for (int i = n - 1; i >= 0; i--) {   // те саме справа наліво
        while (!st.empty() && a[st.back()] <= a[i]) st.pop_back();
        nextGreater[i] = st.empty() ? 0 : st.back() + 1;
        st.push_back(i);
    }
    for (int i = 0; i < n; i++) cout << prevGreater[i] << ' ';
    cout << '\n';
    for (int i = 0; i < n; i++) cout << nextGreater[i] << ' ';
    cout << '\n';
}
```

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    a = list(map(int, data[1:n + 1]))
    prev_greater = [0] * n           # номери з 1; 0 — такого немає
    next_greater = [0] * n
    st = []                          # індекси; значення строго спадають
    for i in range(n):
        while st and a[st[-1]] <= a[i]:
            st.pop()
        prev_greater[i] = st[-1] + 1 if st else 0
        st.append(i)
    st = []
    for i in range(n - 1, -1, -1):   # те саме справа наліво
        while st and a[st[-1]] <= a[i]:
            st.pop()
        next_greater[i] = st[-1] + 1 if st else 0
        st.append(i)
    print(*prev_greater)
    print(*next_greater)

main()
```

Для масиву `3 1 4 1 5 9 2 6` програма виведе

```
0 1 0 3 0 0 6 6
3 3 5 5 6 0 8 0
```

Чому це O(n): кожен індекс кладеться в стек один раз і знімається щонайбільше один раз. Тому всі ітерації внутрішнього `while` разом — не більше n, хоча для окремого `i` їх може бути багато.

Варіанти тієї самої схеми:

- найближчий **менший** — у `while` знак `>=` замість `<=`;
- найближчий **не менший** (більший або рівний) — у `while` строга нерівність `<`;
- найбільший прямокутник у гістограмі: для кожного стовпчика найближчі менші ліворуч і праворуч задають, наскільки широко його можна розтягнути.

### Мінімум у ковзному вікні: монотонний дек

Тепер «вікно» `[i − w + 1, i]` фіксованої ширини `w` рухається праворуч, і для кожного положення треба знати мінімум. Безнадійні кандидати ті самі: якщо `j < i` і `a[j] >= a[i]`, то `a[j]` ніколи не стане мінімумом — `a[i]` не більший і пробуде у вікні довше. Тож у черзі кандидатів значення строго зростають, і мінімум завжди спереду. Новий елемент заходить ззаду (і викидає безнадійних), а старий виходить спереду, коли вікно від нього відсунулося. Потрібні операції з обох кінців — це **дек**.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, w;                        // w — ширина вікна, 1 <= w <= n
    cin >> n >> w;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;

    deque<int> dq;                   // індекси; a[...] строго зростають спереду назад
    for (int i = 0; i < n; i++) {
        // a[i] новіший і не більший — старші кандидати вже ніколи не стануть мінімумом
        while (!dq.empty() && a[dq.back()] >= a[i]) dq.pop_back();
        dq.push_back(i);
        if (dq.front() <= i - w) dq.pop_front();     // вийшов за ліву межу вікна
        if (i >= w - 1) cout << a[dq.front()] << ' ';  // мінімум вікна [i-w+1, i]
    }
    cout << '\n';
}
```

<details>
<summary>Python</summary>

```python
import sys
from collections import deque

def main():
    data = sys.stdin.buffer.read().split()
    n, w = int(data[0]), int(data[1])
    a = list(map(int, data[2:n + 2]))
    dq = deque()                     # індекси; значення строго зростають
    out = []
    for i in range(n):
        while dq and a[dq[-1]] >= a[i]:
            dq.pop()
        dq.append(i)
        if dq[0] <= i - w:           # вийшов за ліву межу вікна
            dq.popleft()
        if i >= w - 1:
            out.append(a[dq[0]])
    print(*out)

main()
```

</details>

Для `n = 8`, `w = 3` і масиву `3 1 4 1 5 9 2 6` програма виведе `1 1 1 1 2 2`.

Знову кожен індекс один раз заходить у дек і один раз виходить, тож O(n). Для максимуму міняємо `>=` на `<=`.

У деку зберігаємо **індекси**, а не значення: лише за індексом видно, чи елемент уже вийшов з вікна (`dq.front() <= i - w`), навіть якщо значення повторюються.

### Два вказівники і два деки: вікно з `max − min ≤ k`

Якщо відрізок задовольняє умову `max − min ≤ k`, то й будь-який його підвідрізок задовольняє. Тому для кожного правого кінця `r` найменший підхожий лівий кінець `l` з ростом `r` лише зсувається праворуч — працюють два вказівники ([тема 12](12-два-вказівники-та-жадібні.md)). Вікно `[l, r]` тепер змінної ширини, але деки працюють так само: один дек тримає кандидатів у максимуми, другий — у мінімуми.

Як це влаштувати:

1. Для кожного нового правого кінця `r` додайте `a[r]` в обидва деки, як у попередньому розділі: з дека максимумів спершу викиньте з кінця всі індекси зі значеннями `≤ a[r]`, з дека мінімумів — зі значеннями `≥ a[r]`.
2. Поки максимум вікна (перший елемент першого дека) мінус мінімум (перший елемент другого) більший за `k`, зсувайте `l` праворуч і викидайте з початку деків індекси, що опинилися лівіше від `l`.
3. Тепер `[l, r]` — найдовше добре вікно з правим кінцем `r`, і з ним можна робити що потрібно за умовою: рахувати, порівнювати з найкращим, запам'ятовувати початок.

Чому це O(n), хоча всередині є цикли `while`: `l` лише зростає і за всю програму зсувається не більше ніж `n` разів, а кожен індекс один раз потрапляє в кожен дек і щонайбільше один раз з нього виходить.

**Вправа.** Скільки відрізків масиву `1 3 2 6 5` мають `max − min ≤ 2`? Порахуйте вручну, а потім напишіть програму за кроками 1–3: для кожного `r` добрими є всі відрізки `[l..r, r]`, тобто `r − l + 1` штук, а сума може сягнути `n(n+1)/2 ≈ 2·10¹⁰` — потрібен `long long`.

## Типові задачі

- «Для кожного елемента знайдіть найближчий більший (менший) ліворуч / праворуч», «скільки днів чекати теплішого дня» — монотонний стек.
- Найбільший прямокутник у гістограмі; найбільший прямокутник з вільних клітинок поля (гістограма для кожного рядка) — монотонний стек.
- «Мінімум (максимум) кожного відрізка довжини w» — монотонний дек.
- «Найдовший відрізок, де найбільше й найменше значення відрізняються не більше ніж на k», «скільки таких відрізків» — два вказівники і два деки.
- Моделювання процесу «поклав — забрав останнього» (сортування стеком, дужки, відкат дій) — звичайний стек.

## Типові помилки

1. **У стеку чи деку значення замість індексів.** Не видно, чи елемент уже вийшов з вікна, якщо значення повторюються. Як виявити: тест з однаковими числами.
2. **Строга чи нестрога нерівність не та.** `<` замість `<=` у `while` дає «найближчий не менший» замість «найближчий більший». Як виявити: тест, де всі числа однакові.
3. **`front()` чи `back()` на порожньому деку.** У C++ це невизначена поведінка. Як виявити: `-fsanitize=address,undefined` і `n = 1`.
4. **Лівий кінець вікна зсувають, а дек не чистять** (або навпаки): у деку лишається індекс, менший за `l`. Як виявити: стрес-тест проти перебору.
5. **Відповідь у `int`.** Кількість відрізків сягає n(n + 1)/2 ≈ 2·10¹⁰ при n = 2·10⁵.
6. **`multiset` замість деків без обережності:** `s.erase(x)` видаляє всі копії `x`; одну копію видаляє `s.erase(s.find(x))`. Розв'язок з `multiset` — O(n log n), теж годиться, якщо видаляти правильно.
