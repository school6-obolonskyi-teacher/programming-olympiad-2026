## Що треба зрозуміти

Після цієї теми ви зможете:

1. Шукати у відсортованому масиві за O(log n) і пояснювати, чому без відсортованості двійковий пошук не працює.
2. Писати двійковий пошук через **інваріант** — твердження про межі `lo` і `hi`, яке залишається істинним на кожному кроці, — і тому не помилятися на одиницю й не зациклюватися.
3. Користуватися `lower_bound` / `upper_bound` у C++ і `bisect_left` / `bisect_right` у Python, зокрема для підрахунку елементів у діапазоні значень.
4. Розпізнавати **двійковий пошук за відповіддю**: є монотонна перевірка «чи можна досягти x», і шукається найменше або найбільше x, для якого відповідь «так».
5. Правильно вибирати початкові межі й уникати переповнення в перевірці.

## Теорія

### Ідея

Задумано число від 1 до 100. Ви називаєте число, вам відповідають «більше» чи «менше». Якщо щоразу називати середину проміжку, проміжок зменшується вдвічі, і за 7 запитань (2⁷ = 128 ≥ 100) число буде знайдено. Так само у відсортованому масиві з 10⁶ елементів потрібний елемент знаходиться за 20 кроків, а з 10¹⁸ можливих відповідей — за 60.

### Пошук з інваріантом

Знайдемо **перший індекс i, для якого `a[i] >= x`** у відсортованому масиві. Уявімо, що ліворуч від масиву стоїть −∞ (індекс −1), а праворуч +∞ (індекс n). Інваріант:

```
a[lo] < x  і  a[hi] >= x
```

На початку `lo = -1`, `hi = n` — інваріант виконується завдяки уявним елементам. Беремо середину `mid`: якщо `a[mid] >= x`, то `mid` стає новим `hi`, інакше — новим `lo`. В обох випадках інваріант не порушується. Коли `hi = lo + 1`, межі сусідні, і відповідь — `hi`.

C++:

```cpp
// a відсортовано за зростанням; повертає перший індекс i з a[i] >= x (або n, якщо такого немає)
int firstNotLess(const vector<long long>& a, long long x) {
    int lo = -1, hi = a.size();          // a[lo] < x, a[hi] >= x (уявні межі)
    while (hi - lo > 1) {
        int mid = (lo + hi) / 2;
        if (a[mid] >= x) hi = mid;       // інваріант для hi зберігся
        else lo = mid;                   // інваріант для lo зберігся
    }
    return hi;
}
```

Python:

```python
def first_not_less(a, x):
    """a відсортовано; перший індекс i з a[i] >= x (або len(a), якщо такого немає)"""
    lo, hi = -1, len(a)                  # a[lo] < x, a[hi] >= x (уявні межі)
    while hi - lo > 1:
        mid = (lo + hi) // 2
        if a[mid] >= x:
            hi = mid
        else:
            lo = mid
    return hi
```

Цикл завжди завершується: `mid` лежить строго між `lo` і `hi`, тож відстань між ними щоразу зменшується. Для `a = [1, 3, 3, 3, 7, 9]` виклики з `x = 3`, `x = 8`, `x = 10`, `x = 0` повернуть 1, 5, 6 і 0.

### Готові функції

| Що шукаємо | C++ | Python (`import bisect`) |
|---|---|---|
| перший елемент `>= x` | `lower_bound(a.begin(), a.end(), x)` | `bisect.bisect_left(a, x)` |
| перший елемент `> x` | `upper_bound(a.begin(), a.end(), x)` | `bisect.bisect_right(a, x)` |

У C++ функції повертають ітератор; щоб отримати індекс, відніміть `a.begin()`. Масив має бути відсортований.

C++:

```cpp
vector<long long> a = {1, 3, 3, 3, 7, 9};
int i = lower_bound(a.begin(), a.end(), 3) - a.begin();   // 1
int j = upper_bound(a.begin(), a.end(), 3) - a.begin();   // 4
cout << i << ' ' << j << ' ' << j - i << '\n';            // 1 4 3 — число 3 трапляється 3 рази
// скільки елементів мають значення від L до R включно
long long L = 2, R = 7;
cout << (upper_bound(a.begin(), a.end(), R) - lower_bound(a.begin(), a.end(), L)) << '\n';   // 4
```

Python:

```python
import bisect

a = [1, 3, 3, 3, 7, 9]
i = bisect.bisect_left(a, 3)                 # 1
j = bisect.bisect_right(a, 3)                # 4
print(i, j, j - i)                           # 1 4 3
L, R = 2, 7
print(bisect.bisect_right(a, R) - bisect.bisect_left(a, L))   # 4
```

Запитання для самоперевірки: як однією з цих функцій порахувати кількість елементів, не більших за x? (Це ключ до задачі 14.)

<details>
<summary>Відповідь</summary>

`upper_bound(a.begin(), a.end(), x) - a.begin()` у C++ або `bisect.bisect_right(a, x)` у Python. Функція повертає індекс першого елемента, **більшого** за x. Усі елементи ліворуч від нього не більші за x, і їх рівно стільки, скільки дорівнює цей індекс (нумерація з 0).

```cpp
vector<long long> a = {1, 3, 3, 3, 7, 9};
for (long long x : {3, 0, 100})
    cout << upper_bound(a.begin(), a.end(), x) - a.begin() << ' ';   // 4 0 6
cout << '\n';
```

```python
import bisect
a = [1, 3, 3, 3, 7, 9]
print(*[bisect.bisect_right(a, x) for x in (3, 0, 100)])   # 4 0 6
```

</details>

### Двійковий пошук за відповіддю

Інколи двійковим пошуком шукають не елемент масиву, а **відповідь задачі**. Це можливо, якщо є перевірка `can(x)` — «чи можна досягти результату x» — і вона **монотонна**: якщо можна для x, то можна й для всіх менших (або для всіх більших).

Приклад. Є мотузки довжиною 802, 743, 457 і 539 см. Треба нарізати з них щонайменше k = 11 однакових шматків цілої довжини. Яка найбільша можлива довжина шматка? Перевірка `can(L)`: з мотузки довжиною a виходить `a / L` шматків, підсумуємо й порівняємо з k. Якщо можна нарізати шматки довжиною L, то й коротші теж — перевірка монотонна. (Це класична задача «Cable Master» з NEERC 2001, [Timus 1184](https://acm.timus.ru/problem.aspx?space=1&num=1184); числа прикладу взято з неї. Повну версію з пастками — відповідь 0, переповнення лічильника — розв'яжіть у [задачі 27 «Стрічки»](../../задачі/27-стрічки/умова.md).)

Інваріант: `can(lo)` істинне, `can(hi)` хибне.

C++:

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<long long> a = {802, 743, 457, 539};
    long long k = 11;
    auto can = [&](long long L) {        // чи можна нарізати k шматків довжиною L
        long long pieces = 0;
        for (long long x : a) pieces += x / L;
        return pieces >= k;
    };
    long long lo = 1, hi = 803;          // can(1) — так (вийде 2541 шматок), can(803) — ні: усі мотузки коротші
    while (hi - lo > 1) {
        long long mid = lo + (hi - lo) / 2;
        if (can(mid)) lo = mid;
        else hi = mid;
    }
    cout << lo << '\n';                  // 200
}
```

Python:

```python
a = [802, 743, 457, 539]
k = 11

def can(L):                              # чи можна нарізати k шматків довжиною L
    return sum(x // L for x in a) >= k

lo, hi = 1, 803                          # can(lo) — так, can(hi) — ні
while hi - lo > 1:
    mid = (lo + hi) // 2
    if can(mid):
        lo = mid
    else:
        hi = mid
print(lo)                                # 200
```

Перевірка: при L = 200 виходить 4 + 3 + 2 + 2 = 11 шматків, а при L = 201 — лише 3 + 3 + 2 + 2 = 10.

Складність: O(log(діапазону) × вартість перевірки). Тут близько 10 перевірок по 4 операції; для n = 2·10⁵ і відповіді до 10¹⁸ — 60 перевірок по 2·10⁵ операцій, і це встигає.

### Межі й переповнення

- Початкові `lo` і `hi` мають задовольняти інваріант. Якщо не впевнені, що `can(lo)` істинне, перевірте це окремо (можливо, відповіді не існує).
- `(lo + hi) / 2` переповнює `int`, якщо сума `lo + hi` перевищує 2 147 483 647 (наприклад, обидві межі близько 1,5·10⁹). Пишіть `lo + (hi - lo) / 2` або беріть `long long`.
- У перевірці теж можливе переповнення: сума часток чи добутків може вийти за межі `long long`. Можна зупиняти підсумовування, щойно сума досягла потрібного значення.

## Типові задачі

- «Скільки елементів не більші (менші, у проміжку від L до R)», багато запитань до одного масиву — сортування й двійковий пошук.
- «Чи є число x у масиві» для багатьох x.
- «Знайдіть найменший час (найбільшу довжину, найменшу місткість), за якого можна…» — двійковий пошук за відповіддю.
- Відповідь може бути дуже великою (до 10⁹–10¹⁸), а перевірити конкретне значення легко.
- «Мінімізуйте найбільше…» або «максимізуйте найменше…» — часто двійковий пошук за відповіддю.

## Типові помилки

1. **Масив не відсортований.** Двійковий пошук мовчки дає неправильну відповідь.
2. **Зациклення.** Варіант `while (lo < hi)` з `mid = (lo + hi) / 2` і присвоєнням `lo = mid` зависає, коли `hi = lo + 1`. Пишіть з інваріантом `hi - lo > 1`, як вище.
3. **Помилка на одиницю у відповіді** (`lo` чи `hi`?). Сформулюйте інваріант словами, і відповідь стане очевидною.
4. **Межі, що не задовольняють інваріант**, наприклад `hi` — можлива відповідь, яку пошук ніколи не поверне.
5. **Немонотонна перевірка.** Тоді двійковий пошук не застосовний.
6. **Переповнення в `mid` або в перевірці.**
7. **`x in list` у Python** — це лінійний пошук, O(n). Для багатьох запитань використовуйте `bisect` або множину `set`.
