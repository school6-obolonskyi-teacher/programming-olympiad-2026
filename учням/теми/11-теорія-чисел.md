## Що треба зрозуміти

Після цієї теми ви зможете:

1. Знаходити всі дільники числа n за O(√n), перебираючи їх парами `d` і `n / d`.
2. Перевіряти число на простоту за O(√n) і розкладати його на прості множники за O(√n).
3. Будувати решето Ератосфена до N і знати, коли воно краще за перевірку кожного числа окремо.
4. Обчислювати НСД алгоритмом Евкліда і НСК через НСД, не допускаючи переповнення.
5. Не помилятися в граничних випадках: 0 і 1 не є простими, i · i ≤ n потребує `long long`, дільник, що дорівнює кореню з n, не враховується двічі.

## Теорія

### Дільники за O(√n)

Якщо `d` — дільник `n`, то `n / d` — теж дільник, і з пари `d`, `n / d` принаймні одне число не більше за √n. Тому досить перебрати `d` від 1 до √n.

C++:

```cpp
long long n = 36;
vector<long long> divs;
for (long long d = 1; d * d <= n; d++) {      // d * d у long long: для n до 10^12 d сягає 10^6
    if (n % d == 0) {
        divs.push_back(d);
        if (d != n / d) divs.push_back(n / d); // 6 · 6 = 36: шістку додаємо лише раз
    }
}
sort(divs.begin(), divs.end());
for (long long d : divs) cout << d << ' ';    // 1 2 3 4 6 9 12 18 36
cout << '\n';
```

Python:

```python
n = 36
divs = []
d = 1
while d * d <= n:
    if n % d == 0:
        divs.append(d)
        if d != n // d:
            divs.append(n // d)
    d += 1
print(*sorted(divs))                          # 1 2 3 4 6 9 12 18 36
```

Для n = 10¹² це близько 10⁶ кроків — встигає. Перебір усіх чисел від 1 до n зробив би 10¹² кроків.

### Перевірка на простоту

Число n > 1 просте, якщо не має дільників від 2 до √n.

C++:

```cpp
bool isPrime(long long n) {
    if (n < 2) return false;                  // 0 і 1 — не прості
    for (long long d = 2; d * d <= n; d++)
        if (n % d == 0) return false;
    return true;
}
```

Python:

```python
def is_prime(n):
    if n < 2:                                 # 0 і 1 — не прості
        return False
    d = 2
    while d * d <= n:
        if n % d == 0:
            return False
        d += 1
    return True
```

Для чисел 1, 2, 91, 97 функції повернуть «ні, так, ні, так» (91 = 7 · 13).

### Розклад на прості множники

Ділимо n на 2, поки ділиться, потім на 3 і так далі, доки p · p не перевищить те, що залишилося від n. Якщо наприкінці залишилося число більше за 1, воно просте — це ще один множник розкладу (у прикладі нижче — 5). Якби воно було складеним, то мало б дільник, не більший за свій корінь, а такі `p` ми вже перебрали.

C++:

```cpp
long long n = 360;
for (long long p = 2; p * p <= n; p++) {
    int e = 0;
    while (n % p == 0) { n /= p; e++; }
    if (e > 0) cout << p << '^' << e << ' ';
}
if (n > 1) cout << n << "^1";                 // залишився ще один простий множник
cout << '\n';                                 // 2^3 3^2 5^1
```

Python:

```python
n = 360
res = []
p = 2
while p * p <= n:
    e = 0
    while n % p == 0:
        n //= p
        e += 1
    if e > 0:
        res.append(f"{p}^{e}")
    p += 1
if n > 1:
    res.append(f"{n}^1")                      # залишився ще один простий множник
print(*res)                                   # 2^3 3^2 5^1
```

Зауважте: перебираємо всі `p`, а не лише прості, але складене `p` ніколи не поділить n — його прості множники вже «вичерпано» раніше.

З розкладу n = p₁^e₁ · p₂^e₂ · … легко отримати кількість дільників: (e₁ + 1)(e₂ + 1)… Для 360 = 2³ · 3² · 5 це 4 · 3 · 2 = 24.

### Решето Ератосфена

Якщо треба знати прості числа до N (або перевіряти багато чисел до N), швидше один раз побудувати решето: беремо список чисел 2…N і для кожного ще не викресленого простого p викреслюємо кратні p, починаючи з p · p. Складність O(N log log N) — майже лінійна.

C++:

```cpp
int N = 100;
vector<bool> isPrime(N + 1, true);
isPrime[0] = isPrime[1] = false;
for (long long p = 2; p * p <= N; p++)
    if (isPrime[p])
        for (long long k = p * p; k <= N; k += p) isPrime[k] = false;
int cnt = 0;
for (int i = 2; i <= N; i++) if (isPrime[i]) cnt++;
cout << cnt << '\n';                          // 25 простих чисел до 100
```

Python:

```python
N = 100
is_prime = bytearray([1]) * (N + 1)
is_prime[0] = is_prime[1] = 0
p = 2
while p * p <= N:
    if is_prime[p]:
        is_prime[p * p::p] = bytes(len(range(p * p, N + 1, p)))   # викреслюємо кратні одним присвоєнням
    p += 1
print(sum(is_prime))                          # 25
```

Простих чисел до 10⁶ — 78 498, до 10⁷ — 664 579. На нашому комп'ютері решето до 10⁷ на C++ будувалося за 0,05 с, у Python варіант зі зрізом, як вище, — за 0,17 с, а з викресленням у звичайному циклі `for` — близько 1 с.

Коли що обирати: одне-два числа до 10¹² — перевірка за √n; багато чисел до 10⁷ — решето.

### НСД і НСК

**Алгоритм Евкліда:** НСД(a, b) = НСД(b, a mod b), а НСД(a, 0) = a. Кожні два кроки числа зменшуються щонайменше вдвічі, тому кроків O(log min(a, b)).

C++:

```cpp
#include <bits/stdc++.h>
using namespace std;

long long myGcd(long long a, long long b) {
    while (b != 0) {
        long long r = a % b;
        a = b;
        b = r;
    }
    return a;
}

int main() {
    long long a = 48, b = 18;
    cout << myGcd(a, b) << ' ' << gcd(a, b) << '\n';   // 6 6 — у C++17 є готова std::gcd
    cout << a / gcd(a, b) * b << '\n';                 // НСК = 144
}
```

Python:

```python
import math

a, b = 48, 18
print(math.gcd(a, b))                 # 6
print(a // math.gcd(a, b) * b)        # 144
print(math.lcm(a, b))                 # 144, є в Python 3.9+
```

Кроки для 48 і 18: 48 mod 18 = 12, 18 mod 12 = 6, 12 mod 6 = 0, отже НСД = 6.

**НСК** = a / НСД(a, b) · b. Саме в такому порядку: спершу ділимо, потім множимо, — тоді проміжний результат не більший за відповідь. У C++17 є `std::lcm`.

НСК швидко росте. НСК чисел від 1 до 42 дорівнює 219 060 189 739 591 200 ≈ 2,2·10¹⁷, а НСК чисел від 1 до 43 уже більший за найбільше значення `long long`. Якщо в задачі НСК багатьох чисел, оцініть, чи він поміститься.

## Типові задачі

- «Ділиться», «кратне», «остача», «скільки чисел від 1 до n кратні k» (відповідь `n / k`).
- «Через скільки часу дві періодичні події знову збіжуться» (автобуси двох маршрутів, світлофори) — часто НСК. Перевірте на малих прикладах, що саме НСК відповідає на запитання задачі.
- «Найбільший спільний розмір», «скоротіть дріб», «на які однакові частини можна поділити» — НСД.
- «Прості числа до N», «скільки простих на відрізку» — решето (і префіксні суми з [теми 07](07-префіксні-суми.md)).
- «Кількість (сума) дільників», «розкладіть на множники» — перебір до √n або розклад.
- Нулі в кінці n!, найбільший степінь простого p, що ділить число, — розклад на множники.

## Типові помилки

1. **`int` для `d * d`.** Якщо n до 10¹², то d сягає 10⁶, і `d * d` у `int` переповнюється. Беріть `long long`. Перевірка `d <= sqrt(n)` через `double` для великих n може помилятися на одиницю; у Python для цього є `math.isqrt(n)`.
2. **1 вважають простим** або забувають про n = 0, n = 1.
3. **Корінь рахують двічі** серед дільників (`d == n / d`).
4. **Забувають останній простий множник** (`if (n > 1)` після циклу).
5. **НСК як `a * b / gcd`** — проміжний добуток може переповнитися.
6. **Окрема перевірка на простоту для кожного з 10⁵–10⁶ чисел** до 10⁷, коли достатньо одного решета.
7. **Решето розміру N замість N + 1** — немає місця для самого N.
