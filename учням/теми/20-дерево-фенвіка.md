## Що треба зрозуміти

Після цієї теми ви зможете:

1. Пояснювати, чому префіксні суми не годяться, коли масив змінюється, і що дає дерево Фенвіка: і зміна елемента, і сума на відрізку — за O(log n).
2. Писати дерево Фенвіка з пам'яті й пояснювати, що зберігає `t[i]` і навіщо `i & -i`.
3. Присвоювати елементу нове значення через додавання різниці.
4. Писати коротке дерево відрізків для мінімуму на відрізку.
5. Брати часткові бали: коли оновлень мало, обійтися префіксними сумами.

## Теорія

### Задача і чому префіксних сум замало

Масив з n чисел; надходять q запитів двох видів: «присвоїти `a[i] = x`» і «сума `a[l] + … + a[r]`». Префіксні суми ([тема 07](07-префіксні-суми.md)) відповідають на суму за O(1), але після зміни `a[i]` треба перерахувати всі `pref[j]` для j ≥ i — O(n). Наївний масив — навпаки: зміна за O(1), сума за O(n). При n = q = 2·10⁵ обидва варіанти в найгіршому випадку дають близько 4·10¹⁰ операцій.

Дерево Фенвіка робить обидві операції за O(log n): близько 18 кроків при n = 2·10⁵.

### Що зберігає дерево Фенвіка

Нумерація з 1. Позначимо `lowbit(i)` — найменший степінь двійки, що є в двійковому записі i (наймолодша одиниця): `lowbit(12) = lowbit(1100₂) = 4`, `lowbit(6) = 2`, `lowbit(5) = 1`. Елемент `t[i]` зберігає суму `lowbit(i)` чисел, що закінчуються на позиції i:

```
t[i] = a[i − lowbit(i) + 1] + … + a[i]

t[1] = a1            t[5] = a5
t[2] = a1 + a2       t[6] = a5 + a6
t[3] = a3            t[7] = a7
t[4] = a1 + … + a4   t[8] = a1 + … + a8
```

**Сума на префіксі `[1, i]`.** Беремо `t[i]` — це відрізок довжини `lowbit(i)`, що закінчується в i. Лишається префікс `[1, i − lowbit(i)]`, для нього повторюємо. Наприклад, `sum(7) = t[7] + t[6] + t[4]` — відрізки `[7, 7]`, `[5, 6]`, `[1, 4]`. На кожному кроці зникає одна одинична цифра i, тож кроків не більше log₂ n + 1.

**Зміна `a[i]`.** Треба оновити всі `t[j]`, чиї відрізки містять i. Це `j = i`, потім `j + lowbit(j)` і так далі, поки `j ≤ n`: наприклад, для i = 3 — це t[3], t[4], t[8]. На кожному кроці наймолодша одиниця зсувається вліво, тож кроків теж O(log n).

**Чому `i & -i` дає `lowbit(i)`.** У доповняльному коді `-i = ~i + 1`: усі біти i інвертуються, а потім додається 1. Нулі в кінці i стають одиницями, і +1 перетворює їх знову на нулі, переносячи одиницю якраз у позицію наймолодшої одиниці i. Вище за неї біти i та `-i` протилежні, тож `i & -i` залишає лише цю одиницю. Приклад: `12 = 01100₂`, `−12 = …10100₂`, `12 & −12 = 00100₂ = 4`.

### Код: присвоювання і суми

Структура `Fenwick` — та сама, що у [фрагменті 14 репертуару](../РЕПЕРТУАР-CPP.md#14-дерево-фенвіка). Присвоєння `a[i] = x` — це додавання різниці `x − a[i]`, тому зберігаємо ще й копію масиву.

Вхід: `n`, `q`, масив, далі запити `1 i x` (присвоїти) і `2 l r` (сума). Номери з 1.

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Fenwick {                         // індекси 1..n
    int n;
    vector<long long> t;
    Fenwick(int n) : n(n), t(n + 1, 0) {}
    void add(int i, long long delta) {   // a[i] += delta
        for (; i <= n; i += i & -i) t[i] += delta;
    }
    long long sum(int i) {               // a[1] + ... + a[i]
        long long s = 0;
        for (; i > 0; i -= i & -i) s += t[i];
        return s;
    }
    long long sum(int l, int r) { return sum(r) - sum(l - 1); }
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    vector<long long> a(n + 1);          // копія масиву: потрібна, щоб присвоювати
    Fenwick f(n);
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        f.add(i, a[i]);
    }
    while (q--) {
        int type;
        cin >> type;
        if (type == 1) {                 // 1 i x: a[i] = x
            int i;
            long long x;
            cin >> i >> x;
            f.add(i, x - a[i]);          // додаємо різницю між новим і старим
            a[i] = x;
        } else {                         // 2 l r: сума a[l..r]
            int l, r;
            cin >> l >> r;
            cout << f.sum(l, r) << '\n';
        }
    }
}
```

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n, q = int(data[0]), int(data[1])
    a = [0] + [int(x) for x in data[2:n + 2]]
    t = [0] * (n + 1)
    for i in range(1, n + 1):        # побудова за O(n): кожен вузол передає суму батькові
        t[i] += a[i]
        j = i + (i & -i)
        if j <= n:
            t[j] += t[i]

    def prefix(i):                   # a[1] + ... + a[i]
        s = 0
        while i > 0:
            s += t[i]
            i -= i & -i
        return s

    out = []
    pos = n + 2
    for _ in range(q):
        if data[pos] == b"1":        # 1 i x: a[i] = x
            i, x = int(data[pos + 1]), int(data[pos + 2])
            delta = x - a[i]
            a[i] = x
            while i <= n:
                t[i] += delta
                i += i & -i
        else:                        # 2 l r: сума a[l..r]
            l, r = int(data[pos + 1]), int(data[pos + 2])
            out.append(prefix(r) - prefix(l - 1))
        pos += 3
    print("\n".join(map(str, out)))

main()
```

### Дерево відрізків для мінімуму (коротко)

Для мінімуму Фенвік не годиться: мінімум не можна «відняти», як суму. Тоді беруть **дерево відрізків**. Найкоротший його варіант — масив `t` розміру 2n: листки `t[n..2n−1]` — сам масив, а кожна внутрішня вершина `v` зберігає мінімум своїх «дітей» `t[2v]` і `t[2v+1]`.

- Зміна `a[i]`: оновити листок і піднятися до кореня, перераховуючи батьків, — O(log n).
- Мінімум на `[l, r]`: межі відрізка піднімаються від листків до кореня. Якщо вершину на межі не можна взяти «разом із сусідом» (її батько покриває й щось поза відрізком — це умови `l & 1` і `r & 1` у коді), беремо її у відповідь окремо. Теж O(log n).

Цей варіант працює для будь-якого n, не лише для степенів двійки, і для будь-якої асоціативної й комутативної операції: мінімуму, максимуму, суми, НСД.

```cpp
#include <bits/stdc++.h>
using namespace std;

struct SegTreeMin {                      // індекси 0..n-1
    int n;
    vector<long long> t;                 // t[n + i] = a[i]; t[v] = min(t[2v], t[2v + 1])
    SegTreeMin(const vector<long long>& a) : n(a.size()), t(2 * a.size()) {
        for (int i = 0; i < n; i++) t[n + i] = a[i];
        for (int v = n - 1; v > 0; v--) t[v] = min(t[2 * v], t[2 * v + 1]);
    }
    void set(int i, long long x) {       // a[i] = x
        i += n;
        t[i] = x;
        for (i /= 2; i > 0; i /= 2) t[i] = min(t[2 * i], t[2 * i + 1]);
    }
    long long getMin(int l, int r) {     // мінімум a[l..r]
        long long res = LLONG_MAX;
        for (l += n, r += n + 1; l < r; l /= 2, r /= 2) {
            if (l & 1) res = min(res, t[l++]);
            if (r & 1) res = min(res, t[--r]);
        }
        return res;
    }
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    SegTreeMin st(a);
    while (q--) {
        int type, x, y;              // 1 i v: a[i] = v;  2 l r: мінімум на [l, r] (з 1)
        cin >> type >> x >> y;
        if (type == 1) st.set(x - 1, y);
        else cout << st.getMin(x - 1, y - 1) << '\n';
    }
}
```

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n, q = int(data[0]), int(data[1])
    t = [0] * n + [int(x) for x in data[2:n + 2]]   # t[n + i] = a[i]
    for v in range(n - 1, 0, -1):
        t[v] = min(t[2 * v], t[2 * v + 1])
    out = []
    pos = n + 2
    for _ in range(q):
        typ, x, y = data[pos], int(data[pos + 1]), int(data[pos + 2])
        pos += 3
        if typ == b"1":              # a[x] = y (номери з 1)
            i = x - 1 + n
            t[i] = y
            i //= 2
            while i > 0:
                t[i] = min(t[2 * i], t[2 * i + 1])
                i //= 2
        else:                        # мінімум на [x, y] (номери з 1)
            res = float("inf")
            l, r = x - 1 + n, y + n
            while l < r:
                if l & 1:
                    res = min(res, t[l])
                    l += 1
                if r & 1:
                    r -= 1
                    res = min(res, t[r])
                l //= 2
                r //= 2
            out.append(res)
    print("\n".join(map(str, out)))

main()
```

### Часткові бали без складних структур

Задачі на дерево Фенвіка майже завжди мають підзадачі, і їх можна взяти простішими засобами:

- **Оновлень немає** — звичайні префіксні суми, O(n + q).
- **Оновлень мало або вони йдуть групами між запитами сум** — префіксні суми, які перераховуємо лише перед запитом суми, якщо з минулого разу були зміни, і лише від найлівішої зміненої позиції. Кожна група оновлень коштує O(n).
- **n і q до кількох тисяч** — наївний масив: сума за O(n) прямо в циклі.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    vector<long long> a(n + 1), pref(n + 1, 0);
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        pref[i] = pref[i - 1] + a[i];
    }
    int dirty = n + 1;               // pref[1..dirty-1] правильні, далі — застарілі
    while (q--) {
        int type;
        cin >> type;
        if (type == 1) {             // a[i] = x: лише запам'ятовуємо, звідки перераховувати
            int i;
            long long x;
            cin >> i >> x;
            a[i] = x;
            dirty = min(dirty, i);
        } else {
            int l, r;
            cin >> l >> r;
            if (dirty <= n) {        // після змін — перераховуємо префікси один раз, O(n)
                for (int j = dirty; j <= n; j++) pref[j] = pref[j - 1] + a[j];
                dirty = n + 1;
            }
            cout << pref[r] - pref[l - 1] << '\n';
        }
    }
}
```

## Типові задачі

- «Масив змінюється; суми на відрізках» — дерево Фенвіка.
- «Мінімум (максимум) на відрізку, масив змінюється» — дерево відрізків.
- «Додати x на відрізку, запитати одне значення» — Фенвік на масиві різниць.
- «Скільки чисел, менших за x, серед уже прочитаних», кількість інверсій — Фенвік за значеннями (зі стисненням координат, якщо значення великі).
- Багато запитів «скільки різних чисел на відрізку» — запити, відсортовані за правим кінцем, і Фенвік (офлайн).

## Типові помилки

1. **Індекс 0 у Фенвіку:** `add(0, x)` не завершується, бо `0 & -0 = 0`. Як виявити: тест, де змінюється перший елемент, якщо ви забули перейти від нумерації з 0 до нумерації з 1.
2. **Присвоєння як додавання:** `add(i, x)` замість `add(i, x − a[i])`, і копію масиву `a` не оновили.
3. **Суми в `int`.** 2·10⁵ чисел по 10⁹ — це 2·10¹⁴.
4. **Сума на відрізку як `sum(r) − sum(l)`** замість `sum(r) − sum(l − 1)`.
5. **Дерево відрізків розміру n замість 2n** (у рекурсивній версії — 4n).
6. **Фенвік для мінімуму з довільними змінами:** мінімум не віднімається, відповіді стають неправильними після збільшення елемента.
7. **Одразу складний розв'язок без простого:** якщо Фенвіка не вдалося налагодити, без простого розв'язку ви залишитеся з нулем.
