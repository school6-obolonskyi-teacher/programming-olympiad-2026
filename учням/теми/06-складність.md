## Що треба зрозуміти

Після цієї теми ви зможете:

1. Ще до написання коду оцінювати, скільки операцій зробить алгоритм при найбільших даних, і записувати це як O(n), O(n²), O(n log n).
2. За обмеженнями з умови визначати, яка складність потрібна, і за підзадачами — який простий розв'язок дасть часткові бали.
3. Називати межі `int` і `long long`, знаходити місця можливого переповнення й уникати його.
4. Швидко читати й виводити великі обсяги даних у C++ і Python.
5. Оцінювати, скільки пам'яті займуть масиви.

## Теорія

### Скільки операцій зробить програма

Рахуйте, скільки разів виконається найглибше вкладене тіло циклу:

| Код | Кількість повторень | Запис |
|---|---|---|
| один цикл до n | n | O(n) |
| два вкладені цикли до n | n² | O(n²) |
| цикл, де n щоразу ділиться навпіл | log₂ n (для 10⁹ це близько 30) | O(log n) |
| сортування | ≈ n · log₂ n | O(n log n) |
| перебір усіх підмножин n елементів | 2ⁿ | O(2ⁿ) |
| цикл `i * i <= n` | √n | O(√n) |

Запис O(…) показує, як зростає час зі зростанням n. Сталі множники відкидаються: `2n` і `n/2` — це O(n).

### Орієнтир швидкості

**Орієнтир: близько 10⁸ простих операцій за секунду на C++ і в десятки разів менше на Python.** Простий цикл у Python ще повільніший: на сучасному ноутбуці 10⁷ повторень циклу з множенням і остачею виконувалися в Python 1–2 с, а 10⁸ таких самих повторень на C++ — 0,16 с. Вбудовані функції Python (`sum`, `sorted`, `max`) написані на C і працюють значно швидше за цикл, написаний вручну.

Це наближені цифри: справжній час залежить від комп'ютера й від того, які саме операції в циклі.

### Обмеження → допустима складність

Для обмеження часу 1 с (за мотивами таблиці з підрозділу 2.3 «Competitive Programmer's Handbook»):

| Найбільше n | Допустима складність (C++) | Приклад алгоритму |
|---|---|---|
| n ≤ 10 | O(n!) | перебір усіх перестановок |
| n ≤ 20 | O(2ⁿ), O(2ⁿ · n) | перебір усіх підмножин |
| n ≤ 500 | O(n³) | три вкладені цикли |
| n ≤ 5000 | O(n²) | усі пари елементів |
| n ≤ 10⁶ | O(n log n) або O(n) | сортування, префіксні суми, два вказівники |
| n ≤ 10¹² | O(√n) | перебір дільників |
| n ≤ 10¹⁸ | O(log n) або O(1) | двійковий пошук, формула |

На Python межі в кожному рядку зсуваються приблизно на порядок униз. Наприклад, O(n²) для n = 5000 — це 2,5·10⁷ операцій: на C++ це соті частки секунди, а в Python — уже секунди.

Обмеження часу буває меншим за 1 с. У I етапі 2025–2026 задачі F–H старшої ліги мали обмеження 0,5 с, а для задач G і H організатори радили обирати PyPy замість звичайного Python.

### Як читати підзадачі

Задача F «Мобільна гра» (I етап 2025–2026, 8–11 кл.): n до 2·10⁵, обмеження часу 0,5 с. За умовою, розв'язок, правильний для n ≤ 100, отримує не менше 10 балів, для n ≤ 1000 — не менше 40.

- n ≤ 100: n³ = 10⁶ — підходить навіть перебір усіх відрізків із перевіркою кожного елемента.
- n ≤ 1000: n² = 10⁶ — перебір усіх відрізків, якщо перевіряти кожен за O(1).
- n ≤ 2·10⁵: n² = 4·10¹⁰ — забагато; потрібно O(n) або O(n log n).

Почніть з простого розв'язку на часткові бали, потім покращуйте.

### Типи даних і переповнення

| Тип | Найменше значення | Найбільше значення | Байтів |
|---|---|---|---|
| `int` | −2 147 483 648 | 2 147 483 647 (≈ 2,1·10⁹) | 4 |
| `long long` | −9 223 372 036 854 775 808 | 9 223 372 036 854 775 807 (≈ 9,2·10¹⁸) | 8 |
| `unsigned long long` | 0 | 18 446 744 073 709 551 615 (≈ 1,8·10¹⁹) | 8 |
| `double` | — | точно зберігає цілі лише до 2⁵³ ≈ 9·10¹⁵ | 8 |

Якщо результат обчислення не поміщається в тип, відбувається **переповнення**: виходить неправильне, часто від'ємне число. (Формально для знакових типів у C++ це невизначена поведінка, тобто програма може зробити що завгодно.)

```cpp
int a = 100000, b = 100000;
long long c = a * b;           // множення відбулося в int і переповнилось
long long d = 1LL * a * b;     // спершу 1LL * a стає long long — усе правильно
cout << c << ' ' << d << '\n'; // 1410065408 10000000000
```

Тип результату визначається типами операндів, а не змінною, у яку його записують. Тому `long long c = a * b` не рятує.

Як вирішувати, який тип потрібен:

- оцініть найбільше значення кожної суми, добутку, відповіді й запишіть оцінку в коментарі;
- якщо може перевищити 2·10⁹ — `long long`;
- добуток двох чисел до 10⁹ поміщається в `long long` (10¹⁸), а трьох — уже ні. Тоді беріть остачу за модулем, якщо цього вимагає умова, або змінюйте порядок обчислень;
- у Python `int` не переповнюється, але дуже великі числа обробляються повільніше.

Не обчислюйте цілі степені через `pow`: він працює з `double`.

```cpp
cout << (long long)pow(3, 39) << '\n';   // 4052555153018976256 — неправильно
long long p = 1;
for (int i = 0; i < 39; i++) p *= 3;
cout << p << '\n';                       // 4052555153018976267 — правильно
```

**Як виявити переповнення:** компілюйте під час тренування з прапорцями

```
g++ -std=c++17 -O2 -Wall -fsanitize=address,undefined мій.cpp     # лише Linux/WSL: MinGW у Windows цих перевірок не підтримує
```

Тоді програма з прикладом `a * b` вище повідомить: `runtime error: signed integer overflow: 100000 * 100000 cannot be represented in type 'int'`. Санітайзери сповільнюють програму, тому на олімпіаду відправляйте звичайну версію.

### Швидке введення й виведення

Виміряно на одному комп'ютері для 10⁶ чисел, по одному в рядку:

| Спосіб | Час |
|---|---|
| Python: `int(input())` у циклі | ≈ 1,45 с |
| Python: `input = sys.stdin.readline` | ≈ 0,34 с |
| Python: `sys.stdin.buffer.read().split()` | ≈ 0,22 с |
| C++: `cin` без налаштувань | ≈ 0,37 с |
| C++: `cin` після `ios::sync_with_stdio(false); cin.tie(nullptr);` | ≈ 0,06 с |
| C++: вивести 10⁶ рядків через `endl` | ≈ 0,72 с |
| C++: вивести 10⁶ рядків через `'\n'` | ≈ 0,05 с |
| Python: 10⁶ викликів `print` | ≈ 0,67 с |
| Python: один `sys.stdout.write("\n".join(...))` | ≈ 0,22 с |

Шаблон C++:

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    long long s = 0;               // до 10^6 чисел по 10^9: сума до 10^15
    for (int i = 0; i < n; i++) {
        long long x;
        cin >> x;
        s += x;
    }
    cout << s << '\n';             // '\n', а не endl
}
```

Після `sync_with_stdio(false)` не змішуйте `cin`/`cout` зі `scanf`/`printf`.

Шаблон Python:

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()   # усі числа входу одним списком
    n = int(data[0])
    a = list(map(int, data[1:n + 1]))
    out = []
    for x in a:
        out.append(str(x * 2))
    sys.stdout.write("\n".join(out) + "\n")  # один виклик замість n викликів print

main()
```

Код усередині функції `main` у Python виконується швидше, ніж на верхньому рівні програми, бо локальні змінні шукаються швидше за глобальні. У нашому вимірюванні той самий цикл з 10⁷ повторень у функції працював 0,8 с, а на верхньому рівні — 1,35 с.

### Пам'ять

- Масив з 10⁶ `int` займає 4 МБ, з 10⁶ `long long` — 8 МБ. При обмеженні 256 МБ поміститься близько 6·10⁷ чисел `int`.
- У Python список з 10⁶ елементів займає близько 8 МБ лише на посилання (`sys.getsizeof([0] * 10**6)` дає 8000056), а кожне велике число — ще 28 байтів. Тож список з 10⁷ різних чисел займе сотні мегабайтів.
- Двовимірний масив 10⁵ × 10⁵ не поміститься ні в яку пам'ять (10¹⁰ елементів).

## Типові задачі

Ознаки в умові, що час подумати про складність і типи:

- n, q до 10⁵–10⁶: розв'язок O(n · q) чи O(n²) не встигне;
- значення до 10⁹ і слова «сума», «добуток», «загальна кількість»: потрібен `long long`;
- «виведіть відповідь за модулем 10⁹ + 7»: справжня відповідь величезна;
- обмеження часу 0,5 с або менше;
- підзадачі з різними обмеженнями n — підказка, які складності очікуються.

## Типові помилки

1. **Сума в `int`.** Як виявити: тест з усіма значеннями, рівними максимуму з умови.
2. **`a * b` обчислюється в `int`, хоча результат записують у `long long`.** Як виявити: `-fsanitize=undefined`.
3. **`endl` у великому виведенні** та **`input()` у циклі** на 10⁵ і більше рядків. Як виявити: запустіть програму на найбільшому тесті й заміряйте час.
4. **Приховані цикли.** Ці операції виглядають як одна, але виконують O(n) дій: `x in list`, `list.pop(0)`, `list.insert(0, x)`, зріз `a[l:r]`, `sum(a[l:r])`, `s.count(...)` у Python; `v.erase(v.begin())`, `v.insert(v.begin(), x)` у C++. У циклі на n кроків вони дають O(n²).
5. **`pow` для цілих чисел і `double` для великих цілих.**
6. **«Python такий самий, як C++».** Програма з 10⁸ операцій на C++ встигає, а на Python — ні. Якщо алгоритм на межі, пишіть на C++ або відправляйте на PyPy, якщо він доступний.
