## Що треба зрозуміти

Після цієї теми ви зможете:

1. Описувати задачу мовою графів: вершини, ребра, орієнтований і неорієнтований граф, шлях, компонента зв'язності.
2. Зберігати граф списками суміжності (і знати, коли підходить матриця суміжності); бачити граф у клітчастому полі.
3. Обходити граф у глибину (DFS) і рахувати компоненти зв'язності.
4. Обходити граф у ширину (BFS), знаходити найкоротші відстані в графі без ваг і відновлювати сам шлях.
5. Писати BFS на клітчастому полі з перевіркою меж і стін.
6. Оцінювати складність обходу: O(n + m), де n — кількість вершин, m — ребер.

## Теорія

### Що таке граф

**Граф** — це набір **вершин** і **ребер**, кожне з яких з'єднує дві вершини. Міста й дороги, учні й дружба, клітинки лабіринту й переходи між сусідніми — усе це графи. Ребра бувають **неорієнтовані** (дорога в обидва боки) і **орієнтовані** (лише в один бік), без ваг або з **вагами** (довжинами). **Компонента зв'язності** — частина графа, у якій з кожної вершини можна дійти до кожної, а до жодної вершини поза нею дійти не можна.

### Як зберігати граф

Найчастіше вхід — це n, m і далі m пар `a b`. Зберігаємо **списки суміжності**: для кожної вершини — список сусідів.

C++:

```cpp
int n, m;
cin >> n >> m;
vector<vector<int>> g(n + 1);       // вершини 1..n
for (int i = 0; i < m; i++) {
    int a, b;
    cin >> a >> b;
    g[a].push_back(b);
    g[b].push_back(a);              // для неорієнтованого графа — в обидва боки
}
```

Python:

```python
n, m = map(int, input().split())
g = [[] for _ in range(n + 1)]      # вершини 1..n
for _ in range(m):
    a, b = map(int, input().split())
    g[a].append(b)
    g[b].append(a)                  # для неорієнтованого графа — в обидва боки
```

Пам'ять — O(n + m). **Матриця суміжності** `adj[a][b]` займає n² клітинок, тож годиться лише для n до кількох тисяч.

### Пошук у глибину (DFS) і компоненти зв'язності

DFS іде від вершини до ще не відвіданого сусіда, звідти — далі, а коли йти нікуди, повертається назад. Масив `used` позначає відвідані вершини, щоб не ходити по колу. Запускаючи DFS з кожної ще не відвіданої вершини, рахуємо компоненти.

C++:

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<vector<int>> g;
vector<bool> used;

void dfs(int v) {
    used[v] = true;
    for (int u : g[v])
        if (!used[u]) dfs(u);
}

int main() {
    int n, m;
    cin >> n >> m;
    g.assign(n + 1, {});
    used.assign(n + 1, false);
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        g[a].push_back(b);
        g[b].push_back(a);
    }
    int components = 0;
    for (int v = 1; v <= n; v++)
        if (!used[v]) {
            components++;
            dfs(v);
        }
    cout << components << '\n';
}
```

Рекурсія в Python швидко впирається в ліміт ([тема 13](13-рекурсія-та-перебір.md#глибина-рекурсії)), тому там DFS зручно писати з явним стеком:

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n, m = int(data[0]), int(data[1])
    g = [[] for _ in range(n + 1)]
    for i in range(m):
        a, b = int(data[2 + 2 * i]), int(data[3 + 2 * i])
        g[a].append(b)
        g[b].append(a)
    used = [False] * (n + 1)
    components = 0
    for s in range(1, n + 1):
        if used[s]:
            continue
        components += 1
        used[s] = True
        stack = [s]
        while stack:                  # явний стек замість рекурсії
            v = stack.pop()
            for u in g[v]:
                if not used[u]:
                    used[u] = True
                    stack.append(u)
    print(components)

main()
```

Для графа з 6 вершинами і ребрами 1–2, 2–3, 4–5 обидві програми виведуть 3: компоненти {1, 2, 3}, {4, 5} і {6}.

У версії з явним стеком вершину позначаємо, коли кладемо її в стек, тому вершини обходяться не в тому порядку, що в рекурсивному DFS. Для підрахунку компонент порядок неважливий. Якщо ж задача залежить саме від порядку входу й виходу з вершин (пошук циклу, топологічне сортування), цей шаблон без змін не підходить.

### Пошук у ширину (BFS) і найкоротші відстані

BFS обходить вершини «хвилями»: спершу стартову, потім усі на відстані 1, потім на відстані 2 і так далі. Тому в графі без ваг (кожне ребро — один крок) BFS знаходить **найкоротші відстані**. Для цього потрібна черга.

C++:

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    vector<vector<int>> g(n + 1);
    for (int i = 0; i < m; i++) {
        int a, b;
        cin >> a >> b;
        g[a].push_back(b);
        g[b].push_back(a);
    }
    vector<int> dist(n + 1, -1), parent(n + 1, 0);   // -1 — ще не відвідана
    queue<int> q;
    dist[1] = 0;
    q.push(1);
    while (!q.empty()) {
        int v = q.front();
        q.pop();
        for (int u : g[v])
            if (dist[u] == -1) {          // позначаємо одразу, коли додаємо до черги
                dist[u] = dist[v] + 1;
                parent[u] = v;
                q.push(u);
            }
    }
    for (int v = 1; v <= n; v++) cout << dist[v] << ' ';
    cout << '\n';
    // шлях від 1 до n: ідемо по parent від n назад до 1 і перевертаємо
    if (dist[n] != -1) {
        vector<int> path;
        for (int v = n; v != 0; v = parent[v]) path.push_back(v);
        reverse(path.begin(), path.end());
        for (int v : path) cout << v << ' ';
        cout << '\n';
    }
}
```

Python:

```python
import sys
from collections import deque

def main():
    data = sys.stdin.buffer.read().split()
    n, m = int(data[0]), int(data[1])
    g = [[] for _ in range(n + 1)]
    for i in range(m):
        a, b = int(data[2 + 2 * i]), int(data[3 + 2 * i])
        g[a].append(b)
        g[b].append(a)
    dist = [-1] * (n + 1)               # -1 — ще не відвідана
    parent = [0] * (n + 1)
    dist[1] = 0
    q = deque([1])
    while q:
        v = q.popleft()
        for u in g[v]:
            if dist[u] == -1:           # позначаємо одразу, коли додаємо до черги
                dist[u] = dist[v] + 1
                parent[u] = v
                q.append(u)
    print(*dist[1:])
    if dist[n] != -1:                   # шлях від 1 до n: по parent назад і перевертаємо
        path = []
        v = n
        while v != 0:
            path.append(v)
            v = parent[v]
        print(*path[::-1])

main()
```

Для 5 вершин і ребер 1–2, 1–3, 2–4, 3–4, 4–5 програми виведуть відстані `0 1 1 2 3` і шлях `1 2 4 5`.

Кожна вершина потрапляє в чергу один раз, кожне ребро переглядається двічі, тож складність O(n + m).

### BFS на клітчастому полі

Поле n × m із символів (`.` — прохід, `#` — стіна) — це граф: вершини — клітинки, ребра — переходи між клітинками зі спільною стороною. Списки суміжності будувати не треба: сусідів обчислюємо масивами зсувів.

C++ (фрагмент: `g` — поле, `dist` — таблиця відстаней, заповнена −1, `q` — `queue<pair<int,int>>`):

```cpp
int dr[4] = {-1, 1, 0, 0};
int dc[4] = {0, 0, -1, 1};
// ... всередині циклу BFS, для поточної клітинки (r, c):
for (int k = 0; k < 4; k++) {
    int nr = r + dr[k], nc = c + dc[k];
    if (nr < 0 || nr >= n || nc < 0 || nc >= m) continue;   // за межами поля
    if (g[nr][nc] == '#' || dist[nr][nc] != -1) continue;  // стіна або вже відвідана
    dist[nr][nc] = dist[r][c] + 1;
    q.push({nr, nc});
}
```

Python (фрагмент):

```python
for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
    nr, nc = r + dr, c + dc
    if not (0 <= nr < n and 0 <= nc < m):              # за межами поля
        continue
    if g[nr][nc] == '#' or dist[nr][nc] != -1:         # стіна або вже відвідана
        continue
    dist[nr][nc] = dist[r][c] + 1
    q.append((nr, nc))
```

Решта — як у звичайному BFS. Поле 1000 × 1000 — це 10⁶ вершин, тож рекурсивний DFS на ньому ризикований (глибина може сягати 10⁶); BFS або DFS з явним стеком безпечні.

## Типові задачі

- «Міста й дороги», «друзі», «комп'ютери в мережі»: чи можна дістатися, скільки окремих груп — DFS або BFS, компоненти зв'язності.
- «Найменша кількість кроків (пересадок, ходів)» без ваг — BFS.
- Лабіринт, поле з перешкодами, «скільки кімнат» — граф на клітчастому полі.
- «Від кожної клітинки до найближчого виходу» — BFS одразу з усіх виходів: на старті в черзі всі джерела з відстанню 0.
- «Чи можна поділити на дві команди так, щоб вороги були в різних» — DFS/BFS з розфарбуванням у два кольори.

## Типові помилки

1. **Ребро додано лише в один бік** для неорієнтованого графа.
2. **Вершину позначають відвіданою під час виймання з черги**, а не під час додавання. Тоді одна вершина потрапляє в чергу багато разів, і на великих полях програма не встигає або вичерпує пам'ять.
3. **Плутанина в нумерації вершин:** в умові з 1, а масиви з 0, або навпаки.
4. **Вихід за межі поля** або переплутані рядки й стовпці (`n` і `m`, `r` і `c`).
5. **Глибока рекурсія в DFS:** `RecursionError` у Python, аварійне завершення в C++ на графах-ланцюжках і великих полях.
6. **Матриця суміжності для n = 10⁵** — 10¹⁰ клітинок.
7. **`list.pop(0)` як черга в Python** — O(n) на кожну операцію; беріть `deque`.
