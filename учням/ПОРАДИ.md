# Поради на олімпіаду

Ці поради стосуються олімпіад формату IOI, у якому проходить Всеукраїнська олімпіада з інформатики. Розв'язки перевіряє автоматична система на наборі тестів, а частково правильний розв'язок теж приносить бали. Бали дають або за підзадачу (лише якщо пройдено всі її тести), або за кожен пройдений тест («потестово»), залежно від етапу. Решту правил туру — тривалість, кількість відправлень, яке відправлення зараховується, що дозволено мати з собою — оголошують організатори етапу. Читайте їх у пам'ятці учасника та в [довідка/ОЛІМПІАДИ.md](../довідка/ОЛІМПІАДИ.md).

## До початку

- Заздалегідь зареєструйтеся на олімпіаду (з 2026/2027 н.р. учасники реєструються самостійно, порядок визначає кожна область) і на Eolymp. Перевірте, що пам'ятаєте пароль.
- Для I етапу розв'яжіть набори задач типу A і B (див. [МАРШРУТ.md](МАРШРУТ.md#перед-i-етапом-обовязково-розвяжіть-набори-a-і-b)).
- Заздалегідь відправте кілька розв'язків на Eolymp і пройдіть хоча б один минулий тур віртуально, на час, щоб знати інтерфейс системи до початку змагання ([інструкція](../довідка/EOLYMP.md)).
- Підготуйте робоче місце: редактор, у якому ви вмієте компілювати й запускати програму, і перевірений шаблон:

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    return 0;
}
```

```python
import sys
input = sys.stdin.readline   # рядок читається разом з '\n': для тексту пишіть input().strip()
```

Що варто вміти написати з пам'яті, без довідки, і які пастки C++ найчастіше коштують балів, — у [РЕПЕРТУАР-CPP.md](РЕПЕРТУАР-CPP.md).

## Перші 10–15 хвилин

Зручно робити це за [карткою туру](КАРТКА-ТУРУ.md).

1. Прочитайте **всі** задачі. Найпростіша задача не обов'язково стоїть першою.
2. Для кожної задачі випишіть обмеження та підзадачі. Підзадачі підказують, які розв'язки автор вважає частковими.
3. Складіть план: що розв'язуєте повністю, де берете лише перші підзадачі.

## Під час туру

- **Спершу прості бали.** Задача на 100 балів, яку ви точно розв'яжете за 15 хвилин, вигідніша за 30 балів у складній задачі за годину.
- **Підзадачі — ваш друг.** Простий перебір часто дає 20–40 балів. Напишіть його, відправте, а потім думайте над повним розв'язком. Повільний розв'язок до того ж допоможе перевірити швидкий.
- **Оцініть складність до написання коду.** При `n = 2·10⁵` алгоритм O(n²) не встигне; при `n ≤ 20` можна перебрати всі 2ⁿ варіантів (див. [тему 06](теми/06-складність.md)).
- **Переповнення.** Якщо відповідь може перевищити 2·10⁹, у C++ потрібен `long long`.
- **Формат виведення.** Виводьте рівно те, що просить умова: без «Відповідь:» і без запрошень до введення. Пишіть `YES`/`NO` саме так, як в умові (регістр важливий).
- **Тестуйте самі.** Приклади з умови — лише мінімум. Перевірте найменші значення (`n = 1`), однакові елементи, найбільші числа.
- **Не застрягайте.** Якщо 30 хвилин немає прогресу, перейдіть до іншої задачі й поверніться пізніше.
- **Зберігайте робочі версії.** Перш ніж переписувати розв'язок, збережіть копію того, що вже набрало бали.
- **З'ясуйте, яке відправлення зараховується.** В одних системах зараховується найкращий результат, в інших — лише **останнє** відправлення. Так було на II етапі 2025/2026 в Google Colab. В останньому випадку ніколи не відправляйте наприкінці туру неперевірену «покращену» версію, яка може виявитися гіршою.
- **Не відкладайте відправлення на останні хвилини**: система чи інтернет можуть підвести.
- **Штучний інтелект на олімпіаді заборонено** в будь-якому вигляді, зокрема вбудований у середовище програмування. Вимкніть такі розширення заздалегідь.

## Потестове оцінювання: не залишайте тестів порожніми

На I етапі 2025–2026 і на II етапі 2025/2026 у Google Colab бали давали **за кожен пройдений тест** (у задачах G і H старшої ліги I етапу — 100 тестів по 1 балу). Тоді рахується не «повний розв'язок або нічого», а скільки тестів пройде ваша програма.

**Експеримент.** Задача [19. Гуртки](../задачі/19-гуртки/умова.md) має 23 тести; правильна ідея — жадібно за часом кінця заняття. Ми перевірили скриптом чотири розв'язки учасника, який цієї ідеї не знайшов:

| Розв'язок | Тестів пройдено | Бали за підзадачами | Бали потестово |
|---|---|---|---|
| Перебір усіх наборів занять (встигає лише при `n ≤ 15`) | 15 з 23 | 30 | 65 |
| Жадібно «за часом початку» (хибна ідея) | 16 з 23 | 0 | 70 |
| Жадібно «спершу найкоротші» (хибна ідея) | 17 з 23 | 0 | 74 |
| **Перебір при `n ≤ 15`, інакше «спершу найкоротші»** | **19 з 23** | **30** | **83** |

Що з цього випливає:

1. **За потестового оцінювання хибна, але правдоподібна ідея теж приносить бали:** тести не завжди ловлять кожну помилку. Не залишайте задачу без відправлення.
2. **Розгалуження за розміром входу** — найвигідніший прийом, коли повного розв'язку немає: `if (n <= МЕЖА) перебір(); else найкраща_ідея();`. На малих тестах перебір гарантовано правильний, на великих працює ваша ідея. Межу беріть з підзадач і з оцінки часу перебору.
3. **За оцінювання підзадачами** (III етап, олімпіади формату IOI) хибна ідея дає 0, а комбінація — лише ті підзадачі, які перебір проходить повністю. Тому спершу прочитайте в умові, як рахують бали.

**Не перевищуйте час мовчки.** Тест із перевищенням часу дає 0, навіть якщо відповідь «майже знайдена». Якщо програма шукає найкращий варіант довгим перебором, стежте за часом і виводьте найкраще знайдене до кінця обмеження:

```cpp
auto start = chrono::steady_clock::now();
auto elapsed = [&] { return chrono::duration<double>(chrono::steady_clock::now() - start).count(); };
// усередині циклу перебору; час перевіряємо раз на 1024 кроки, бо сам виклик теж коштує
if ((step & 1023) == 0 && elapsed() > 0.8) break;   // 80 % від обмеження 1 с — виводимо найкраще знайдене
```

У Python: `start = time.perf_counter()` на початку і `if time.perf_counter() - start > 0.8: break` у циклі.

**Окремі випадки — окремі бали.** Серед тестів майже завжди є особливі: `n = 1`, усі числа однакові, масив уже впорядкований. Якщо загальний розв'язок не виходить, розберіть такі випадки окремо: кожен такий тест — теж бали.

**Якщо зараховується останнє відправлення** (як на II етапі 2025/2026 у Colab), зберігайте окремим файлом версію, яка набрала найбільше на тестах журі, і повертайтеся до неї, якщо нова виявилася гіршою.

Скрипт [перевірити.py](../інструменти/перевірити.py) показує обидва підсумки: за підзадачами і потестово. Перевірте свій «комбінований» розв'язок на задачах репозиторію і подивіться, скільки тестів він бере.

## Якщо система повідомляє про помилку

| Вердикт | Що означає | Що перевірити |
|---|---|---|
| Неправильна відповідь (WA) | Програма видає не те | Граничні випадки, переповнення, формат виведення, чи прочитано весь вхід |
| Перевищено ліміт часу (TL) | Алгоритм надто повільний або програма зациклилась | Складність алгоритму, швидке введення/виведення, умову виходу з циклу |
| Помилка виконання (RE) | Програма аварійно завершилась | Вихід за межі масиву, ділення на нуль, завелика глибина рекурсії (ліміт у Python, розмір стеку в C++) |
| Перевищено пам'ять (ML) | Забагато пам'яті | Розмір масивів: `10⁸` чисел `int` — це 400 МБ |
| Помилка компіляції (CE) | Код не компілюється | Чи вибрано правильну мову і компілятор у системі |
| Частково правильно | За тест чи задачу дали частину балів | Які тести не пройдено: найчастіше великі (швидкість) або граничні (особливі випадки) |

Назви вердиктів у різних системах трохи відрізняються, але суть однакова. Як вони звучать на Eolymp («Зараховано», «Неправильна відповідь», «Перевищено ліміт часу»…), див. у [довідка/EOLYMP.md](../довідка/EOLYMP.md#4-вердикти-і-бали).
