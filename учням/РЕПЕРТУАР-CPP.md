## Частина 1. Репертуар: 15 фрагментів напам'ять

Фрагменти 2–15 вставляються в `main` шаблону з фрагмента 1. Функції та структури (`struct`) пишіть над `main`. Де значення можуть перевищити 2·10⁹, скрізь `long long`.

### 1. Шаблон зі швидким введенням

**Коли:** на початку кожної задачі.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    // ... розв'язок ...
    cout << n << '\n';
    return 0;
}
```

**Увага:**

- `'\n'`, а не `endl`: `endl` щоразу скидає буфер і на 10⁶ рядків повільніший у рази (пастка 5).
- Після `sync_with_stdio(false)` не змішуйте `cin`/`cout` зі `scanf`/`printf` (пастка 20).

### 2. Читання n чисел і поля

**Коли:** «перший рядок — n, другий — n чисел»; поле із символів `.` і `#`.

```cpp
int n;
cin >> n;
vector<long long> a(n);
for (auto& x : a) cin >> x;        // & обов'язковий: читаємо в сам елемент

int rows, cols;
cin >> rows >> cols;
vector<string> g(rows);            // g[r][c] — символ клітинки
for (auto& row : g) cin >> row;
```

**Увага:**

- Без `&` (`for (auto x : a) cin >> x;`) числа читаються в копію, і масив лишається з нулями.
- `cin >>` сам пропускає пробіли й переведення рядків, тож неважливо, як числа розташовані в рядках.

### 3. Сортування: пари (значення, індекс) і власний компаратор

**Коли:** треба відсортувати й не загубити номери; сортування за кількома ознаками.

```cpp
vector<pair<long long, int>> p(n);   // (значення, індекс)
for (int i = 0; i < n; i++) p[i] = {a[i], i};
sort(p.begin(), p.end());   // за значенням, при рівності — за індексом
// p[0].second — індекс найменшого елемента

struct Item { int score, id; };      // s[i] — бали учасника i + 1
vector<Item> v(n);
for (int i = 0; i < n; i++) v[i] = {s[i], i + 1};
sort(v.begin(), v.end(), [](const Item& x, const Item& y) {
    if (x.score != y.score) return x.score > y.score;  // більше балів — вище
    return x.id < y.id;                                // далі менший номер
});
```

**Увага:**

- Компаратор відповідає на запитання «чи стоїть `x` раніше за `y`?» і для рівних елементів мусить повертати `false`. Тому лише `<` і `>`, ніколи `<=` (пастка 2).
- `sort` не стабільний: якщо порядок рівних важливий, додайте в компаратор ще одну ознаку (як `id` вище) або візьміть `stable_sort`.
- За спаданням: `sort(a.rbegin(), a.rend())`.

### 4. lower_bound і upper_bound

**Коли:** «скільки чисел менших за x / не більших за x / з відрізка [l, r]», «найменше число, не менше за x».

```cpp
sort(a.begin(), a.end());          // лише для відсортованого масиву!
int cntLess = lower_bound(a.begin(), a.end(), x) - a.begin();   // < x
int cntLE = upper_bound(a.begin(), a.end(), x) - a.begin();     // <= x
int cntLR = upper_bound(a.begin(), a.end(), r)
          - lower_bound(a.begin(), a.end(), l);    // l <= a[i] <= r
auto it = lower_bound(a.begin(), a.end(), x);      // перший >= x
if (it != a.end()) cout << *it << '\n';
else cout << "none\n";
```

**Увага:**

- `lower_bound` — перший елемент `>= x`, `upper_bound` — перший `> x`.
- Перш ніж брати `*it`, перевірте `it != a.end()`.
- Для `set` пишіть `st.lower_bound(x)`. Виклик `lower_bound(st.begin(), st.end(), x)` повертає те саме, але йде множиною крок за кроком: у нашому запуску 2000 таких запитів до множини з 2·10⁵ чисел тривали 6,4 с, а через `st.lower_bound(x)` — менше 0,001 с.

### 5. Частоти: map і unordered_map

**Коли:** «скільки разів трапляється кожне значення», значення великі (до 10⁹) або це рядки.

```cpp
map<long long, int> cnt;            // ключі впорядковані за зростанням
for (long long x : a) cnt[x]++;
cout << cnt.size() << '\n';         // кількість різних значень
for (auto& [value, c] : cnt)        // від меншого ключа до більшого
    cout << value << ' ' << c << '\n';
cout << (cnt.count(x) ? "yes" : "no") << '\n';  // не створює ключ x

unordered_map<long long, int> fast;  // у середньому O(1), але без порядку
for (long long x : a) fast[x]++;
```

**Увага:**

- Навіть читання `cnt[x]` створює ключ `x` зі значенням 0. Щоб лише перевірити, чи є ключ, пишіть `count(x)` або `find(x)`.
- Перебір `unordered_map` іде в непередбачуваному порядку.
- `unordered_map` можна «зламати» спеціально підібраними числами (пастка 11). `map` працює за O(log n), і цього майже завжди досить.

### 6. Префіксні суми

**Коли:** багато запитань «сума на відрізку [l, r]» до масиву, що не змінюється.

```cpp
vector<long long> pref(n + 1, 0);   // pref[i] = a[0] + ... + a[i-1]
for (int i = 0; i < n; i++) pref[i + 1] = pref[i] + a[i];
long long sum = pref[r + 1] - pref[l];   // a[l] + ... + a[r], індекси з 0
```

**Увага:**

- Розмір `n + 1` і `pref[0] = 0`: тоді відрізок, що починається з першого елемента, не потребує окремого випадку.
- Якщо в умові індекси з 1, сума — `pref[r] - pref[l - 1]`.
- Тип `long long`: 2·10⁵ чисел по 10⁹ дають 2·10¹⁴.

### 7. Двійковий пошук за відповіддю

**Коли:** «знайдіть найбільше x, за якого ще можна…», і перевірка `ok(x)` монотонна: якщо можна для x, то можна й для всіх менших.

```cpp
// ok(x) = true для x <= A і false для x > A. Шукаємо A.
// Приклад: A — ціла частина кореня з n (n до 10^18).
auto ok = [&](long long x) { return x * x <= n; };

long long lo = 0;             // ok(lo) — істинне
long long hi = 2000000000;    // ok(hi) — хибне
while (hi - lo > 1) {
    long long mid = lo + (hi - lo) / 2;
    if (ok(mid)) lo = mid;
    else hi = mid;
}
// тут hi = lo + 1, і lo — найбільше x, для якого ok(x) істинне
```

**Увага:**

- Інваріант: `ok(lo)` завжди істинне, `ok(hi)` завжди хибне. Початкові межі мають це гарантувати. Межу, де `ok` не можна обчислити (наприклад, довжина 0 і ділення на 0), беріть «уявною»: `mid` завжди лежить строго між `lo` і `hi`, тож її ніколи не перевірять.
- Шукаєте **найменше** x, для якого `ok(x)` істинне (`ok`: хибне… хибне, істинне… істинне)? Той самий цикл, тільки гілки міняються місцями, а відповідь — `hi`.
- `mid = lo + (hi - lo) / 2` і межі в `long long`. Перевірте, що в `ok` нічого не переповнюється для `x < hi` (тут `x * x < 4·10¹⁸`).

### 8. НСД, НСК і решето Ератосфена

**Коли:** дроби, кратність, «через скільки кроків знову збіжиться»; багато перевірок на простоту чисел до 10⁶–10⁷.

```cpp
long long g = gcd(a, b);       // C++17; gcd(x, 0) = x
long long l = a / g * b;       // НСК: спершу ділення, потім множення
```

Те саме вручну (алгоритм Евкліда; функція — над `main`):

```cpp
long long myGcd(long long a, long long b) {
    while (b != 0) {
        a %= b;
        swap(a, b);
    }
    return a;
}
```

```cpp
const int N = 1000000;
vector<bool> isPrime(N + 1, true);
isPrime[0] = isPrime[1] = false;
for (long long i = 2; i * i <= N; i++)
    if (isPrime[i])
        for (long long j = i * i; j <= N; j += i) isPrime[j] = false;
```

**Увага:**

- Вираз `a * b / g` переповнюється раніше, ніж `a / g * b`: для `a = b = 4·10⁹` добуток `a * b = 1,6·10¹⁹` не вміщується в `long long`, а `a / g * b` дає правильні `4·10⁹`.
- Зовнішній цикл решета — до `i * i <= N`, а `i` і `j` — `long long`. З `int i` до `N` добуток `i * i` переповнюється (так ламаються розв'язки задачі 16).
- Решето до 10⁷ у `vector<bool>` займає ≈ 1,25 МБ (один біт на число), у `vector<char>` — 10 МБ.

### 9. Рекурсія із запам'ятовуванням

**Коли:** рекурсивна формула, у якій ті самі підзадачі повторюються (ДП «зверху вниз»).

```cpp
const long long MOD = 1000000007;
vector<long long> memo;          // memo[i] = -1: ще не обчислено

// скількома способами набрати суму i доданками 1, 3, 4
long long ways(int i) {
    if (i < 0) return 0;
    if (i == 0) return 1;
    long long& res = memo[i];    // посилання: пишемо одразу в memo
    if (res != -1) return res;
    res = (ways(i - 1) + ways(i - 3) + ways(i - 4)) % MOD;
    return res;
}
// у main: memo.assign(n + 1, -1); cout << ways(n) << '\n';
```

**Увага:**

- −1 годиться як позначка «не обчислено», лише якщо справжня відповідь ніколи не дорівнює −1. Інакше заведіть окремий масив `vector<char> done`.
- Без `&` у `long long& res` результат не потрапить у `memo`, і рекурсія знову стане експоненційною.
- Глибина рекурсії доходить до n. У нашому запуску (стек 8 МБ) цей фрагмент пройшов n = 2·10⁵ і впав при n = 3·10⁵ (пастка 9). Для більших n пишіть таблицю знизу вгору.

### 10. BFS на сітці

**Коли:** найменша кількість ходів на полі; найкоротший шлях у графі без ваг.

```cpp
// g — поле з '.' і '#', старт (sr, sc); dist = -1 — ще не відвідано
vector<vector<int>> dist(rows, vector<int>(cols, -1));
queue<pair<int, int>> q;
dist[sr][sc] = 0;
q.push({sr, sc});
int dr[] = {-1, 1, 0, 0}, dc[] = {0, 0, -1, 1};
while (!q.empty()) {
    auto [r, c] = q.front();     // копія, не посилання: далі буде pop()
    q.pop();
    for (int d = 0; d < 4; d++) {
        int nr = r + dr[d], nc = c + dc[d];
        if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
        if (g[nr][nc] == '#' || dist[nr][nc] != -1) continue;
        dist[nr][nc] = dist[r][c] + 1;   // позначаємо одразу при додаванні
        q.push({nr, nc});
    }
}
// dist[fr][fc] — відповідь; -1 означає «недосяжно»
```

**Увага:**

- Спершу перевірка меж, потім звернення до `g[nr][nc]`.
- Позначайте клітинку відвіданою, коли **кладете** її в чергу, а не коли виймаєте: інакше одна клітинка потрапить у чергу кілька разів.
- Для графа зі списком суміжності все те саме, тільки сусіди беруться з `adj[v]`.

### 11. DFS зі своїм стеком (компоненти зв'язності)

**Коли:** «чи досяжна вершина», «скільки компонент», обхід великого графа без ризику переповнити стек викликів.

```cpp
// adj — списки суміжності: для ребра u-v
// adj[u].push_back(v); adj[v].push_back(u);
vector<int> comp(n, -1);        // номер компоненти; -1 — не відвідано
int comps = 0;
for (int s = 0; s < n; s++) {
    if (comp[s] != -1) continue;
    vector<int> st = {s};       // власний стек замість рекурсії
    comp[s] = comps;
    while (!st.empty()) {
        int v = st.back();
        st.pop_back();
        for (int u : adj[v])
            if (comp[u] == -1) {
                comp[u] = comps;    // позначаємо, коли кладемо в стек
                st.push_back(u);
            }
    }
    comps++;
}
```

**Увага:**

- Рекурсивний DFS на графі-ланцюжку з 2·10⁵ вершин у нашому запуску впав через переповнення стека (пастка 9). Власний стек такої межі не має.
- Порядок обходу тут інший, ніж у рекурсивного DFS. Для досяжності й компонент це неважливо, а для задач, де потрібен саме порядок входу й виходу з вершин, пишіть рекурсію і стежте за глибиною.
- Ребро неорієнтованого графа додавайте в обидва боки.

### 12. Дейкстра

**Коли:** найкоротші відстані від однієї вершини в графі з **невід'ємними** вагами ребер.

```cpp
// adj[v] — пари (сусід, вага): vector<vector<pair<int, long long>>>
const long long INF = LLONG_MAX / 2;
vector<long long> dist(n, INF);
priority_queue<pair<long long, int>, vector<pair<long long, int>>,
               greater<pair<long long, int>>> pq;   // зверху — найменша
dist[s] = 0;
pq.push({0, s});
while (!pq.empty()) {
    auto [d, v] = pq.top();
    pq.pop();
    if (d != dist[v]) continue;      // застарілий запис — пропускаємо
    for (auto [u, w] : adj[v])
        if (dist[v] + w < dist[u]) {
            dist[u] = dist[v] + w;
            pq.push({dist[u], u});
        }
}
// dist[v] == INF — вершина недосяжна
```

**Увага:**

- Без `greater<…>` черга видає **найбільший** елемент. Відстані все одно вийдуть правильні, але вершини оброблятимуться багато разів, і на спеціально складених тестах програма не встигне.
- Рядок із «застарілим записом» обов'язковий: одна вершина може лежати в черзі кілька разів, а обробляти її треба один раз.
- Від'ємні ваги Дейкстра не підтримує. Складність O((n + m) log m).

### 13. Система неперетинних множин (DSU)

**Коли:** «об'єднати дві групи», «чи в одній групі u і v», кількість компонент, що зростають з додаванням ребер.

```cpp
struct DSU {
    vector<int> parent, sz;
    DSU(int n) : parent(n), sz(n, 1) {
        iota(parent.begin(), parent.end(), 0);  // кожен — сам собі корінь
    }
    int find(int x) {                       // зі стисненням шляху
        if (parent[x] == x) return x;
        return parent[x] = find(parent[x]);
    }
    bool unite(int a, int b) {              // false — уже в одній множині
        a = find(a);
        b = find(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) swap(a, b);      // менше дерево — під більше
        parent[b] = a;
        sz[a] += sz[b];
        return true;
    }
};
// DSU d(n); d.unite(u, v); if (d.find(u) == d.find(v)) ...
```

**Увага:**

- Порівнюйте корені `find(u) == find(v)`, а не `parent[u] == parent[v]`.
- Об'єднання за розміром тримає дерева неглибокими (до log₂ n), тож рекурсія у `find` безпечна.
- Кількість множин = n мінус кількість успішних `unite`.

### 14. Дерево Фенвіка

**Коли:** масив змінюється, і впереміш ідуть запити «додати до елемента» і «сума на відрізку».

```cpp
struct Fenwick {                         // індекси 1..n
    int n;
    vector<long long> t;
    Fenwick(int n) : n(n), t(n + 1, 0) {}
    void add(int i, long long delta) {   // a[i] += delta
        for (; i <= n; i += i & -i) t[i] += delta;
    }
    long long sum(int i) {               // a[1] + ... + a[i]
        long long s = 0;
        for (; i > 0; i -= i & -i) s += t[i];
        return s;
    }
    long long sum(int l, int r) { return sum(r) - sum(l - 1); }
};
// Fenwick f(n); f.add(i, x); cout << f.sum(l, r) << '\n';
```

**Увага:**

- Індекси **з 1**. Виклик `add(0, …)` не завершується: `0 & -0 = 0`, і `i` не росте (перевірено: нескінченний цикл).
- Щоб **присвоїти** `a[i] = v`, тримайте копію масиву і викликайте `add(i, v - a[i])`, а потім `a[i] = v`.
- Обидві операції — O(log n).

### 15. Бінарне піднесення до степеня за модулем

**Коли:** `aᵉ mod m` для e до 10¹⁸; обернене число за простим модулем.

```cpp
long long power(long long a, long long e, long long mod) {   // a^e % mod
    long long res = 1 % mod;
    a %= mod;
    while (e > 0) {
        if (e & 1) res = res * a % mod;
        a = a * a % mod;
        e >>= 1;
    }
    return res;
}
// обернене до a за простим модулем p (a не ділиться на p): power(a, p - 2, p)
```

**Увага:**

- Добуток двох чисел, менших за `mod`, має вміщатися в `long long`: `mod` до ≈ 3·10⁹ (для `10⁹ + 7` — із запасом).
- Для від'ємного `a` спершу зробіть `a = (a % mod + mod) % mod` (пастка 4).
- `1 % mod`, а не `1`: при `mod = 1` відповідь 0.

```
g++ -std=c++17 -O2 -D_GLIBCXX_DEBUG мій.cpp     # перевірки всередині STL
```

Санітайзери працюють у Linux, WSL і Colab; MinGW у Windows їх не підтримує.

### 1. Знакове переповнення — невизначена поведінка

```cpp
int cnt = 0;
for (int i = 1; i > 0; i *= 2) cnt++;   // «поки i не стане від'ємним»
```

**Що сталося.** З `-O0` цикл зупинився після 31 кроку. З `-O2` він не зупинився зовсім: переповнення `int` — невизначена поведінка, тому компілятор вважає, що `i > 0` завжди істинне. Санітайзер: `signed integer overflow: 1073741824 * 2 cannot be represented in type 'int'`.

**Правильно.** Не розраховувати на переповнення: `long long` і явна межа, наприклад `for (long long i = 1; i <= n; i *= 2)`.

### 2. Компаратор з `<=`

```cpp
vector<int> v(n, 5);
sort(v.begin(), v.end(), [](int a, int b) { return a <= b; });
```

**Що сталося.** При n = 100 програма завершилася без видимих проблем, але санітайзер показав читання за межами вектора (`heap-buffer-overflow`). При n = 10⁵ — аварійне завершення (`Segmentation fault`) у 4 запусках з 5, при n = 10⁶ — у 5 з 5. З `-D_GLIBCXX_DEBUG` помилку видно вже при n = 3: `comparison doesn't meet irreflexive requirements`.

**Правильно.** Лише строгі `<` і `>`; для рівних елементів компаратор повертає `false`.

### 3. `1 << 40`

```cpp
long long a = 1 << 40;     // зсув виконується в int
long long b = 1 << k;      // k = 40
```

**Що сталося.** Для сталої g++ попередив `left shift count >= width of type` і дав 0. Зі змінною `k = 40` вийшло 256: процесор узяв зсув за модулем 32. Санітайзер: `shift exponent 40 is too large for 32-bit type 'int'`.

**Правильно.** `1LL << 40`, `1LL << k`.

### 4. `%` і `/` для від'ємних чисел

```cpp
cout << -7 % 3 << ' ' << -7 / 2 << '\n';    // -1 -3
```

**Що сталося.** Остача від'ємного числа в C++ від'ємна (−1, а не 2), ділення округлює до нуля (−3, а не −4). Перевірка непарності `x % 2 == 1` для від'ємних x не спрацьовує.

**Правильно.** `x % 2 != 0` для непарності; остача від 0 до m − 1 — `(x % m + m) % m`.

### 5. `endl` у циклі

```cpp
for (int i = 0; i < n; i++) cout << i << endl;
```

**Що сталося.** 10⁶ рядків у файл: з `endl` — 0,47 с, з `'\n'` — 0,04 с. `endl` після кожного рядка примусово скидає буфер.

**Правильно.** `'\n'`. Буфер однаково буде скинуто наприкінці програми.

### 6. `accumulate` з `0` замість `0LL`

```cpp
vector<long long> v(3, 1000000000);
cout << accumulate(v.begin(), v.end(), 0) << '\n';
```

**Що сталося.** Вивело `-1294967296`: тип суми визначає третій аргумент, а `0` — це `int`.

**Правильно.** `accumulate(v.begin(), v.end(), 0LL)` дає `3000000000`.

### 7. `v.size() - 1` і порівняння знакового з беззнаковим

```cpp
vector<int> v;                                // порожній
for (int i = 0; i < v.size() - 1; i++) s += v[i];
```

**Що сталося.** `v.size()` беззнаковий, тому `v.size() - 1` для порожнього вектора — це 18446744073709551615. Цикл пішов за межі вектора; без санітайзера програма зависла (ми зупинили її через 5 с), із санітайзером — `runtime error: reference binding to null pointer`. `-Wall` попереджає: `comparison of integer expressions of different signedness`.

**Правильно.** `for (int i = 0; i + 1 < (int)v.size(); i++)` або спершу `int n = v.size();`.

### 8. `pow` і `sqrt` для цілих

```cpp
long long n = 999999999999999999LL;          // 10^18 - 1
long long r = (long long)sqrt(n);
long long p = (long long)pow(3, 39);
```

**Що сталося.** `r = 1000000000`, хоча 10⁹ · 10⁹ > n. `p = 4052555153018976256`, а правильно `4052555153018976267`. `double` точно зберігає цілі лише до 2⁵³ ≈ 9·10¹⁵.

**Правильно.** Корінь підправити: `while (r * r > n) r--; while ((r + 1) * (r + 1) <= n) r++;` або знайти двійковим пошуком (фрагмент 7). Степені — циклом або фрагментом 15.

### 9. Глибина рекурсії

```cpp
void dfs(int v) {                // рекурсивний DFS
    used[v] = true;
    for (int u : adj[v]) if (!used[u]) dfs(u);
}
```

**Що сталося.** На графі-ланцюжку з 10⁵ вершин усе гаразд, з 2·10⁵ — `Segmentation fault`: закінчився стек (8 МБ у Linux; у Windows за замовчуванням він ще менший). Цікаво, що простіша рекурсія `f(n) = f(n - 1) + n` з `-O2` пройшла навіть глибину 10⁷: компілятор сам перетворив її на цикл. Тож «у мене на простому прикладі працює» нічого не гарантує.

**Правильно.** Для глибини понад 10⁵ — власний стек (фрагмент 11) або ДП знизу вгору.

### 10. Великий локальний масив

```cpp
int main() {
    int a[10000000];             // 40 МБ у стеку
```

**Що сталося.** `Segmentation fault` одразу після запуску. Той самий масив, оголошений глобально (поза функціями), працював.

**Правильно.** Глобальний масив або `vector<int> a(10000000);` — обидва лежать не в стеку.

### 11. `unordered_map` і анти-хеш тести

```cpp
unordered_map<long long, int> cnt;
for (int i = 1; i <= 200000; i++) cnt[i * 172933LL]++;
```

**Що сталося.** 44 с. Ті самі 2·10⁵ вставок ключів 1, 2, 3, … — 0,01 с. Числа, кратні певному простому, потрапляють в один «кошик» хеш-таблиці, і кожна операція стає O(n). На змаганнях, де учасники складають тести проти чужих розв'язків, такі тести роблять навмисно.

**Правильно.** `map` (у цьому самому тесті 0,04 с) або власна хеш-функція з випадковим зсувом:

```cpp
struct SafeHash {
    size_t operator()(unsigned long long x) const {
        static const unsigned long long R =
            chrono::steady_clock::now().time_since_epoch().count();
        x += R + 0x9e3779b97f4a7c15ULL;            // splitmix64
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return x ^ (x >> 31);
    }
};
unordered_map<long long, int, SafeHash> cnt;   // той самий тест: 0,04 с
```

### 12. `getline` після `cin >>`

```cpp
cin >> n;
getline(cin, s);                 // вхід: "5", потім "hello world"
```

**Що сталося.** `s` порожній: `cin >> n` прочитав `5` і залишив `'\n'`, а `getline` прочитав «рядок» до цього `'\n'`. Навпаки теж буває пастка: `cin >> s` читає лише одне слово, до пробілу.

**Правильно.** `getline(cin >> ws, s);` — `ws` пропускає пробіли й переведення рядка. Тоді `s = "hello world"`.

### 13. `abs` для `long long`

```cpp
long long x = -5000000000LL;
cout << ::abs(x) << '\n';        // C-шна abs(int)
int a = 2000000000, b = -2000000000;
cout << abs(a - b) << '\n';
```

**Що сталося.** `::abs(x)` (так само `abs` у мові C) вивела `705032704`: число обрізалося до `int`. `abs(a - b)` вивела `294967296`: різниця переповнилася ще до виклику `abs`. Натомість звичайний `abs(x)` з `bits/stdc++.h` і `using namespace std` дав правильні `5000000000`.

**Правильно.** `abs(x)` з `using namespace std` (або `llabs(x)`), а різницю рахувати в `long long`: `abs((long long)a - b)`. Не беріть `fabs`: вона рахує в `double` і для 999999999999999999 дала 10¹⁸.

### 14. Читання до кінця файлу

```cpp
while (!cin.eof()) {
    cin >> x;
    cnt++;
    sum += x;
}
```

**Що сталося.** Для входу `1 2 3` з переведенням рядка наприкінці: `cnt = 4`, `sum = 9`. Після числа 3 кінець файлу ще не досягнуто (лишився `'\n'`), тож цикл пішов ще раз, читання не вдалося, а `x` зберіг старе значення 3.

**Правильно.** `while (cin >> x) { … }` — умова істинна, лише якщо число справді прочитано.

### 15. `s = s + c` у циклі

```cpp
for (int i = 0; i < n; i++) s = s + 'a';
```

**Що сталося.** n = 10⁵ — 0,17 с, n = 2·10⁵ — 0,90 с: кожне `s + 'a'` копіює весь рядок, разом O(n²). `s += 'a'` для n = 10⁶ — 0,002 с.

**Правильно.** `s += c` або `s.push_back(c)`.

### 16. Неініціалізована змінна

```cpp
long long total(const vector<int>& v) {
    long long s;                 // забули = 0
    for (int x : v) s += x;
    return s;
}
```

**Що сталося.** Для `{1, 2, 3}` з `-O2` вивело 6 — випадково правильно. З `-O0` — `-5406842045563327738`. На іншому комп'ютері чи в іншому місці програми результат може бути будь-яким. `-Wall` попереджає: `'s' is used uninitialized`.

**Правильно.** Завжди `long long s = 0;`. Глобальні змінні заповнюються нулями автоматично, локальні — ні.

### 17. Вихід за межі масиву без жодної помилки

```cpp
vector<int> v(5, 1);
cout << v[5] << '\n';
```

**Що сталося.** Вивело 0, жодного повідомлення. Запис `a[5] = 0` у масив `int a[5]` теж минув «тихо» (g++ з `-Wall` лише попередив). Такі помилки псують сусідні змінні й проявляються далеко від місця, де сталися.

**Правильно.** Шукати такі помилки під час тренувань: `-fsanitize=address,undefined` (повідомив `index 5 out of bounds for type 'int [5]'`), `-D_GLIBCXX_DEBUG` (зупиняє програму на `v[5]`) або `v.at(5)` (кидає виняток `out_of_range`).

### 18. `vector<bool>`

```cpp
vector<bool> vb(3, false);
auto x = vb[0];
vb[0] = true;
cout << x << '\n';
```

**Що сталося.** Вивело 1: `x` змінився разом з елементом. `vector<bool>` зберігає біти, і `vb[0]` повертає не `bool`, а «посилання на біт». З `vector<int>` той самий код вивів 0.

**Правильно.** `bool x = vb[0];` (явний тип) або `vector<char>`. Для решета `vector<bool>` годиться (він ущільнює пам'ять у 8 разів), якщо не копіювати елементи через `auto`.

### 19. `memset` не на 0 і не на −1

```cpp
int a[3];
memset(a, 1, sizeof a);
cout << a[0] << '\n';
```

**Що сталося.** Вивело `16843009`, а не 1: `memset` записує значення в **кожен байт**, а `int` має 4 байти (`0x01010101`). Для 0 і −1 це збігається з очікуваним, бо всі байти однакові. `memset(a, 0x3f, sizeof a)` дає 1061109567 (≈ 1,06·10⁹) — популярна «нескінченність» для `int`; для `long long` той самий виклик дає ≈ 4,6·10¹⁸.

**Правильно.** `fill(a, a + n, 1);` або `vector<int> a(n, 1);`.

### 20. `printf`/`scanf` разом із `cout`/`cin` після `sync_with_stdio(false)`

```cpp
ios::sync_with_stdio(false);
printf("1\n");
cout << "2\n";
printf("3\n");
```

**Що сталося.** Вивело `2`, `1`, `3`: у C++ і C тепер окремі буфери, і вони скидаються в різний час. З введенням ще гірше: після `cin >> a;` виклик `scanf("%d", &b)` на вході `1 2` число 2 не прочитав — його вже забрав у свій буфер `cin`.

**Правильно.** В одній програмі — або лише `cin`/`cout`, або лише `scanf`/`printf`.

## Частина 3. Стрес-тест за 5 хвилин

Стрес-тест порівнює ваш розв'язок із простим повільним, але очевидно правильним розв'язком на сотнях маленьких випадкових тестів і зупиняється на першому тесті, де відповіді різні. Маленький тест легко розібрати вручну.

Потрібно три файли. Приклад: найбільша сума відрізка масиву, у швидкому розв'язку навмисна помилка.

`brute.cpp` — перебір усіх відрізків, O(n²):

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    long long best = LLONG_MIN;
    for (int l = 0; l < n; l++) {
        long long s = 0;
        for (int r = l; r < n; r++) {
            s += a[r];
            best = max(best, s);
        }
    }
    cout << best << '\n';
}
```

`sol.cpp` — швидкий розв'язок, O(n):

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    long long best = 0, cur = 0;     // помилка: best = 0
    for (long long x : a) {
        cur = max(x, cur + x);
        best = max(best, cur);
    }
    cout << best << '\n';
}
```

`gen.py` — генератор маленького тесту; номер тесту задає `seed`, тож тест можна відтворити:

```python
import random
import sys

random.seed(int(sys.argv[1]))
n = random.randint(1, 8)
print(n)
print(*[random.randint(-10, 10) for _ in range(n)])
```

**Linux, WSL, Colab** — файл `stress.sh`, запуск `bash stress.sh`:

```bash
g++ -O2 -o sol sol.cpp && g++ -O2 -o brute brute.cpp || exit 1
for i in $(seq 1 1000); do
    python3 gen.py $i > in.txt
    ./sol < in.txt > out1.txt
    ./brute < in.txt > out2.txt
    if ! cmp -s out1.txt out2.txt; then
        echo "DIFF on test $i"; cat in.txt
        echo "sol:"; cat out1.txt
        echo "brute:"; cat out2.txt
        exit 1
    fi
done
echo "OK: 1000 tests"
```

У Colab створіть файли клітинками `%%writefile sol.cpp` (так само для решти) і запустіть `!bash stress.sh`.

**Windows (PowerShell).** Спершу скомпілюйте: `g++ -O2 -o sol.exe sol.cpp` і `g++ -O2 -o brute.exe brute.cpp`. Потім вставте у вікно PowerShell (або збережіть як `stress.ps1` і запустіть `powershell -ExecutionPolicy Bypass -File stress.ps1`):

```powershell
$sol = "sol.exe"; $brute = "brute.exe"     # Python: "python sol.py"
$ok = $true
for ($i = 1; $i -le 1000; $i++) {
    cmd /c "python gen.py $i > in.txt"
    cmd /c "$sol < in.txt > out1.txt"
    cmd /c "$brute < in.txt > out2.txt"
    if ((Get-Content out1.txt -Raw) -ne (Get-Content out2.txt -Raw)) {
        "DIFF on test $i"; Get-Content in.txt
        "sol:"; Get-Content out1.txt
        "brute:"; Get-Content out2.txt
        $ok = $false; break
    }
}
if ($ok) { "OK: 1000 tests" }
```

Чому через `cmd /c`: у PowerShell 5.1 немає перенаправлення `<`, а `>` записує файл у кодуванні UTF-16, яке C++-програма прочитає неправильно.

На цьому прикладі обидва скрипти зупиняються на тесті, де всі числа від'ємні: `sol` виводить 0, а `brute` — найбільше з чисел. Для задач репозиторію все це вже зроблено: `python інструменти/перевірити.py --stress NN мій.cpp` порівнює ваш розв'язок із повільним розв'язком задачі NN на випадкових тестах.

Якщо стрес-тест нічого не знаходить, а система не приймає розв'язок, збільште числа в генераторі (переповнення) і перевірте граничні випадки: n = 1, усі числа однакові, найбільші значення з умови.
